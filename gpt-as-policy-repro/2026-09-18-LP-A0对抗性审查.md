## 0. 判定

**narrow 结论可维持，验收标签不可维持。**

- **可维持**：Torch CPU ↔ Torch NPU 在"单固定观测 + 单固定噪声"下的实测差（max_abs=3.565e-03、mean_abs=7.657e-04、p99=3.137e-03、mean_rel=1.488e-02）与 CPU 双跑确定性 0.0，经独立复核**真实、内部一致、证据链闭合**（脚本三方 md5 一致、服务器日志逐字节一致、噪声注入语义核实无误）。作为"运行时差值的实测点"成立。
- **不可维持**：按 LIBERO-PRO 计划 v0.2 §2 对 LP-A0 的定义（"固定观测、固定噪声下 **JAX CPU → Torch CPU → Torch NPU**：逐张量中间量、未解码动作、最终动作块对比；噪声按主计划 W7 规则由 **JAX 侧**生成注入"，通过判据"沿用主计划 W6/W7 **预注册阈值**"），本次结果**只完成了其中 Torch 内部一段**，且阈值是事后经验解释。commit message 与 lock 中的 **"LP-A0 PASS" 是对自定缩小口径的通过，不是对计划定义口径的通过**。应改记为："Torch 段通过；JAX leg 与预注册阈值未完成"。

## 1. P1 发现

### P1-1 阈值程序违反预注册纪律（"落在 bf16/归约量级"是事后判断）

- 主计划 `2026-09-17-GPT-as-Policy在MuJoCo与昇腾上的复现计划.md:243`（W6）："**预注册 `validation.json` 的阈值后才做验收**：用同参考实现重复运行/精度变化的校准 fixture 确定数值噪声范围……**校准与验收 fixture 分离，不能看失败结果后放宽**。" LIBERO-PRO 计划 §2 LP-A0 通过判据同口径（"沿用主计划 W6/W7 预注册阈值"）；§7.3 并明确"容差……不由用户凭经验直接指定一个数"。
- 实况：仓库**不存在** `configs/validation.json`（`configs/` 下仅 `campaigns/`、`libero_pro.lock.json`、`upstream.lock.json`，本审查 ls 核实）。lock `lp_a0.status` 写 "pass (… within **observed** bf16/归约量级)"——判据带是在看到 3.565e-03 之后划定的。
- **自相矛盾点**：被审脚本自己声明 `scripts/lp_a0_numerical_check.py:6-7` "正式 W6/W7 阈值仍按主计划预注册程序另行确定，**不以本脚本输出反推**"，lock `interpretation` 亦复述此话；但同一 lock 的 `status` 字段与 commit message 却直接给出 "PASS"。声明了不反推，结论却反推了。
- 缓解（属实之处）：本审查独立做了量级解析——双侧同为 bf16 精度制度（`policy_config.py:55` 无条件 `to_bfloat16_for_selected_params("bfloat16")`，layernorm/norm 等保 fp32，`gemma_pytorch.py:71-82`），bf16 unit roundoff ≈2⁻⁹≈2e-3 相对量级，经 10 步 Euler 累积后 3.6e-3 的 max_abs 落在带内。**解释在数值上说得通，但程序上不合规**——解析支持不能替代预注册。

### P1-2 对照计划定义，LP-A0 缺 JAX CPU leg、缺中间量/未解码动作对比

- LIBERO-PRO 计划 §2（`2026-09-17-LIBERO-PRO补充面板初步计划.md:38`）：LP-A0 = "固定观测、固定噪声下 **JAX CPU → Torch CPU → Torch NPU**：**逐张量中间量、未解码动作**、最终动作块对比；噪声按主计划 W7 规则由 JAX 侧生成注入"。主计划 W7（计划 `:251`）："CPU 使用固定原 JAX 版本、PRNG 配置、seed0、**原 key 分裂次序和 dtype，生成真实噪声后注入 Torch/NPU**……只用 `torch.manual_seed(0)` 不通过。"
- 实况：JAX 参与为零。噪声由 numpy PCG64 生成注入（脚本 `:48`），只覆盖 Torch CPU ↔ Torch NPU 一段；只比最终解码后 7 维动作，无逐张量中间量、无未解码 32 维动作对比。
- 影响评估：LP2 已证明 811 张量逐位相等（lock `lp2_conversion.fidelity_audit`），权重级风险已被大幅消解；但**运行时 kernel 差异（JAX vs Torch 的 rope/attention/归约实现）不会因权重逐位相等而消失**，JAX↔Torch CPU 段的运行时差在 pi05_libero 上从未量化。LP-A0 作为"W6/W7 方法论彩排"（计划 §1.2）的核心目的——演练 JAX 随机流注入与三栈对比——未达成。lock `noise_rule` 自己承认"JAX 基线对齐在 W6/LP-A0 完整链中补"，即**缺口是被明知的**，明知缺失仍标 PASS 属过度表述。
- 严重度定 P1 而非 P2 的理由：这是验收对象定义的一部分，且 commit/lock 的对外口径（PASS）会让下游误以为三栈链已闭合。

## 2. P2 发现

### P2-1 单样本代表性不足以支撑"运行时等价"

- fixture 构成：1 个观测（seed0 `uniform(-1,1)` 的 8 维 state + **均匀随机像素**图像 + 1 条 prompt）× 1 个噪声 draw × batch=1 → 70 个标量动作元素。p99 of 70 个点就是次大值邻域（3.137e-3 vs max 3.565e-3），无尾部信息。
- 均匀随机像素是 SigLIP 的**分布外输入**：attention 模式、激活范围与真实 LIBERO 帧不同，单点差值不能外推为运行时误差的上界或代表值。主计划 W6（`:242`）明确要求"用**真实原任务观测**……原始观测不足时先用迁移原任务观测，并注明输入域限制"——脚本未用真实观测，也未注明该限制。
- 支撑 W6/W7 级验收至少需要：真实 LIBERO 帧若干条（覆盖不同 prompt token 长度、含右腕零填充与真实三相机两种路径）、每条多噪声 draw、跨样本聚合的按维 max/mean 与翻转分析；中间量（prefix KV、每步 v_t、x_t）抽样对比。当前 n=1 是"开发诊断样本"规模（LIBERO-PRO 计划 §7.1），被当作了"数值验收样本"（§7.2）使用。

### P2-2 "分开播种 max_abs≈2.0" 无入库证据

- 解释声明把 3.6e-3 的可信度锚在"分开播种时 ≈2.0"上，但该数字**无任何留存记录**：`lp_a0_result.log` 每次重跑覆盖（`lp-a0-blocker.md:15` 自认"每次重跑覆盖"），仓库与服务器均无 separate-seed 运行的 artifact。
- 机制上成立（E3 推断）：旧版脚本（`af7c31d` 版，本审查 `git show` 核实）用 `torch.manual_seed(SEED)` 后各自 infer——同 seed 跨设备（CPU MT19937 流 vs NPU 设备侧流）产生的噪声**逐位不同**，生成式流匹配对初值敏感，≈2.0 的发散合理。但：2.0/3.565e-3 ≈ 561 ≈ **2.75 个数量级**，commit message 写 "3 orders" 是向上取整；且作为定量论据的 2.0 本身无证据。建议降格为定性表述或补一次可存档的 separate-seed 运行。

### P2-3 W7 记录要素缺失，fixture 身份不可事后重建

- 主计划 W7（`:252`）要求记录 "inference_index、key 前后状态、**noise shape/hash**、**observation hash**、**checkpoint ID**"。入库 evidence 仅 6 行汇总 + `cpu_sample[0,:5]`/`npu_sample[0,:5]`，无噪声哈希、无观测哈希、无权重指纹引用。任何人事后无法验证"当时注入的就是那个噪声/那个观测"。
- 本审查尝试从宿主复核权重 md5：`/workspace/data/checkpoints/pi05_libero_pt` **在宿主不存在**（实测 `no /workspace on host`，checkpoint 在 gap-repro 容器内部），只读审查无法进容器 → 权重身份只能依赖 LP2 记录的 md5（`032ad466…`/`87c6c228…`），本次无法独立重验。这是证据布局问题：验收证据应落在宿主可审计路径。

### P2-4 GE/TBE 事件根因只有会话叙述，无服务器证据入库

- 已独立复核为真的部分（只读 ssh，2026-09-18 15:00 CST）：
  - `/root/atc_data` 现已缺席（`ls` → missing）——与"mv 复位"叙述一致；

- 缺失部分："缓存损坏"与"编译资源竞争"两个根因**均无 plog/日志入库**；blocker 自己承认（`:17`）"GE 失败计数为 0……GE 子进程 plog 待定位"。复位实验（mv 后消失）的"复位前状态"无记录。

## 3. P3 发现

### P3-1 计时口径混淆

脚本 `:46-60`：`t0` 先于 `build("cpu")`，故 `cpu_time=612.8s` = 权重加载 + **2 次** CPU 推理；`npu_time=205.4s` = 权重加载 + **1 次** NPU 推理。二者不可比，"NPU 快 3 倍"不成立（7.2GB safetensors 加载在两个窗口里都占大头）。`policy_timing["infer_ms"]`（`policy.py:103-105`）现成可用而未记录。方向性结论（NPU 更快）大概率仍成立，但应补纯推理计时。

### P3-2 噪声 shape 硬编码

`(10, 32)`（脚本 `:48`）恰好等于 pi05 内部约定（`pi0_config.py:17` `action_dim=32`；`config.py:745` `action_horizon=10`），且 `policy.py:86-87` 自动补 batch 维 → `(1,10,32)`，与 `pi0_pytorch.py:381` 内部形状一致。但 W7 明确要求"**shape 从模型内部动作维度读取**，不能直接填解码后的 14 维"——本次是"碰对了"而非"按规程读的"。应改为 `cfg.model.action_dim`/`action_horizon` 派生。

### P3-3 CPU 确定性检查的范围有限

`a_cpu1`/`a_cpu2` 同进程、同线程池、同 oneDNN plan cache。作为"同运行时确定性"证据成立；作为普遍确定性证据未覆盖跨进程/跨线程数扰动。正式验收建议加一次变线程重跑。路径本身无缓存污染：KV cache 每次 `sample_actions` 新建（`pi0_pytorch.py:394-400`），无跨调用状态；`inference_mode` 与模型自带 `@torch.no_grad` 叠加无害；噪声经 `torch.from_numpy` 零拷贝共享但路径内无就地修改（`:418` `x_t = x_t + dt * v_t` 新建张量），三次 infer 间噪声完整性成立。

### P3-4 fixture 复现性对 numpy 版本敏感

`np.random.default_rng(0)/(42)` 的流稳定性不被 numpy 官方跨版本保证（NEP 19 允许 Generator 换流），服务器 numpy 版本未入证据。建议在 evidence 里记录 `numpy.__version__` 并把噪声数组哈希入库。

### P3-5 杂项

- `SEED = 1234`（脚本 `:24`）在最后一次编辑后成死变量——从 manual_seed 方案迁移的残留，应删。
- lock `lp_a0.method` 称"卡1"，脚本只写 `build("npu")`，物理卡号由容器设备映射决定，evidence 中无卡号记录。
- `mean_rel=1.488e-02` 偏大是分母含近零动作所致（`denom=max(|cpu|,1e-6)`），非异常，但报告口径应同时给按维统计，避免误读。

## 4. 确认无误清单（独立复核通过）

1. **noise 形参语义**（`policy.py:68,83-88`）：kwarg-only；PyTorch 路径 `torch.from_numpy(noise).to(device)`，`ndim==2` 时补 batch → (1,10,32)；JAX 路径 `jnp.asarray(noise)`（同形参对 JAX 可用——补做 JAX leg 时无需改上游）。
2. **噪声贯穿整个去噪循环**（`pi0_pytorch.py:405-419`）：`x_t = noise` 是流匹配初值 x₁，10 步 Euler 每步 `x_t = x_t + dt*v_t` 都携带它，非仅首步；time 调度确定（1.0 → dt=-0.1 递减），`sample_time`/Beta（`:182-185`）只在训练 `forward` 用。
3. **注入分布与内部约定等价**：内部 `sample_noise` = `torch.normal(0,1,float32)`（`:173-180`）；注入 numpy `standard_normal` float32 同分布同尺度同 dtype。
4. **推理路径无其他随机源**：`preprocess_observation_pytorch` 全部增强在 `if train:` 分支内（`preprocessing_pytorch.py:52-142`），eval 路径确定 → 固定噪声下 CPU determinism=0.0 可信。
5. **输入契约正确**：脚本输入与 `make_libero_example`（`libero_policy.py:10-17`）同构（8 维 state、224×224×3 uint8、prompt；右腕零填充 mask=False，`:62-68`）；输出切片 `[..., :7]`（`:100`）→ shape=(10,7) 与内部 32 维噪声并存自洽（pi05 内部 action_dim=32，LIBERO 解码 7 维）。
6. **双侧同精度制度**：`policy_config.py:55` 两设备都强制 bf16（选中参数保 fp32），"bf16/归约顺序量级"解释的**数量级**经本审查独立解析成立（见 P1-1 缓解）。
7. **eager 验收**：脚本关闭 `pytorch_compile_mode`（默认 `max-autotune`，`pi0_config.py:26`），符合 W7 "eager 验收"。
8. **证据链身份闭合**（只读 ssh 实测）：服务器执行脚本 `/data_nv0/gpt-as-policy-repro/repo/scripts/lp_a0_numerical_check.py` md5 = `b664bd41191942b88283d7684daba01f` = commit `664a524` 版 = 本地工作区版，三方一致；服务器 `/data_nv0/gpt-as-policy-repro/data/lp_a0_result.log`（331B，mtime Sep 18 14:19）与入库件**逐字节一致**；结果行数值与 lock `lp_a0.results` 完全一致。
9. **结果内部一致**：`cpu_sample`/`npu_sample[0,:5]` 逐项差（1.9e-3/1.3e-3/2.5e-3/0.6e-3/0.2e-3）均 ≤ max_abs=3.565e-3；p99 ≤ max。
10. **服务恢复属实**：`:8642/health` → `{"ok": true, "device": "npu"}`（2026-09-18 15:00 CST 实测）。
11. **JAX leg 补做路径可行且便宜**：服务器已装 `jax==0.5.3/jaxlib` CPU（`jax_install.log`）；`w6_jax_ref.py` 已在原 checkpoint 上跑通同型 JAX CPU 参考前向（`w6_jax_ref.json` 在库）；pi05_libero JAX 权重已本地化且 16/16 crc32c 对账（lock `weight_integrity`）；`Policy.infer` 的 noise 形参 JAX 路径原生支持。无新依赖，数小时级工作量。

## 5. 补做路径（建议的最小闭合方案）

1. **预注册阈值**：先按 W6 程序跑校准 fixture（同参考实现 × 重复运行 × 精度扫描），把阈值写进 `configs/validation.json`，**再**做验收比较；校准与验收 fixture 分离。
2. **JAX CPU leg**（gap-repro 容器内）：`create_trained_policy(pi05_libero 的 TrainConfig, /workspace/data/checkpoints/pi05_libero)`（不带 `pytorch_device` → JAX 路径），同一 inputs + 同一噪声调 `infer`；对比 JAX CPU ↔ Torch CPU 的最终动作 + 抽样中间量（prefix KV、v_t、未解码 32 维 x₁/输出）。
3. **W7 噪声规则**：改用 `jax.random.PRNGKey(0)` + 原 key 分裂次序生成噪声，记录 noise shape/hash、observation hash、checkpoint ID、inference_index，前若干次与原代码生成值逐字节对比；shape 从 `cfg.model.action_dim/action_horizon` 读取。
4. **代表性**：换真实 LIBERO 帧（≥3 条不同任务/token 长度）× 每条 ≥3 噪声 draw，报跨样本按维 max/mean；CPU 侧加一次变线程重跑。
5. **证据入库**：纯推理计时（`policy_timing`）、权重 md5（宿主可审计路径）、GE 事件如复发先开 `ASCEND_GLOBAL_LOG_LEVEL=0` 抓 plog 再动手复位。

## 6. 结论

LP-A0 的实测数字真实可信、证据链身份闭合、噪声注入语义经上游逐行核实无误——这部分**经攻击后存活**。但 "LP-A0 PASS" 作为验收结论不成立：缺计划定义的 JAX CPU leg 与中间量对比（P1-2）、阈值未预注册而是事后划带（P1-1）、n=1 分布外观测的代表性不足（P2-1）、关键论据 ≈2.0 无存证（P2-2）。**建议改记状态为 "Torch 段通过（开发诊断级证据）；JAX leg 与预注册阈值未完成"，按 §5 路径补齐后再升格为验收 PASS。**
