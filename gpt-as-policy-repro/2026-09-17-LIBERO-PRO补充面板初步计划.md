## 1. 定位与双重角色

1. **泛化归因面板**：三方法（GPT Direct / GPT Hybrid / Student-only）× 4 套件 ×（Ori + 5 扰动）= **72 个汇总格**，产出逐维归因表。
2. **W6/W7 方法论彩排场**：在有官方公开成绩的官方 checkpoint 上，完整演练"JAX 参考 → Torch 转换 → NPU 数值验收 → 闭环对表"的流水线；其结论反哺主计划 W6/W7 的**流程与工具**，但**不得用 LIBERO 成功率反向调整 W6/W7 数值容差**（容差仍按主计划 W6 的预注册程序独立确定）。

报告口径约束不变：该面板只支持"管线可信度"与"泛化归因"两类结论，不表述为第三套主实验。

## 3. 正式矩阵：72 格（修正 v0.1 的"三路线 × 九条件"）

**结构：3 方法 × 4 套件 ×（Ori + Obj/Pos/Sem/Task/Env）= 72 格。**
每套件 10 任务；论文口径每任务 50 集 = 每格 500 集 = 全矩阵 36,000 集；10×10 口径则 7,200 集。

- **精度现实**（E3，按二项分布）：p≈0.5 时每格 100 集的 Wilson 95% 半宽约 ±0.10，500 集约 ±0.044。论文的 36,000 集口径才有表级精度；7,200 口径只能给方向性结论。
- **体量现实**（E3，待 A1 吞吐实测定标）：按已测 robodojo 服务 661ms/chunk、每集 44–104 个 chunk（max_steps/5）估算，7,200 集 ≈ 58–138 小时纯 NPU 推理；36,000 集 ≈ 290–690 小时。仿真端 CPU 192 核并行不是瓶颈。
- **集数决策放到冻结时点**：以"主要比较 + 目标精度"反推每格集数，允许不同格不同 n（例如 Task/Sem 格与 Goal/10-Ori 格给高精度，其余格降 n），**必须先写出每格 n 与其精度，再开跑**。这一决策随冻结的任务清单一起核算，不在本计划里预设。
- Sem 维度每任务 3 个改写，集数在改写间分配方式按 fork 实现锁定。
- 学生基线行（Student-only）是**全部 72 格的第一批数据**，也是与论文对表的直接对象。

## 4. 工作包与验收门（LP 系列，v0.2 顺序）

**顺序：来源锁定 → 环境与数值验收 → 学生基线核查 → GPT 契约适配 → 冻结正式矩阵 → 三方法评测。**

- [ ] **LP0 来源与权源锁定（进行中）**：剩余项——①RLinf 与 Zxy-MLlab 两源核对，锁定规范 fork + commit，输出与 openpi `third_party/libero` pin 的差异清单；②`gs://openpi-assets` 可达性实测与 checkpoint 身份哈希；③论文表格数值二次核对（含 π₀ 行：PRO 0.44、Position 0.00）；④许可证记录。
- [ ] **LP1 环境与 session 适配器**：版本策略（替代 v0.1 的"一个版本都不升"）——**影响物理、观测、评分的组件（mujoco/robosuite、渲染后端、LIBERO/PRO 代码本身）按 fork 声明精确锁定；平台依赖（CUDA torch 等官方安装里的 GPU 项）做最小适配，逐项记录"原值→我们的值→理由→验证方式"**；CPU 渲染吞吐与旧依赖在本机兼容性为 LP1 实测项。session 适配器按 suite 名加载 bddl/init，配对初态与成功判定走 LIBERO 原生接口；reset 指纹一致性测试。
- [ ] **LP2 推理服务与转换**：按 LP0 结论走官方转换脚本得到 Torch 权重；pi05_libero 服务实例独立部署，不碰同事交付包；**传输协议建议直接沿用 openpi `serve_policy.py` 的 websocket 形态**，客户端行为与官方 `examples/libero/main.py` 逐项对齐（wait10 / 旋转180° / resize224 / replan5 / max_steps 按套件），差异需显式记录。
- [ ] **LP3 GPT 路线契约移植（冻结清单）**：三方法除"决策者"外一切输入输出必须一致，冻结项至少包括：相机与本体输入内容及来源、图像预处理（旋转/缩放/裁剪）、动作单位与缩放、夹爪方向语义、控制预算（各套件 max_steps 与 wait）、重规划间隔、接管/交还规则、模型身份与推理档位、传输协议。**Task 扰动一致性四件套**：指令、BDDL、初态、成功判据同步换，三方法同源取用；Sem 维度仅指令换，同样三方法同源。agent 可见范围与评测真值隔离沿用主计划 W9 规则。
- [ ] **LP4 验证阶梯执行**：按 §2 顺序 A0→A1→A2，记录归因。
- [ ] **LP5 正式矩阵与报告**：先冻结任务清单 + 每格 n + 精度表（§3），再开跑；attempt 账本与 §8 纪律全程适用。

## 5. 方法验收逻辑（分离两类目标，避免结果偏向）

- **Student-only 基线**：可与论文/官方表格对照（锚定对象仅此一行）。
- **Direct / Hybrid**：验收 = 协议正确（契约冻结项逐项通过）+ 记录完整（§7 交付物），**不预设也不要求成绩符合任何预期方向**。
- **"GPT 主场"降级为待检验假设**：注意 Sem（纯指令改写）与 Task（目标替换）是两个不同问题——前者是语言鲁棒性，后者是目标跟随。两者都测，结论分开写；仅取得非零成绩不能直接推出"理解能力更强"，需与失败案例定性分析配套。

## 6. 工程与资源

- **双容器**：仿真容器（新起，LP1 老栈环境，只跑 LIBERO/PRO，不占卡）+ 推理容器（现有 NPU 宿主上加挂 pi05_libero 服务，默认 0 号卡，另派卡需用户指定）。HTTP/websocket 按_LP2 决定；容器间不共享文件写权限，数据全部在 `/data_nv0` 我们目录。
- **卡分配**：显式设备映射、可观测、避开任何可能属于别人的卡（维持现状约定）。
- **CPU 并行**：192 核，拟 8–16 环境，LP-A1 实测定值。

## 7. 统计与交付（三类样本分离）

1. **开发诊断样本**（LP-A1/A2、调试）：永不进入正式统计，规模自由。
2. **数值验收样本**（LP-A0）：固定观测/固定噪声 fixture，规模按主计划 W6/W7 程序。
3. **正式统计样本**（LP-A3/LP5）：每格 n 由目标精度反推（§3），冻结后才跑；容差按比较目标推导并记录推导过程，不由用户凭经验直接指定一个数。
4. **交付物**：72 格 × {n, 成功率, 95% 区间, 配对差} 全表；学生基线与论文对表及偏差；Direct/Hybrid 的失败案例定性归因（至少 Task/Sem 两维）；全部 attempt 与账本；栈差异声明（渲染后端、推理设备、所有"原值→我们的值"适配记录）。

## 8. 可选加强项（锚定 gate 通过后再议）

- **pi0_libero 对照**（论文同表可取数）：证明结论对学生强弱不敏感；同一流水线多挂一个官方 checkpoint，LP-A3 通过后启动。
- **Sem/Task 维度 GPT 假设检验**：见 §5，作为预注册假设写入 LP5 报告框架，结果无论方向如实报告。
