## 红

1. **（A）step_queries 是死代码，"超限判败 / !=aim→reward 0" 端到端不存在。**
   全仓 grep：`register_query`/`step_queries` 仅环境定义处（environment.py L61-79），无任务注册、无测试、
   无调用方。`take_action` 只调 `step_criteria`（L299），success 判定（L300-301）完全不看 query 计数；
   `step_queries` 返回的 `(within, exact)` 无任何消费点。上游接线点是 eval_env.py L457（每控制步
   `reward_manager.step`），超限即 `_mark_env_failed`（reward_manager.py L373-374），get_reward 再按
   `>aim`/`!=aim` 清零 reward（L545-557）——repro 无对应链路。commit 所称 "original aim counting" 仅为
   未接线的孤立方法。
2. **（A）RewardManagerView.reset 漏清 query_list。** environment.py L45-48 只清三清单；上游
   reward_manager.py L43-45 reset 同时清 `query_list`/`trigger_query_list`。`environment.reset`（L217）
   经 rm.reset() 后，旧 episode 的 query 条目连同计数器 `query[2]` 原样残留——一旦红1接线，即跨 episode
   泄漏判败状态。
3. **（B/E）commit message 声称 "unstable_envs as set"，代码是空列表，且本 commit 根本没改它。**
   L133 `self.unstable_envs = []`（87dab47 引入；`git show 9cae18d` 的 diff 无该行）。全仓对该字段只有
   初始化+注释（L131-133），无 set()、无写入点、无 `mark_env_unstable` 等价物。上游对应机制齐全：
   eval_env L123/L225 `set()`、L250-253 `check_layout_stability`→`UnStableError`、L467-473
   `mark_env_unstable`、L790-794 run_eval 剔除——repro 全缺，`invalid_native_layout` 分类路径不可达。
4. **（C）get_obs 把 ee_joint_state 从归一化 opening 静默改为原始关节角，违背其自称的 "raw session 契约"。**
   旧实现 states 用 `r.gripper_openings[a]`（归一化，`_robot_state_from_mj` L160 `(j7-lo)/(hi-lo)`）；
   新实现 L236-239 直接放原始 `d.qpos[joint7]`。上游 obs_manager L171-186：state 的 `ee_joint_state`
   是**归一化值**（`(val-gripper_scale[0])/(gripper_scale[1]-gripper_scale[0])`，且取 prev_control
   命令值）。GRIPPER_SCALE=(-0.01, 0.044)（robots.py L18），即 14D 第 6/13 维尺度差约 18.5 倍——
   policy proprio 输入（session obs['states']，session.py L66-68）身份被破坏，也与本仓上一版行为不一致。

## 黄

1. **（A）step_queries 判据节点格式与仓内体系冲突。** L72 按 2 元组 `c[0]/c[1]` 平铺 AND（上游 Func
   格式）；仓内判据节点是 3 元组 `("call", name, args)`（check_once.py L18-22）且 OR/AND 交替递归
   （L23-49）。上游 step 的 query 段逐 check 走完整 check_once（reward_manager.py L365-369）。按仓内
   格式注册的 query 在 step_queries 处直接 `{**c[1]}` 对字符串展开 → TypeError。
2. **（C）vision=None 使 session._observe 以 TypeError 崩溃而非干净 BLOCKED。** L248 返回 `vision=None`；
   session.py L73-76 `n in raw['vision']` 对 None 抛 TypeError。BLOCKED 只护 `include_vision=True`
   （L252-254），而 session 调 `get_obs()` 不传参（session.py L64）。应返回 `{}` 走 require
   ("Missing cam_high") 的干净失败路径。docstring L226 "raw['vision']（含 color）" 未兑现。
3. **（D）确定性是断言不是证据。** pi05_service.py 不在仓内，服务端 sampling/温度/NPU 非确定性无法
   审计；脚本单次调用（L29-32），无双跑 sha 对拍自检；synthetic 噪声图使 "outputs track absolute
   state as expected"（commit message）在仓内无任何 artifact 支撑。
4. **（D）基线不足以做 W7 按维验收锚点。** docstring L7 声称 "逐维统计"，record 实际只有
   absmax/mean/row0（L42-44），其余 49×14 维缺失；W7 要求 "保存按维误差"（计划 L254）。且基线写死
   容器路径 /workspace/data（L47-48）未入仓（repo 内无该文件），record 无 numpy/权重/服务代码的版本
   哈希（"weights" 为描述字符串，L38）——锚点丢失后不可重建。
5. **（E）"W5b closeout" 与残留 "待 W5b" 措辞互相矛盾。** `query_support_arm_traj` 仍
   NotImplementedError "待 W5b（imitate_sorting/make_kong）"（L97、L311）；`run_reward` 其他任务判据
   "pending (W5b)"（L199）。要么 closeout 超额声明，要么这些措辞已过期，需二选一对齐。
6. **（C）env.instruction 默认 ""（L145），仅测试 fixture 手工注入**；接 session 后 reset.json /
   metadata 的 instruction 将为空串，任务指令注入点尚无落位（与本轮 get_obs 声称的契约配套缺口）。
