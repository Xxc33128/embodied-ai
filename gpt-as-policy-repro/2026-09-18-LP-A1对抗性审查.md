## 二、P1 发现（验收结论不可靠）

### P1-1 指纹硬门对 fixture 布局全盲；"物理状态 reset 间逐位确定"过宽；图像差异归因 OSMesa 未隔离

**链条一：set_init_state 不恢复 fixture 布局。**
`ControlEnv.set_init_state` → `regenerate_obs_from_state` → `set_state` → `sim.set_state_from_flattened`（LIBERO-PRO `libero/libero/envs/env_wrapper.py` L133-141）：

```python
def set_state(self, mujoco_state):
    self.env.sim.set_state_from_flattened(mujoco_state)
```

`set_state_from_flattened` 只恢复 time/qpos/qvel（gap-sim 内 robosuite 1.4.0 `utils/binding_utils.py` L1157-1170，`self.data.time/qpos/qvel`，连 `act` 都不恢复）。fixture 的 `body_pos/body_quat` 是模型场（model field），不在任何 sim state 内——**不被配对初态覆盖**。

**链条二：每次 reset 都随机重采样 fixture 布局。**
robosuite `environments/base.py` L128 `self.deterministic_reset = False`（仅在 `reset_from_xml_string` L551-560 临时置 True，本流程不经过）；`env.reset()`（L246-251，hard_reset=True）销毁并重建 sim 后 `_reset_internal()` → BDDLBaseDomain `_reset_internal`（`bddl_base_domain.py` L736-776）在 `if not self.deterministic_reset:` 分支执行 placement 采样，fixture 分支：

```python
body_id = self.sim.model.body_name2id(obj.root_body)
self.sim.model.body_pos[body_id] = obj_pos
self.sim.model.body_quat[body_id] = obj_quat
```

采样器为 `MultiRegionRandomSampler`（`libero/libero/envs/regions/base_region_sampler.py` L62-83）：`np.random.uniform(low=min, high=max)`。以 libero_goal 所审任务族 BDDL 为例（`bddl_files/libero_goal/put_the_bowl_on_the_stove.bddl`，服务器实测读取）：

- stove_region ranges `(-0.42, 0.2, -0.4, 0.22)` → **2cm×2cm 区域，每次 reset 均匀随机**；
- cabinet_region `(0.02, -0.25, 0.04, -0.23)`、wine_rack_region `(-0.27, -0.27, -0.25, -0.25)` → 同为 2cm×2cm。

即每 reset 随机流前进一步（seed(0) 仅在 `__init__` 播一次），**flat_stove_1 / wooden_cabinet_1 / wine_rack_1 的世界位姿每次 reset 几乎必然不同（±1cm 级）**。

**链条三：指纹对上述扰动全盲。**
`fingerprint_state`（libero_session.py L91-104）覆盖 qpos/EEF/gripper/object-state。object-state 由 `_setup_observables` 的 `for (i, obj) in enumerate(self.objects)`（`bddl_base_domain.py` L470）生成，而 `self.objects = list(self.objects_dict.values())`（L383），`objects_dict` 只在 `_load_objects_in_arena` 填充可移动物体（`problems/libero_tabletop_manipulation.py` L55-58），fixtures 只进 `fixtures_dict`（L47-51）。**object-state 不含任何 fixture**。可移动物体 qpos 又恰好被 set_init_state 完全覆盖 → 观测到的"逐位一致"是构造性保证，对场景布局漂移零灵敏度。

**链条四：成功判定语义随 fixture 漂移。**
目标谓词 `(On akita_black_bowl_1 flat_stove_1_cook_region)` 由 `_check_success → _eval_predicate → object_states_dict`（problem 类 L135-154）求值；`flat_stove_1_cook_region` 是随 stove body 移动的 site（SiteObjectState，`bddl_base_domain.py` L242-249）。碗位姿被 init state 锁定、stove 位姿每 reset 随机 ±1cm → **reset 间"成功"的边界语义本身在协议内漂移**。

**链条五：图像差异归因未隔离，且模块内自相矛盾。**
- libero_session.py L55-56 注释："预热后**同物理状态的渲染逐位稳定**"（作者自己实测的渲染器行为：同状态 → 位级稳定）。
- 同文件 L96-97 却说："渲染图像则有 **OSMesa 逐次微小非确定性**（mean |Δ|≈3 灰度、~20% 像素有差）"。

两者矛盾：若同物理状态渲染逐位稳定，而可移动物体+机器人状态逐位一致（evidence JSON），则 reset 间图像差**不可能来自渲染器**，只能来自未被指纹覆盖的状态差——按链条一至四，头号嫌疑正是 fixture 布局漂移。"渲染器非确定性"与"场景重采样"两种解释没有任何一次对照实验隔离（无 fixture body_pos 指纹、无同状态双渲染 diff），evidence JSON 也无空间分布分析支撑声明中的"差异集中于物体区域"。

**对验收的影响**：
1. 计划 v0.2 §4 LP1 的"reset 指纹一致性测试"在实现定义下通过，但其要支撑的"同 case 重置稳定"只对 robot+movables 成立；lock `lp_a1.render_discovery` 把 mean≈3/255 的图像差记为"OSMesa 逐次微小非确定性"，是未经隔离的归因。
2. LP-A2 的"与 A1 同初态配对"将继承一个未声明的噪声源（每 reset ±1cm 场景抖动）。这本身与论文协议同构（openpi `examples/libero/main.py` L93-97 同样 reset→set_init_state，LIBERO-PRO 论文方协议相同），**不伤论文可比性**，但必须显式入档，否则配对差值的归因模型是错的。

**要求（解除 P1 的最小动作）**：一次性只读实验——(a) 对 3 次 reset 各哈希 `sim.model.body_pos[fixture root bodies]`；(b) 同一物理状态连续渲染 2 次做 image_diff。两者把 P1-1 的两种归因彻底分离；随后把 fixture 位姿哈希并入 `fingerprint_state`（或在 lock 中显式声明"场景布局 reset 间协议内在扰动 ±region/2，与论文一致"）。

## 三、P2 发现（显著缺口）

### P2-1 图像容差只监控 agentview；腕部相机（策略输入）零监控

### P2-2 容差数值无推导、样本 n=4；lock 数字与存档证据不可对账

## 六、必查清单逐问回答

**Q1 协议合规 vs 计划**：计划 v0.2 §4 LP1 原文仅"reset 指纹一致性测试"（"同 case 重置的观测指纹稳定"为验收方的 paraphrase）。定性：把图像移出硬门是**被迫且正当的**——同栈下位级观测指纹不可能逐位稳定（作者自己记录的首渲染暂态差至 185/255 即渲染器层面证据），字面执行计划反而不可通过。但现实现把"fixture 布局"也连带静默排除（见 P1），这不是渲染器逼的，是指纹设计的真空。图像非确定性本身（若确为渲染器行为）：**记录即可，不必追因至逐位稳定**——openpi/LIBERO-PRO 论文协议跑在同类 OSMesa/EGL 栈上，论文口径是 50 集/任务的统计成功率，不要求图像位级复现；追 OSMesa 线程调度属于过度工程。**必须做的替代动作**是 P1-1 的两个一次性对照实验，把"渲染器噪声"与"场景重采样"分离归因后各自入档。

**Q2 适配器忠实性**：`.env.env._check_success()` 对全部 6 个 problem 类成立（证据见确认清单 5）；配对初态原样使用属实，但 `env.reset()` 的 robosuite 随机化被 set_init_state 覆盖的**不是全部相关状态**——time/qpos/qvel 被覆盖，fixture `body_pos/body_quat` 不在其列且每 reset 被重采样（P1 链条一、二）。

**Q3 指纹覆盖面**：qpos/EEF/gripper/object-state（movables pos/quat/rel）已覆盖；遗漏：fixture 位姿（关键，见 P1）、site（movable 附着 site 可经 qpos 传递确定，fixture 附着 site——如 stove cook_region——无覆盖）、qvel。图像移出硬门的后果由 image_diff_stats 部分补偿，但只看 agentview、无腕部相机、无空间分析（P2-1）。

**Q4 统计与容差**：n=4、单任务单日，容差无推导记录；evidence JSON 与服务器一致（md5 同），与声明数值一致（对 4 对差的复算），但 **lock 中 3.1/19.5%/6.4% 与存档证据对不上账**（P2-2）。

**Q5 流程卫生**：Mac skip 处理正确；`/workspace` 硬编码路径为已知约定、vendored 缓解有效；commit 一致；wait_steps dummy（gripper -1）与 openpi 逐字一致且扰动被 hard reset 归零。遗留：lock 自相矛盾、测试无存档日志、185/255 无出处（P3）。
