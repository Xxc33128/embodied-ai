## 2. P2 审查结论

### 2.1 总结结论

P2 的科学结果可以接受，决策为：

```text
NO_INCREMENTAL_ARM_GROUP_EFFECT
```

P2 将 14 个手臂关节的 MuJoCo armature 统一设置为 Isaac runtime 值 `0.01`。其中右肘已经在 P1 中完成匹配，所以 P2 的主问题是：其余 13 个手臂关节是否能在 right-elbow-only 基础上继续改善完整 `dance_9` 的 Sim2Sim 一致性。

答案为没有得到增量改善。`ARM_ONLY` 相对 `right-elbow-only`：

- 13 个新增关节的主指标变差；
- 29 关节整体误差变差；
- 14-body 位置略有改善；
- body orientation 明显变差并触发系统保护门禁；
- right elbow 原有收益基本保留。

统一修改整个手臂组的 armature 会引入闭环系统代价。当前证据支持“关节级参数需要逐项验证”，不支持“所有手臂关节统一复制同一 armature 值”。

### 2.2 关键数字

以下结果由包内 trace 独立复算，和 `04_analysis/p2_final_gate.json` 一致。

## 9. Step P3-1：实现延迟并建立 D0 延迟语义门禁

这是 P3 最重要的有效性步骤。D0 未通过时禁止解释动作结果。

### 9.1 runner 修改原则

现有两个 runner 都会拒绝非零 delay。创建 P3 专用副本后：

1. 只解除 `fixed_delay_ms=20` 的拒绝；
2. 保留 `0 ms` 和 `20 ms` 两种固定配置；
3. 延迟放在 `q_des → PD/actuator` 路径；
4. 每个 physics step 都更新 FIFO；
5. 两侧使用相同的 first-q_des prefill；
6. manifest 写入请求延迟和实测延迟；
7. trace 同时记录请求值和执行器实际接收到的值。

禁止把 20 ms 写成 sleep、渲染延迟或 observation 延迟。禁止只在 manifest 中修改数字。

### 9.2 必须增加的日志字段

控制周期字段：

```text
q_des_requested       shape=(n_control, 29)
q                     shape=(n_control, 29)
action                shape=(n_control, 29)
```

physics substep 字段：

```text
q_des_effective_substep shape=(n_control, physics_steps_per_control, 29)
```

建议同时保存：

```text
tau_substep
physics_time_substep
fifo_index_substep
```

Isaac 当前的 `actual_processed_q_target` 可能仍位于 actuator delay 之前，不能直接把它视为有效延迟目标。必须从 delayed actuator 输出端或 PD 实际输入端读取 `q_des_effective_substep`。

MuJoCo 必须记录 `q_des_eff`，不能只记录每个控制周期的原始 `q_des`。

### 9.3 纯 FIFO 单元测试

构造标量序列：

```text
输入：0, 0, 1, 1, 1, 0, 0 ...
```

分别验证：

- Isaac FIFO 输出相对输入恰好滞后 4 个 physics step；
- MuJoCo FIFO 输出相对输入恰好滞后 10 个 physics step；
- 0 ms 输出逐点等于输入；
- reset 后 prehistory 为第一个有效输入；
- episode reset 不携带上一 episode 的缓存。

输出：

```text
01_delay_gate/fifo_unit_test.json
```

JSON 至少记录 requested steps、measured steps、measured ms、max value error 和 pass。

### 9.4 引擎内集成脉冲测试

在两侧分别运行一个短测试，不运行完整舞蹈结论。向一个不会造成危险的目标关节注入可识别的 `q_des` 脉冲，并记录请求值与 PD 实际输入值。

门禁：

```text
Isaac measured_delay_steps == 4
MuJoCo measured_delay_steps == 10
abs(Isaac measured_delay_ms - 20.0) <= 2.5 ms
abs(MuJoCo measured_delay_ms - 20.0) <= 1.0 ms
非目标关节没有被脉冲修改
两侧 prehistory 规则一致
```

实测值必须从 trace 计算，manifest 常量不能代替测量。

### 9.5 0 ms 回归门禁

## 14. P3 结论规则

P3 将有效性判断和物理结果分开。

### 14.1 有效性决策

| 条件 | 结果 |
|---|---|
| D0 任一门禁失败 | `INVALID_DELAY_IMPLEMENTATION` |
| 0 ms 回归失败且没有成对重跑 | `INVALID_BASELINE_PAIRING` |
| trace/hash/shape/finite 失败 | `INVALID_P3` |
| 全部有效性门禁通过 | `VALID_P3` |

### 14.2 物理结果标签

| 现象 | 标签 | 解释范围 |
|---|---|---|
| 两侧 20 ms 均存活，连续指标退化较小 | `BOTH_TOLERATE_20MS` | 当前 dance_9 和控制栈具备基础延迟容忍度 |
| 两侧均存活，但某侧多项主指标明显退化 | `ASYMMETRIC_DELAY_SENSITIVITY` | 两侧执行语义或动力学对延迟敏感度不同 |
| 一侧提前失败 | `ONE_ENGINE_DELAY_FAILURE` | 记录 failure time 和失败前连续指标 |
| 两侧均提前失败 | `BOTH_FAIL_AT_20MS` | 20 ms 超出当前策略的基础容忍范围 |

工程预警线可以设置为主指标相对退化超过 20%，但必须标为 `alert`，不要把它写成通用物理定律。无摔倒也要报告连续误差退化。

## 19. 最终报告需要吸收的 P2 经验

最终总结中应写入：

1. 隔离实验能够定位单关节机制，完整闭环实验负责验证迁移价值；
2. right elbow armature 对齐从隔离条件迁移到了完整 `dance_9`；
3. 将相同数值扩展到整个手臂组没有继续改善主指标；
4. 局部 position 指标改善可能伴随整体关节和 orientation 代价；
5. Sim2Sim 对齐需要 joint-specific 证据，统一参数复制风险较高；
6. `q → observation → action/q_des → actuator` 的闭环会传播局部参数变化；
7. 资产相同、接口相同和执行时序相同属于三类独立门禁；
8. 延迟实验必须记录执行器实际收到的 target，不能只记录策略请求 target；
9. validity gate 和物理效果 gate 需要分开；
10. 视频用于展示，trace、哈希和可复算指标构成结论证据。

P2 研究已经完成预注册的决策任务。下一项新增仿真应聚焦 P3 最小延迟实验。
