这一步未完成前，不发布任何新的实验代码。

### 2.2 冻结唯一 Isaac 参考环境

不能把 `5.1.0 / 0.48.0` 的结果写成 `5.0 / 2.3.2` 的结果。先做以下二选一决策：

#### 方案 A：恢复原计划版本

使用 Isaac Sim 5.0 + Isaac Lab 2.3.2 重新执行 exporter、capture 和 gate。

适用于：官方 SONIC checkpoint 和仓库说明确实以这套版本为准。

#### 方案 B：正式重新冻结当前可运行版本

如果官方 checkpoint 能在当前 Windows Isaac 环境稳定运行，则把实际 Isaac Sim 版本、Isaac Lab 源码 commit/tag、PhysX、Kit、Python、driver 和 CUDA 全部写入新 fingerprint，并将它作为新的实验参考环境。

注意：`Isaac Lab 0.48.0` 必须进一步确认是哪个 Python distribution 的版本，不能只依赖包名输出。至少记录：

```text
Isaac Lab 源码目录
git remote
git commit
git describe/tag
Python distribution 名称与版本
Isaac Sim build/version
PhysX/Kit build
```

推荐判定：先在当前环境运行官方 checkpoint 的 Isaac-only sanity。如果 checkpoint 无法稳定复现，就回到方案 A；如果能够复现，再采用方案 B，但所有报告必须明确写“重新冻结后的版本”。

### 2.3 排除循环验证

当前 gate 的结果接近精确相等，这是好信号，但还必须证明不是共享公式造成的必然结果。

Isaac trace 的字段必须分别从正式环境中读取：

- observation manager 输出的各 named block 与最终 actor observation；
- policy 原始 action；
- wrapper/action manager 裁剪后的 action；
- actuator 实际 target；
- PhysX articulation/actuator 的实际 applied torque 或对应正式 runtime buffer；
- reset、history 与 action 生效 substep 的真实时序。

MuJoCo trace 的对应字段必须从正式 `MuJoCoEnv`/模型数据中读取：

- 环境实际生成的 observation/history；
- 环境实际 action clipping 和 target；
- 每个 physics substep 实际写入的 `data.ctrl`/`qfrc_applied` 或正式控制量；
- `mj_forward`/`mj_step` 后的正式状态。

共享 `common.py` 可以用于格式校验、名称映射和 state-set 读取，但不能同时替两个引擎生成 observation、target 和 torque，再把生成结果当成引擎证据。

需要增加的反向测试：

- 故意交换两个 Isaac runtime joint index，gate 必须失败并指出关节；
- 故意改变 Isaac history 更新时间，gate 必须失败；
- 故意在 wrapper 多加一次 action clip，gate 必须失败；
- 故意让 MuJoCo torque 晚一个 substep 生效，gate 必须失败；
- 故意改变 quaternion 顺序或符号处理，rotation gate 必须失败。

## 3. Phase 8A：建立零改参的 18-case 成对物理基线

### 3.1 本阶段目标

使用当前 Maxwell 物理配置，不修改任何参数，分别在 Isaac 和 MuJoCo 运行完整 18-case：

- 6 个代表性关节的 joint step；
- 4 个 zero-torque free fall；
- 8 个 fixed-PD landing。

第一轮只测量差异，不设物理通过阈值，不挑选“最好参数”。

### 3.2 接触模型先冻结，不急着补手部 mesh

当前 Isaac/MuJoCo collider 数量为 54/40。不能只凭 collider 总数判断等价，必须生成 collision contract，逐个记录：

```text
canonical body
shape/type
pose/size
material
contact mask
self-collision
是否进入本轮 benchmark
```

手部 18 个 mesh 的建议：

- 如果本轮动作没有手部接触、手部自碰撞或物体交互，则两侧一致关闭手部接触，并在 contract 中明确排除；
- 不要为了让数量相等而盲目补 mesh；
- 如果最终 checkpoint 包含手部接触，再单独建立 hand-contact profile 和测试场景。

本轮优先保证脚底、小腿、躯干和地面的碰撞语义一致。

### 3.3 固定实验条件

两侧必须一致：

- canonical 29-DoF joint order；
- 初始 root pose、q、qd；
- physics/control timestep 与 decimation；
- 重力；
- Kp/Kd、default pose、action scale、effort limit 和 torque clip；
- case seed；
- 地面高度、摩擦语义和碰撞启用范围；
- 每个 case 的仿真时长与采样率；
- 模型、scene、checkpoint、motion 和 config SHA-256。

正式运行前，必须确保 Phase 7 使用的无碰撞 P0/P1 配置没有泄漏进 Phase 8。

### 3.4 fit/holdout 不得改动

沿用已经冻结的 13 个 fit case 与 5 个 holdout case：

- fit 只用于选择参数；
- holdout 只用于决定候选能否晋级；
- 看到结果后不得重新划分 case。

### 3.5 记录指标

Joint step：

- q/qd/torque 曲线误差；
- rise time；
- overshoot；
- settling time；
- steady-state error；
- 最大 qdd；
- torque saturation ratio。

Free fall / PD landing：

- touchdown time；
- GRF peak 与 impulse；
- penetration depth；
- 接触期足端滑移；
- root displacement 与 rotation；
- energy change；
- q/qd/torque；
- torque saturation ratio。

不同单位的指标分别报告 MAE、RMSE 和 max error，不能把米、弧度、牛顿、焦耳混成一个未经归一化的总分。

### 3.6 Windows 运行模板

以实际 Python/Isaac 启动方式替换 `<python>`，配置文件必须是已经冻结并记录 SHA-256 的正式配置：

```powershell

.\scripts\cross_engine\run_windows_suite.ps1 `

<python> -m gear_sonic.cross_engine.benchmark_compare `

  --mujoco-root artifacts/cross_engine/phase8_baseline/mujoco `

  --output-json artifacts/cross_engine/phase8_baseline/paired_comparison.json `
  --output-markdown artifacts/cross_engine/phase8_baseline/paired_comparison.md
```

如果实际 Windows 分支的 CLI 或输出目录结构已经改变，应以 `--help` 和代码为准，但不得改变 case 定义和 fit/holdout 划分。

### 3.8 Phase 8A 停止条件

以下任一情况出现即停止，不进入参数优化：

## 4. Phase 8B：分参数族优化 MuJoCo

只有 Phase 8A 成对基线完整后才开始。

### 4.1 永久保留三条配置

```text
official_sonic_15dof：旧 SONIC sim-to-sim 参考，不作为 29-DoF 默认值
maxwell_29dof_baseline：当前冻结基线，永不被候选覆盖
calibrated_29dof_candidate：当前待验证候选
```

SONIC 15-DoF 参数只能作为候选来源和对照，不能直接宣称为 PhysX 等价值。

### 4.2 优化顺序

一次只允许修改一个参数族，建议顺序：

1. timestep、decimation、integrator/substep 语义；
2. mass、inertia、CoM；
3. Kp/Kd、armature、damping、friction loss、effort/velocity limit；
4. 脚底碰撞几何及其位姿；
5. friction、restitution、margin/contact offset；
6. MuJoCo `solref`、`solimp`、`impratio`、`cone`、`iterations`。

注意：模型里可以直接从 Isaac runtime 导出的质量、惯量、CoM 和限位，优先做语义一致化；不可映射的 PhysX/MuJoCo solver 参数只能做行为标定，不能建立未经验证的数值换算。

### 4.3 每次实验的最小记录

```text
candidate_id
parent_candidate
git_commit
config_sha256
changed_parameter_family
before/after values
parameter source（Isaac runtime / Maxwell / SONIC / search）
fit metrics
holdout metrics
failed cases
checkpoint status
decision（reject / keep-for-analysis / promote）
```

### 4.4 候选晋级规则

候选只有在以下条件全部满足时才能晋级：

- fit 集主要目标改善；
- holdout 不出现实质退化；
- 没有新的 NaN、穿透、抖动或长期力矩饱和；
- 误差改善来自可解释的参数族，而不是同时修改多组参数；
- 与 Maxwell baseline 和上一候选相比都有完整报告。

不要在第一轮使用 PPO 微调补偿物理错误。

## 5. Phase 9：官方 checkpoint 双引擎裁决

选择 Phase 8B 晋级的候选后，使用完全相同的官方 SONIC checkpoint 和固定 sample motion，分别运行 Isaac 和 MuJoCo。

硬门：

- 两侧都完成动作片段；
- 不跌倒；
- 无异常穿透；
- 无长期 torque saturation；
- 无 observation/action NaN；
- checkpoint、motion、control profile 和 joint mapping SHA 一致。

比较指标：

- root/feet tracking；
- 存活时间；
- 足端滑移；
- GRF 与触地时序；
- action/torque 抖动；
- Isaac 与 MuJoCo 指标保持率。

如果物理指标改善但 checkpoint 在任一引擎失效，候选立即否决，不能成为默认配置。

## 6. Phase 10：留出动作、扰动与稳健性

单一 sample motion 通过后，再增加：

- 未用于标定的 motion；
- 不同初始高度、姿态、水平偏移和速度；
- 小幅质量、摩擦和控制延迟扰动；
- 多个 deterministic seed；
- 必要时独立的手部接触场景。

如果不存在一组固定参数同时改善留出关节响应、足端冲量、滑移和 root motion，则停止追求单点精确匹配，转向：

- 围绕标定值做物理随机化；或
- 研究低层跨引擎 adapter。

这两条路线必须作为新实验，不得悄悄混入已经冻结的 baseline。

## 7. 最近的具体方向

当前不要开始修改 MuJoCo 参数。最近的正确顺序是：

```text
撤销 PAT并安全 push
    ↓
确认唯一 Isaac 版本/commit
    ↓
证明 capture 来自两侧正式 runtime，而非共享公式重算
    ↓
重新运行环境检查、测试、exporter 与 interface gate
    ↓
冻结 collision contract
    ↓
运行零改参完整 18-case paired baseline
    ↓
返回聚合结果并冻结第一轮评价阈值
    ↓
才开始第一个参数族实验
```

建议第一个真正的物理实验不是直接调 `solref/solimp`，而是先确认 timestep/control timing 和无接触 joint-step 响应。如果 joint-step 已不一致，优先审计 actuator/passive 与控制生效时序；如果 joint-step 一致而落脚差异大，再进入脚底碰撞、材料和 solver 标定。
