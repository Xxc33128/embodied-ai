# bowl 标准测试流程：各模型共享20个初始化场景

> v1.0，2026-09-15。依据用户本轮要求制定。本文是后续正式实验的标准；此前mock、GLM试跑和Codex交互成功演示均为开发记录，不纳入正式成绩。本轮仅制定规范，没有启动10次或20次模型实验。
> 证据口径：现有接口/代码事实为E1，安装版本为E2；以下新增预算、数据集划分、提示词与操作规程为本项目规范选择（E3），不冒充RoboCurve原评测的完整原样配置。

## 1. 实验设计

**问题：在相同场景、相同观测与工具、相同预算下，不同模型能否独立把红块放入碗中？**

- 每个模型20个正式trial，每个trial对应一个预先固定的初始化场景，每模型每场景只取首次正式尝试。
- 正式场景种子固定为**2000–2019**，开发集使用1000系列及此前已用场景，两者分开。模型不能获得种子编号或由种子推导的物体位置。
- 每个trial使用新的模型上下文、环境实例、控制器状态和噪声随机数状态；trial内部允许使用自己的观测与动作历史，trial之间不传递经验。
- 同一个scene在所有模型间共享初始机器人状态、物体位姿/尺寸、碗、相机、物理参数和执行噪声生成规则。模型是主要比较因素。
- 同种子只保证冻结实现下环境可重放，不保证模型输出确定性，也不意味着模型执行不同步数后仍处于同一物理状态。
- 统一环境为robosuite Panda + OSC bowl。与原真机YAM评测有差异；结果作为仿真模型对照，不能直接解释为原报告成功率的重现。

配套文件集中在[bowl-eval-v1](bowl-eval-v1/)：`protocol.json`、`seeds.csv`、`prompts/`与空白`results-template.csv`。它们构成同一个版本，不复制多份独立修改。

## 2. 种子不够，还要冻结初始化

**固定三元组**：`eval_seed=0, scene.init_seed=2000+i, epoch=0`，i=0…19。当前harness通过CRC32派生实际环境seed，完整映射已经写入`seeds.csv`；不要直接把scene seed传给环境reset来冒充同一场景。[E1：inspect-robots `rollout.py::derive_seed`]

正式批次开始前，运行一次不调用模型的场景生成/复位检查，生成20份`initialization.json`和三路初始PNG。每份至少记录：

- scene seed、实际环境seed、环境版本、源文件/资产/配置SHA256；
- 完整仿真初始状态（含qpos、qvel、act等非空状态）、控制器复位参数、噪声seed；
- 实际方块位置、四元数、尺寸；碗的位置与几何版本；
- 初始机器人本体观测和三相机PNG哈希。

后续每个模型每个trial先按相同reset流程重建，**在模型首次调用前**与对应标准初始状态核对。固定本机软件/渲染栈时，状态逐项对比并检查图像；跨机器若出现数值或图像差异，先检查、单独记录环境条件，不能只看种子相同便认定初始化一致。不能仅恢复qpos而遗漏控制器内部状态或噪声源。

当前随机分布保留为：方块x∈[-0.12,-0.04]m、y∈[-0.10,0.10]m、yaw∈[-0.1745,0.1745]rad。当前方块半边长也在0.020–0.022m内采样；每个种子的实际尺寸一并冻结，不能让各模型重新抽尺寸。[E1：robosuite_bowl_env.py]

场景检查只排除无法初始化、图像损坏、物体初始相交等环境无效情况，不按模型能否成功筛选。若存在无效场景，保留证据并修订整个场景集版本；任何已运行模型必须在新版本重新完成整组测试，不能只替换其失败场景。

## 3. 提示词和模型可见信息

### 3.1 固定任务句

正式任务提示使用同一英文原文，避免为不同模型另行翻译：

> Pick up the red block from the table and place it inside the blue bowl.

中文含义：把桌上的红色方块拿起来，放进蓝色碗里。

### 3.2 固定系统提示与接口说明

唯一标准文本为`prompts/system.txt`和`prompts/embodiment.txt`。系统提示规定：根据图像和本体状态，通过工具完成任务；每轮恰好一个工具调用；移动带简短观察/理由；最多20次模型调用；不能请求场外帮助。接口说明只给单位、坐标系、动作边界、观测含义与夹爪语义。

**不提供**物块/碗的精确位置、成功动作序列、抓取高度答案、图像到世界坐标的未经校准映射、之前试次经验、特定模型专用提示。桌面高度属于机器人工作空间说明，可提供；物体真值留在评分侧。

首个请求与后续请求均由同一适配器构造，顺序固定为：系统提示 + 接口说明；任务句；机器人观测；三路图像；工具JSON schema。精确文本、字段顺序、schema与图像处理方式按批次冻结。`protocol.json`记录提示词SHA256。

### 3.3 可见观测

- 相机：front、side、wrist，每路224×224 RGB；统一图像方向，不做模型专用裁剪/放大/箭头标注。
- 文本：实际测量的末端位置、姿态、夹爪开度，关节位置、速度、执行器力矩；字段、精度、单位相同。
- 每次请求保留完整的本trial文本/工具历史，图像只保留最近**2次观测**，所有模型一致。
- 不给模型环境seed、cube_pos、cube_quat、contact/grasp布尔真值、success或phase分数、脚本诊断。终止信号由harness处理，不作为额外解题提示。
- 子agent只访问当次公开请求及其图像，不读取项目代码、AGENTS、旧日志、评分目录或其他trial，不运行自定义控制代码。

### 3.4 新上下文与接入方式

API路径：每trial新建policy/client或经验证完整reset；不传前一trial的conversation/thread id、prior_learnings、检索/记忆、hindsight，不人工追加反馈。结束后关闭实例。服务端透明缓存另记，不把它与有内容的跨trial记忆混为一谈。

子agent路径：至少每trial新建`fork_turns="none"`子agent，父agent只给中性的请求读取/单工具回复规程；不提供模型表现、成功经验或操作建议。为了严格匹配API“最近2组图像”与完整显式请求，推荐**每次决策也新建无历史子agent，只装载当次完整请求**；若复用一个子agent完成整trial，它会保留此前已看过的图像/额外运行指令，应把该接入方式单独分组并披露，不能标记为完全等同的API条件。

所有参与者的任务信息采用同一标准；API包装格式可以因供应商不同而转换，但转换不能增加/省略观测、预算或工具说明。保存转换前的规范请求及转换后的实际wire请求，做等价性核对。原Astra使用responses，本地GLM使用chat这一差异必须披露。无法证明信息等价的接入方式分组呈现。

## 4. 固定运行参数

| 项目 | v1标准 |
|---|---|
| 每模型trial数量 | 20；一个种子一次正式尝试 |
| 模型决策预算 | 最多20次LLM调用，含无效工具回复、done/give_up；不把900步当作900次调用 |
| 控制步预算 | 最多900步；当前20Hz，最多45秒仿真时间；推理等待墙钟另计 |
| 推理effort | 统一请求medium；记录供应商是否支持/实际生效，不能把同名档位说成同等算力 |
| 速度限制 | max_speed_frac=0.25；控制器、动作范围与native max_step全模型相同 |
| 动作 | 现有move_to绝对x/y/z/yaw/二值夹爪；done/give_up；工具schema冻结 |
| 执行时序 | 按现有toolset动作chunk执行，结束即返回观测；不另加脚本沉降或按模型延长执行 |
| 噪声 | 当前默认(0.0015,0.001,0.017)及其实际代码换算；同trial seed重置；只声明输入参数，不冒充校准后的实际末端标准差 |
| 额外帮助 | 无人为提示，无自动抓放宏，无跨trial学习 |
| 成功/终止 | 统一环境success、模型done/give_up、预算耗尽、基础设施错误；原始终止原因单独保留 |

当前存在“重复指定gripper会改变chunk长度”的行为，v1保留并披露，所有模型都可使用相同工具。若决定修执行时序，应在正式批次前修好、重验并更新环境哈希；不能测到一半只为某模型补沉降。

temperature、模型采样seed、最大输出token等不得因模型成绩临时调整。v1保留原agent默认省略这些参数，记录每个端点的有效配置/不可确认项；若另设统一数值，只能在批次前建立新配置版本并完成兼容性检查。记录精确模型ID/快照、运行日期、API或子agent方式；未知版本写unknown，不能假装完全锁定。

## 5. 一次trial的标准操作顺序

1. 加载冻结的protocol、模型配置与seed行；检查代码/资产/提示词哈希。创建唯一attempt目录，已有目录不覆盖。
2. 新建环境并复位；核对初始化状态/初始图；启动连续视频与事件记录。
3. 创建无历史模型上下文，只发送标准系统提示、接口说明、任务、当前观测与工具schema。
4. 模型返回恰好一个工具调用。先保存原始回复，再由统一toolset验证与展开；保存每个展开后的低层动作和实际观测。
5. 每个控制步推进物理并录像。动作chunk结束后，按同一规则返回新观测。推理等待时仿真暂停；模型耗时不会暗中改变抓持物理。
6. success/done/give_up/任一预算耗尽或错误触发时停止；不追加解题动作或偷偷给额外调用。保存终帧、实际状态、最后模型请求与明确终止原因。
7. 关闭环境和上下文；完成视频编码、日志完整性检查与评分。模型不获得评分结果作为下一trial输入。
8. 进入下一个预定种子。20个全部结束后汇总，再分析失败与提出下一版本改进。

同一模型按seed表顺序执行。多个模型若交错运行，用预先固定的轮换次序（偶数trial按模型注册顺序、奇数trial逆序），避免根据结果选择先后；不要让模型看到自己的顺位。机器负载影响墙钟延迟，串行运行作为时长比较主条件。

## 6. 评分：动作意图、真实完成程度分开

主结果按原任务含义记录**历史最高阶段0–4**，结合视频与私有物理日志复核：

| 分数 | 达到条件 |
|---|---|
| 0 | 尚未达到与方块接触的阶段 |
| 1 | 机械臂/夹爪与方块发生实际接触；只接近不算 |
| 2 | 方块被抓起并离开桌面；碰撞弹飞不算抓起 |
| 3 | 持有方块并将其移到碗开口上方；看实际方块，不看目标坐标 |
| 4 | 松爪后方块落入碗内并达到最终放置状态；仍夹在碗上方不算 |

最高阶段只增不减，成功率按最终审核stage=4计算。`env_success`另存，保留自动判定与复核结论的差别；模型调用done或harness顶层status=success都不自动等于任务成功。

现有`_phase`仍有距离近似，不能直接作为最终评分；自动阶段为候选指标。复核者使用隐藏模型名称/顺序的纯画面视频和状态轨迹，先评阶段再看模型notes，避免被“我已经抓住了”的文字带偏。记录reviewer、时间和简短依据；边界样本追加独立复核，不改原始日志。

主表给出每模型成功数/20、平均最高阶段、各阶段达到数量；另给调用数、物理步数、仿真时长、墙钟时长与有实据的token/成本。按相同seed逐行对照，不仅报平均值。只有20个场景时结论限于该冻结场景集，不夸大泛化能力。

## 7. 每次必须保存的产物

| 产物 | 要求 |
|---|---|
| manifest/config | experiment id、协议版本、模型ID/接入方式、全部参数、seed映射、代码/包/资产/提示词哈希 |
| initialization.json | 标准初始状态及本次匹配检查；物体真值仅评分侧可见 |
| model_requests.jsonl / model_responses.jsonl | 每一次实际模型请求和回复，保留tool schema与图像引用、call id、时间、重试记录；禁止保存授权头或key |
| transcript.jsonl | 任务、观测文本、模型notes、工具错误与返回；不要求也不伪造模型内部思维链 |
| actions.jsonl | 原始工具参数及每个展开后的动作，关联call id、step id、坐标/单位与时间 |
| observations.jsonl / physics.jsonl | 机器人状态与私有物块/接触/评分轨迹分开；绝不把私有字段回流给模型 |
| frames/ | 初始、每次模型可见观测、结束时三路无损PNG；文件名含step/call/camera，SHA256可追溯到wire请求。保留模型看到的原图 |
| video/ | front、side、wrist连续视频，至少另有三视图并排review.mp4；每控制步一帧、20fps，含初始与终帧，不剪掉失败段。若只保存并排视频，必须可无损定位每个原224²视角，并在manifest声明 |
| timing.jsonl | 请求开始/返回、动作开始/结束、sim_time与wall_time；20fps视频表示仿真推进时间，不把无思考停顿视频当实际完成耗时 |
| result.json | success、stage_max、env_success、终止原因、错误类别、调用/步数/时长/token/成本、评分依据 |

建议目录：

```text
experiment-<id>/
  protocol.json  seeds.csv  versions.json  prompts/
  initializations/scene-01/ ... scene-20/
  <model-id>/<scene-id>/attempt-01/
    manifest.json initialization.json result.json
    model_requests.jsonl model_responses.jsonl transcript.jsonl
    actions.jsonl observations.jsonl physics.jsonl timing.jsonl
    frames/ video/
  summary.csv paired-by-seed.csv report.md
```

每个trial结束立即检查：视频可解码、帧数与步数对应、模型请求引用的图像存在、call/step编号连续、终止原因存在、私有字段未混入模型请求。失败录像也必须保存。token/成本拿不到填null，不写0；子agent账户用量不能由伪造API usage字段代替。

## 8. 失败、重试与冻结纪律

- 抓空、掉落、模型错误判断、无效工具调用耗尽预算、主动/强制give_up都保留为模型/执行结果，不换seed、不择优重跑。
- 网络、录制失败、进程崩溃等基础设施问题单独标记。只允许从同一标准初始状态以同一配置重跑整个trial，保留原attempt与重跑原因，采用第一个有效attempt；不得利用已看到的动作修提示词再重跑。HTTP传输重试不能让一个工具执行两次。
- 某scene仍缺有效attempt时，报告“已完成N/20、基础设施失败M”，不把缺失样本静默删去或假记为模型成功/失败。
- 正式批次期间不调模型提示词、相机、物理、评分或预算；需要改则另建protocol版本，并对所有模型完整重测20个场景。
- GLM无需先达到高成功率才能测试Astra。开发检查只确认环境、信息和执行接口可靠；冻结后真实低分也是有效结果。
