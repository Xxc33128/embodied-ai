## 3. 为什么 hip G2 不能按“只超 10%”放行

README 只强调 Isaac 稳态窗口漂移 `1.11e-4 rad` 比 `1e-4` 超约 10%，但 G2 原始数据还有更大的越线项：

| G2 项目 | 原计划阈值 | 实测 | 倍数/判断 |
|---|---:|---:|---|
| hip MJ other-joint peak | 1e-4 rad | 3.24e-4 rad | 3.24×，FAIL |
| hip Isaac other-joint peak | 1e-4 rad | 2.00e-4 rad | 2.00×，FAIL |
| hip MJ root drift | 1e-5 | 1.30e-4 | 12.96×，FAIL |
| hip Isaac root drift | 1e-5 | 7.93e-5 | 7.93×，FAIL |
| hip Isaac other-joint `t>=0.15` | 1e-4 rad | 1.11e-4 rad | 1.11×，FAIL |
| elbow Isaac other-joint peak | 1e-4 rad | 1.25e-4 rad | 1.25×，同样未过原始 peak gate |

当前 gate 脚本做了两项未经事先批准的门槛漂移：

1. 其他关节只用 `t>=0.15 s` 的“steady window”判定，把阶跃开始后的最大尖峰排除；
2. Isaac root 阈值从原计划的 `1e-5` 放宽到 `1e-4`。

这会让 elbow 被标为 G2 PASS，也会淡化 hip 的问题。clean isolation 的目的正是检查强激励刚开始时的约束有效性，因此不能删除 `0.10–0.15 s` 的峰值。

### 根因判断

两侧当前都不是物理上的固定关节/固定根，而是：

```text
substep 前写回 q0/root0
  → 让这些自由 DOF 参与一次物理积分
  → substep 后记录它们已经产生的漂移
  → 下一 substep 前再次写回
```

这是一种离散投影近似，不等价于真正的约束。hip 的初始力矩约 41 Nm，远大于 elbow 的约 3.8 Nm，所以刚开始阶跃时 root、waist 等自由 DOF 会在每个 substep 内被明显带动。两个引擎又使用 2 ms 和 5 ms 的不同 physics dt，投影误差会不同，正好污染跨引擎比较。

### 应采用的处理

优先方案：

1. Isaac 使用固定根 articulation/asset；
2. MuJoCo 使用 weld/equality 把 root 真正约束到 canonical pose；
3. 其余 28 个关节用两侧等价的固定关节、joint equality 或硬约束锁在 q0；
4. 被测关节是唯一保留的动态 DOF；
5. 继续记录 constraint force/impulse、root drift 和 other-joint drift。

如果实现硬约束需要较长时间，可以用“前后双投影”做 v2 smoke 诊断，但必须同时保存：

- `pre_projection_root_drift`；
- `pre_projection_other_joint_drift`；
- `post_projection_root_drift`；
- `post_projection_other_joint_drift`。

G2 仍应对 **pre-projection peak** 使用原阈值。仅在记录前写回并让 post-projection 数值变成 0，不算修复，因为目标关节在刚才的 substep 中已经受到了自由 root/其他关节的耦合影响。

## 4. 全量运行前还必须修的 gate 问题

### P0-0：打包的 Isaac runner 无法通过语法编译

独立执行：

```bash
python -m py_compile scripts/run_isaac_onnx.py
```

在第 564 行失败：

```python
q_now_pol[others_rt_pol := [...]]
```

assignment expression 放在 subscription 中需要额外括号；更稳妥的修法是不用 walrus，提前生成索引：

```python
others_pol_idx = [i for i in range(29) if i != jidx]
drift_others = float(np.max(np.abs(
    q_now_pol[others_pol_idx] - q0_pol[others_pol_idx]
)))
```

`n5_r_summarize.py` 和 `run_mujoco_step_test.py` 可以编译，只有打包的 Isaac runner 失败。与此同时，包内 stdout 显示 Isaac smoke 确实执行完成，因此出现两种可能：

1. 实际运行时使用的是另一份可编译 runner；
2. 实验跑完后修改/打包脚本时引入了语法错误。

无论是哪一种，本包都不能证明“所附脚本就是产生结果的脚本”。v2 必须：

- 三个脚本先全部通过 `py_compile`；
- 每次 manifest 保存 `run_isaac_onnx.py`、`run_mujoco_step_test.py`、`n5_r_summarize.py` 的 SHA256；
- 打包时校验 manifest 中的 runner hash 与包内脚本 hash；
- 将编译结果保存为 `checks/script_compile.txt`。

### P0-1：G1 的阶跃时间计算 off-by-one

当前代码：

```python
i = np.argmax(np.abs(np.diff(qdes[:, jidx])))
step_on = t_command_start[i]
```

`diff` 的索引 i 表示变化发生在 `i -> i+1`，应读取 `i+1` 行，或者直接查第一条非基线 q_des：

```python
changed = np.flatnonzero(np.abs(qdes[:, jidx] - qdes[0, jidx]) > 1e-8)
assert len(changed) > 0
first = int(changed[0])
step_on = float(t_command_start[first])
```

必须同时检查 Isaac、MJ native、MJ matched，并断言都是 `0.100 s`。

### P0-2：G1 检查不完整

下一版应检查：

- 三条 trace 的 t 严格递增；
- t0=0、tfinal=0.5；
- 样本数 26/251/251；
- 全部 29 个 q0 误差，而非只看被测关节；
- 全部 29 个 dq0；
- root initial pose/velocity readback；
- step amplitude、step joint 和 step time；
- native/matched 使用相同 q0、step、Kp/Kd、hash。

### P0-3：G6 不能在单次运行时写 PASS

当前：

```json
"G6_repeat": {
  "pass": true,
  "note": "单次运行"
}
```

这会让 elbow 的 `all_pass=true`，属于假 PASS。应改为：

```json
"G6_repeat": {
  "status": "NOT_EVALUATED",
  "pass": null
},
"smoke_pass_excluding_g6": true,
"all_pass": false
```

全量运行前先实现自动重复比较器，不能等 18 次跑完后“人工比对”。

G6 至少检查：

```text
同一条件三次 t/q/dq/q_des/torque 的 pairwise max diff <= 1e-6
manifest 中 runtime 参数、初态、XML/policy/motion hash 完全一致
三次 contact、saturation 和 gate 状态一致
```

### P0-4：MuJoCo manifest 的 final-time flag 算错

当前 251 点 trace 的最后时间确实是 0.500 s，但 manifest 写成：

```yaml
t_final_is_0_500: false
```

原因是用了 `n_rec * physics_dt`。应直接检查 `t_state[-1]`，或使用 `(n_rec - 1) * physics_dt`。

### P0-5：contact 不可用时会被假装成 0

Isaac 在 contact sensor 不存在时写 `-1`，但初始样本硬编码为 0；汇总器取 `max([0,-1,...])` 会得到 0，从而错误 PASS。

修法：

```text
任一 ncon/contact-force 样本 < 0 → status=UNAVAILABLE → G2 FAIL
```

另外 Isaac 当前测的是“净接触力非零的 body 数量”，不是 PhysX 的真实 contact pair count。字段应改名为 `contacting_body_count_estimate`，不要叫 `ncon`。本包 stdout 没有 sensor 缺失警告，当前这两次 smoke 的 0 接触力可以接受，但工具仍需修正上述退化路径。

### P0-6：common-state PD contract 证据没有完整打包

包内只有 Isaac 推进 20 ms 后的 `engine_torque_readback`，没有独立的 Isaac `pd_contract_at_common_state.json`；MuJoCo parity 目录也没有进入 ZIP。因此 README 中“层 1 已跨引擎逐关节比较”无法从本包复核。

v2 应包含 elbow/hip 两个关节的：

```text
isaac_parity/<joint>/pd_contract_at_common_state.json
isaac_parity/<joint>/engine_torque_readback.json
mujoco_parity/<joint>/pd_contract_at_common_state.json
mujoco_parity/<joint>/engine_torque_readback.json
pd_contract_comparison.json
```

common-state raw/clipped torque 的最大差必须 `<=1e-5 Nm`。

### P1：Isaac torque 只记录 control tick 最后一个 substep

当前 Isaac 每个 20 ms control cycle 内推进四次 5 ms，但 computed/applied torque 只在第四次之后读取。因此：

- hip 初始理论 PD 命令约 41.49 Nm；
- 图表汇总的 Isaac torque max 只有约 9.94 Nm；
- 这不是同一采样阶段，不能与 MuJoCo 的 41.49 Nm peak 直接比较；
- 如果前几个 substep 短暂 saturation、最后一个 substep 不 saturation，当前 `step_saturated_any` 也可能漏检。

建议保留 26 点 control trace，同时增加 101 点 `physics_substep_trace.npz`，逐 5 ms 保存 q/dq/q_des/computed/applied/saturation/root/contact。MuJoCo 再插值到这组真实 physics 时间进行 torque 对比。

若本周时间不够实现 substep torque trace，则删去跨引擎 torque max/MAE 结论，只保留 common-state PD contract 和 position-response 结论，并明确 saturation 由离线峰值相对 limit 的裕量证明。
