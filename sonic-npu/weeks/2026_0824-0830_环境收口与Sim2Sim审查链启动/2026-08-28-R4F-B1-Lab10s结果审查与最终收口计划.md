## 3. 必须修正的问题

## P0-1：重录 Lab 视频

### 观察证据

抽查视频 0、2、5 s：

- Isaac 单侧视频均为全黑帧。
- MuJoCo 视频能渲染，但机器人长期只有半个机身位于画面左缘。
- side-by-side 左半边全黑，右半边只看到部分 MuJoCo 机器人。
- 视频没有原计划要求的 run ID、engine、control dt、delay、gain 标注。

### Isaac 建议修改

当前 capture 代码把 sensor numpy view 直接加入列表：

```python
img = camera.data.output["rgb"][0].cpu().numpy()
video_frames.append(img)
```

优先改为：

```python
img = camera.data.output["rgb"][0].detach().cpu().numpy().copy()
video_frames.append(img)
```

理由：不 `.copy()` 时，保存的 numpy 数组可能共享后续被复用或清空的相机缓冲；运行中的 camera smoke 可以非黑，但最终编码出的所有帧仍会变黑。

同时建议：

1. 使用 Isaac Camera API 的 `set_world_poses_from_view(eyes, targets)`，避免自写 `look_at` quaternion 的顺序或轴约定错误。
2. 保存第 1、50、中间、最后一帧 PNG 作为录像门禁。
3. 编码后重新解码首/中/尾三帧，而不是只检查编码前内存中的 `img.max()`。
4. 输出黑帧比例；任一抽样帧 `max<=5` 或亮像素比例过低则录像 FAIL。

### MuJoCo 建议修改

当前代码在 `update_scene(data, camera=-1)` 后手动修改 `renderer.scene.camera[0]`，画面构图没有达到预期。改用显式 `mujoco.MjvCamera`：

```text
cam.type = mjCAMERA_FREE
cam.lookat = root position + [0, 0, 0.75]
cam.distance = 3.5～4.0
cam.azimuth/elevation 固定
renderer.update_scene(data, camera=cam)
```

验收要求：

```text
[ ] 0 s、5 s、9 s 机器人头、脚和双臂全部可见
[ ] 机器人不接触画面边缘
[ ] 相机可跟随水平位置，但距离和高度不突变
[ ] 1280×720，约 30 fps
[ ] 视频时长与仿真时长一致
```

### 重跑范围

只需重录 10 s 双侧视频；已有数值 trace 可以保留。若 runner 不能从 trace 离线回放，则以相同条件重跑一遍 10 s，并再次验证新 trace 与旧 10 s 前缀/全程是否一致。
