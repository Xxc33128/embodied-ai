## 0. 目标背景（为什么要装这套环境）

在 Windows 笔记本（AMD Ryzen 9 7845HX + AMD Radeon 610M 核显 + **NVIDIA RTX 5060 Laptop 8GB**，Blackwell sm_120）上搭建 **GR00T-WholeBodyControl / SONIC**（NVIDIA G1 人形机器人全身控制）环境。

最终目标不是完整训练 SONIC，而是建立 **Isaac–MuJoCo 物理对齐工作流**：
- **Isaac/PhysX = 黄金参考生成器**（golden traces），只跑 1 env、短 rollout、确定性状态注入、18 个物理 case；
- **MuJoCo = 被调教的学生**（candidate traces，逐参数族对齐）；
- 最后用官方 SONIC checkpoint（last.pt）做闭环裁决（Level 0–4）。

硬约束：
- **C 盘几乎满（曾剩 0GB）**：所有大文件装 E 盘（WSL 虚拟盘、venv、pip 缓存全部 E 盘）；
- **16GB 物理内存 + 8GB 显存**：非常脆弱，反复触发 OOM/断电重启；
- 国内网络：官方源被墙，pip/HF 需要镜像。

## 2. 遇到的问题与解法（按主题分类）

> 以下“现象 → 根因 → 解法”格式，与《防重复踩坑手册》对应条目互相引用。

### 2.1 显卡驱动 / 渲染层（全项目最大的坑，最高优先级）

#### 坑 1：`rtx.scenedb.plugin.dll` 确定性崩溃（跨 Isaac 4.5 与 5.1 两代 Kit）
- **现象**：Isaac Sim 4.5（Kit 106.5）和 5.1（Kit 107）都在**还没创建 World/PhysX 之前**，于 RTX/Hydra 渲染器创建阶段 100% 复现 access violation（0xC0000005），crash offset 完全固定。GUI / headless / Storm 渲染器 / IsaacLab experience 全部崩溃。
- **尝试过但无效**（浪费了大半天）：TLAS 实例上限调参、`cudaInterop=false`、注册表强制 python.exe 用 NVIDIA GPU、换 VC DLL、试 Storm。
- **根因**：NVIDIA 驱动 **610.88** 与 RTX 5060 Laptop（Blackwell GB207）的 RTX 渲染栈机器级不兼容，与 Isaac 版本无关。
- **解法**：回退到 **580.88**（Isaac Sim 5.1 官方测试驱动）+ 禁用 Parsec/MuMu 虚拟显示适配器 + 清理 C 盘 10.6GB CrashDumps → `smoke_isaac51.py` 原样复跑 PASS（app ready 32s / 100 物理步 OK）。
- **固化规则**：**永远不升/不改 NVIDIA 驱动（580.88 是修复不是默认值）**；出现 scenedb 崩溃先查 `nvidia-smi` 而不是改 DLL/调参数。
- 参考：《防踩坑手册》坑 1.1/1.2；`artifacts/phase3_gate1_report.txt`（FAIL 全程证据）、`phase3r2_isolation_report.txt`（PASS 全程证据）。

#### 坑 2：虚拟显示适配器干扰 GPU 枚举
- **现象**：Parsec Virtual Display、MuMu Virtual Display 存在时 Vulkan/DXGI 枚举混乱，叠加驱动问题放大崩溃。
- **解法**：`Disable-PnpDevice` 禁用两个设备（脚本 `disable_virtual_displays.ps1`），保持禁用。

#### 坑 3：headless 被切到 Vulkan → URDF importer 死锁
- **现象**：collect 脚本 headless 跑，URDF 导入在原生 C++ `import_robot` 处静默挂起（py-spy 可见 `urdf/impl/commands.py:145 do()`）；最小复现和 audit 用 D3D12 全通过。
- **根因**：渲染 API 被切到 Vulkan（某些路径注入），URDF mesh 解析在 Vulkan headless 下死锁。
- **解法**：所有 Isaac headless 脚本显式加 `--/renderer/activeApi=d3d12`。**遇到 URDF 卡死先查 activeApi，不要 strip mesh、不要改日志级别。**

#### 坑 4：kit 日志级别设 error → 让 URDF importer 卡死
- **现象**：`--/log/level=error` 下 URDF 导入正常推进变卡死（无日志可看，误判死锁）。
- **规则**：Isaac 脚本**禁止设 error 级日志**，保持默认 info。

#### 坑 5：`simulation_app.close()` Windows 收尾挂死
- **现象**：审计数据已打印、`Closing application` 出现，但进程卡在 PhysX 收尾，JSON 未写出。
- **解法**：导出/采集类脚本**先落盘 JSON/NPZ 再退出**，用 `os._exit(0)` 或推迟 close（官方 Maxwell 脚本同样做法）。

### 2.2 Python 依赖 / 版本兼容矩阵（最痛的认知类坑）

> 核心矛盾三角：
> - A. Isaac Sim 4.5 要：Python 3.10 + numpy<2.0 + torch.jit（torch ≤2.9 左右）
> - B. RTX 5060 (sm_120) 要：torch ≥2.7 且 cu128（cu126 不行）
> - C. Isaac Lab 要：与 isaacsim 匹配（2.1.x 兼容 4.5+py3.10；2.2+ 只有 cp311）
>
> 结论路径：**放弃 4.5 组合，走 Isaac Sim 5.1 + Python 3.11 + IsaacLab 2.3 + torch 2.7.0+cu128 + numpy 1.26**（后被冻结为 freeze_isaac.json，方案 B）。

#### 坑 6：torch nightly 2.12.0.dev 坏（c10.dll 损坏 + torch.jit 移除）
- **解法**：`pip install torch==2.7.1 torchvision==0.22.1 --index-url https://download.pytorch.org/whl/cu128 --force-reinstall`（4.5 环境）；5.1 环境用 2.7.0/0.22.0。

#### 坑 7：`--force-reinstall` 连带顶掉 numpy
- **现象**：装 torch 把 numpy 顶到 2.2.6，isaacsim 硬要求 `<2.0` → 兼容冲突。
- **规则**：任何大安装后先 `pip show numpy` 验证；冲突时固定 1.26.4（5.1）或 1.26.0（isaacsim 自动 pin）。

#### 坑 8：Isaac Sim 自带旧 VC++ 运行时遮蔽系统新运行时
- **现象（4.5 环境）**：启动加载 wheeled_robots 扩展的 osqp/qdldl 原生模块必崩；事件 1000 faulting module = `site-packages\omni\MSVCP140.dll`。
- **根因**：Isaac Sim 自带 VC 运行时 14.29（VS2019）遮蔽系统 14.51；VS2022 编译的新 pyd 混用旧运行时 → 崩溃。
- **解法**：把 `omni\` 下 8 个 VC DLL（msvcp140*/vcruntime140*/ucrtbase）替换为 System32 新版，原件备份 `vcrt_backup_omni\`。
- **备注**：5.1 环境未再出现此坑，但机制通用（新 pyd 崩溃先查 omni 目录 VC 运行时版本）。

#### 坑 9：依赖 pin 冲突 → 以 Isaac Sim 的 pin 为准
- **现象**：isaaclab 装完破坏 isaacsim 精确 pin（packaging/click/typing-extensions/fastapi/starlette/psutil）。
- **规则**：**Isaac Sim 是黄金参照，其 pin 永远优先**；isaaclab 的 pin 若运行时不被 import 可忽略（starlette 案例）；psutil 必须 5.9.8。

#### 坑 10：flatdict 构建失败 / venv 缺 wheel
- flatdict 4.0.1 旧式 setup.py 需 `pkg_resources` → `--no-build-isolation` + setuptools 78；
- venv 缺 `wheel` → `bdist_wheel` 无效，先补 wheel。

#### 坑 11：pip 清华源会拉 cu126 的 torch → 破坏 sm_120
- **规则**：装 torch 相关时附加 `--index-url https://download.pytorch.org/whl/cu128`，装完校验 `torch.__version__` 带 +cu128。

#### 坑 12：策略依赖链缺失（tensordict 等）
- **现象**：collect 加载 SONIC policy 时连环 `ModuleNotFoundError`：tensordict → pyvers → vector_quantize_pytorch → einx → torch-einops-utils → frozendict。
- **解法**：全家桶 `--no-deps` 安装（别碰 torch）；用 `grep -rhE '^\s*(import|from) [a-z_]+' gear_sonic/ | sort -u` 预检全链。

#### 坑 13：torio/torchaudio ffmpeg DLL 缺失
- **现象**：`libtorio_ffmpeg6.pyd` "or one of its dependencies" 找不到（文件在但依赖 ffmpeg dll 缺失）。
- **判断**：采集/评测不需要音频 → **不必修复**，只需按坑 17 屏蔽其日志。

### 2.5 系统资源 / 内存（16GB 机器的血泪，反复崩溃）

#### 坑 16：git-lfs 全量拉取 → 内存瞬间打满 → Event 41 断电重启（×2）
- **根因**：LFS smudge 链大量并发进程 + 大文件 inflate，16GB 内存瞬间打满。
- **硬规则**：全局禁止无界 `git lfs pull`/fetch；需要单资产时 `git lfs fetch --include="路径"`；clone/checkout 一律 `GIT_LFS_SKIP_SMUDGE=1`；大 git 操作前记录内存基线。

#### 坑 17：日志递归风暴吃光内存（5GB+）
- **现象**：python 进程涨到 5.2GB、CPU 满、stderr 刷 `RecursionError`。
- **根因**：collect 脚本 root logging DEBUG → torchaudio→torio 的 ffmpeg 失败重试 DEBUG 日志被 HydraLoggerBridge 转发给 loguru → loguru 渲染异常抛错又成新 record → **无限递归**。
- **解法**：`logging.getLogger().setLevel(WARNING)` + torio/torchaudio.io 三个 logger 设 CRITICAL + propagate=False。**新脚本禁止把 root logging 设 DEBUG**。

#### 坑 18：反复启停 Kit 拖垮系统
- **现象**：2 小时内反复 launch/kill Isaac（每实例 3-4GB），最终 bash 报 fork retry、PowerShell DLL 初始化失败、tasklist 都起不来。
- **规则**：每 2-3 轮 Isaac 运行自查内存；空闲内存 <3GB 立即停手；批次间清理 + 间隔。

#### 坑 19：agent 自身操作引发 OOM（系统级诊断，见 8A 文档 §7）
- **证据链**：Event 26（虚拟内存不足）→ Event 41/6008 崩溃重启；8/20 崩 4 次、8/21 崩 3 次，崩溃窗口与 agent git 活动高度重合。
- **根因（四层叠加）**：
  1. agent 一轮并发 2-3 个 bash，每条 git 派生 5-8 个进程（git.exe→sh.exe→ssh/GCM），一轮 git 检查 = 30-50 进程；
  2. 超大仓库（5GB 工作区 + 2.3GB .git）放大每条 git 命令的内存；
  3. pi + opencode 双 agent 同时操作同一仓库；
  4. 15.2GB 物理内存天花板（node + git 树 + Kit 4-8GB + Defender + Chrome）。
- **规避（三档）**：A. git 操作串行、只对单仓库、禁并行多 git、用 `git status --short`；跑 Kit 前查 Free RAM、跑完杀残留；**同一时间只开一个 agent**。B. 已做：旧 IsaacLab/isaaclab_env 回收/隔离；建议页面文件固定 D 盘 32GB、Defender 排除大目录。C. 长期：16→32GB 内存最有效。
- **应急处置**：Event 26→41 即崩溃；`tasklist | findstr /i git` 找大户；taskkill；超时命令的子进程会残留锁目录（改名/删除被拒先查残留进程）。

#### 坑 23：push 卡死 `info/lfs/locks/verify` 超时
- **解法**：`git config lfs.<repo-url>/info/lfs.locksverify false`；GitHub 偶发 443 超时需多试。

#### 坑 24：Windows 平台测试三件套（pytest 平台差异）
- `Path.write_text` 文本模式 \n→CRLF 破坏 LFS 指针前缀检测 → `newline=""`；
- `Path.read_text()` 无 encoding 用 GBK 读 UTF-8 崩 → 显式 utf-8；
- 文本资产 sha：read_bytes 是 CRLF checkout，与 git LF hash 不同 → `replace(b"\r\n", b"\n")` 后哈希。

#### 坑 25：committed 文件禁止本地绝对路径
- **现象**：4 个 wrapper 默认值里有 `E:\`/`C:` 本地绝对路径（git diff 检出）。
- **规则**：默认值一律环境中立：`Python="python"`、`RepoRoot` 由 `$PSScriptRoot` 推导、Log 用 `$env:TEMP`。diff 的 grep 会把注释行误报（CRLF 假象），用 python repr 复查。

### 2.7 Isaac Sim / Isaac Lab 运行时专项（Phase 4–8 踩坑）

#### 坑 26：EULA 交互喂不进后台管道
- **现象**：`import isaacsim`/SimulationApp 每次要键盘读 `y`，后台管道喂不进去，进程无声挂着。
- **解法**：`OMNI_KIT_ACCEPT_EULA=yes`（每个入口都要 setdefault——训练入口 train_agent_trl.py 一开始就漏了）。

#### 坑 27：warmup 预热 spawn 与 env 的 SimulationContext 冲突
- **现象**：collect 为绕 Vulkan 死锁加的"预热 spawn"先建 SimulationContext，env 构造报 `SimulationContext already exists`。
- **解法**：D3D12 修复根因后**预热 spawn 整段移除**；未来若再卡，恢复预热并令 env 复用 context，不要两边共存。

#### 坑 28：CUDA index out of bounds（motion_lib 默认只加载 num_envs 个 motion）
- **现象**：`get_motion_state` 报 `IndexKernel.cu:93 index out of bounds` + 设备断言，随后进程被污染崩溃（PhysX fabric 连环报错误导）。
- **根因**：`load_motions()` 默认 `num_motion_to_load = num_envs`（=1），内部数组缩成 1 行，而 collect 的 `_desired/_name2idx` 是全量 key 索引（0..11）→ 越界。
- **解法**：collect 配对前显式 `load_motions(num_motions_to_load=len(_ml._motion_data_keys), random_sample=False)`。
- **诊断要点**：CUDA 设备断言是异步的，一旦触发后续 CUDA 调用全部假失败；先看原始断言行定位真实越界，别被连环错误误导。

#### 坑 29：isaacsim 5.1 URDF importer 碰撞回归（官方 #461，特大）
- **现象**：`export-isaac` audit 报 `Colliders = 0`；stage 里 0 个碰撞几何 prim（连内联 cylinder/sphere 都不生成），但关节/质量/惯量正常。
- **根因**：isaacsim 5.1（importer 2.4.31）官方回归：不再把 `<collision>` 转成碰撞几何，无任何开关（ImportConfig 方法列表里根本没有）。
- **排查链**：全 stage 探针 → 最小复现同款失败 → 手工 Capsule+CollisionAPI 写不进去（link/collisions Xform 是 **instance prim**，proxy 只读、prototype 拒写）→ 突破口 **`SetInstanceable(False)` un-instance 后 normal authoring**。
- **修复（已入仓）**：`gear_sonic/cross_engine/exporters/isaac_colliders.py` 解析同一份 main.urdf 的 `<collision>` → 生成 Capsule/Sphere prim + UsdPhysics.CollisionAPI（26 cyl + 1 sphere；18 个手部 mesh 跳过）；`exporters/isaac.py` 在 Articulation 构造后、`SimulationContext.reset()` 前调用。验证：colliders 0→54，趴地不穿透（min root_z 0.066）。
- **连带影响**：P0/P1 历史采集是"无碰撞"状态（release 接触力恒值 993.9 = 假数据）→ Phase 8 必须用带碰撞环境重采。

#### 坑 30：adapter 里 `robot` vs `self.robot` NameError 被吞
- **现象**：adapter 构造函数崩，被外层 `except → IsaacAdapterUnavailable` 包住后表现成"进程静默 exit(0)/挂起"而非报错，排查 1h+（probe 1–13 全过、唯独构造函数崩）。
- **解法**：populate 临时包 try+print 才暴露 NameError。规则：**adapter 构造内变量名必须 self.* 一致**。

#### 坑 31：AppLauncher 两坑（isaaclab 0.48）
- Windows headless **必须显式 `--/renderer/activeApi=d3d12`**（kwargs 方式静默失败）；
- 0.48 AppLauncher 第一参数是 Namespace/dict → 用 `add_app_launcher_args(parser)` + `parse_known_args()`。

#### 坑 32：adapter 内 argparse 全量 parse 吞 CLI 参数
- **现象**：capture-interface CLI 调 adapter 时报 `unrecognized arguments: capture-interface --engine …`。
- **解法**：`parse_known_args()`（AppLauncher 参数与 CLI 参数共存）。

#### 坑 33：torque rel 对近零参考爆炸
- **现象**：torque abs=2.96e-6（达标）但 rel=1.0（超阈值 1e-5）→ gate failed。
- **根因**：Isaac write→readback 把 q 量化到 float32（max|dq|≈3e-8）→ 微差；参考近零帧 rel=Δ/max(|ref|,1e-12)≈1。
- **正解**：torque 用**注入的精确同状态 q/qd 计算**（两侧同一输入状态，符合 same-state 语义）；readback 仅作 sanity 记录。

#### 坑 34：ContactSensor 初始化时序
- 构造 → `simulation.reset()` → `update(dt)`（reset 前构造，reset 触发初始化回调）；顺序错则 `_timestamp` AttributeError。
- isaaclab 0.48 ContactSensor 无 signed-distance 数据 → `_penetration_depth` 返回 NaN（不 raise，降级处理）。

#### 坑 35：audit 的 attribute size 提取遇 Gf 向量
- **现象**：populate 后崩 `could not convert string to float: Gf.Vec3f(...)`。
- **解法**：`_flatten_numbers` 递归展平（int/float 直取，其余迭代组件）。

#### 坑 36：fingerprint 相对路径基准
- **现象**：`file entry 'isaac_asset' is missing`，文件明明存在。
- **根因**：fingerprint 把相对路径解析为 input 文件所在目录/相对路径（非 cwd）。
- **解法**：input 里用绝对路径；输出只留 label/size/sha256（无路径）。

#### 坑 37：手工 USD 自由体不参与物理
- 手工 RigidBodyAPI + Capsule + CollisionAPI + 地面，落体 z 恒定 → 不要用它验证碰撞；直接在真实采集环境（G1 cfg + GroundPlaneCfg）验证。

#### 坑 38：手写 rollout 必须显式 spawn GroundPlane
- 只 populate colliders 不加地 → 直接穿透 z=-10；正确：`ground_cfg.func("/World/defaultGroundPlane", ground_cfg)`。

### 2.8 MuJoCo 侧

#### 坑 39：MuJoCo 3.11 严格全局命名
- **现象**：`repeated name 'groundplane'/'floor'`（scene 与 include 模型命名空间冲突）。
- **解法**：逐个改名（`groundplane_tex`/`groundplane_mat`/`alignment_floor`）；验证用 `mujoco.MjModel.from_xml_path` 直接编译（31 bodies / 36 qpos / 77 geoms 通过）。

#### 坑 40：Windows CRLF vs git LF 的 sha 不一致（benchmark 层 blocker）
- 文本资产（.xml/.urdf/.mjcf/.txt）read_bytes 在 Windows checkout 是 CRLF，与 git blob LF 不同 → fingerprint sha 永不匹配。
- **解法**：`assets.py` 对文本文件先做 **LF 规范化**再哈希；EXAMPLE 配置 sha 同步更新。

### 2.9 脚本 / 自动化细节坑

| 坑 | 现象 | 解法 |
|---|---|---|
| PowerShell `$args` | 自动变量被遮蔽后 splat 参数错位 | 数组变量改名（$innerArgs）或显式命名参数 |
| `ReadToEnd` 死锁 | 子进程未退出时 ReadToEnd 阻塞 | 先 Kill 再排空流；能写 .ps1 就写文件执行 |
| bash 嵌套引号 | 反斜杠被吃（转义地狱） | Git Bash 直调 Windows python；避免复杂嵌套传参 |
| py-spy | 死锁定位 | `py-spy dump --pid` 直接看 Python 栈（两次抓到 URDF importer 停在主线程） |
| hydra `+` vs `++` | 已存在键 append 报错；`++` 把 group 替换成字符串 | 已存在键用 `++`，不存在用 `+`；config group 用斜杠 `manager_env/recorders=empty` |
| observation block | 报 width 必须 3×10=30，received 10 | block 是 base×history 扁平向量（30/290/930），不是 list-of-frames |
| 批量产物 glob | `release_*_clip_00.npz` 匹配不到单下划线 | 双通配 `*{pol}*{clip}*_00.npz`；重要判定批后人工核对 |
| benchmark NaN | metrics NaN 检查挡住 Isaac | penetration_depth 允许 NaN |
| SimulationApp.close | CLI 挂死 | 先写 run.json，close 加 10s 超时 |

### 2.10 训练冒烟阶段（8/21，Session 01a02257）

#### 坑 41：train_agent_trl.py 缺 Windows 关键补丁
- 原代码**没有 `OMNI_KIT_ACCEPT_EULA=YES` 和 `--/renderer/activeApi=d3d12`**（采集脚本验证过的 Windows headless 硬性要求，训练入口却漏了）→ 照抄 isaac_baseline_collect.py 补上（commit 36780c2，+7/-2）。

#### 坑 42：num_envs 必须是 num_mini_batches 倍数
- **现象**：`num_envs=1` 时日志报 `batch_size must be a multiple of num_mini_batches, inexact division: 1/4=0.25`，episode 统计全 NaN。

## 3. 沉淀的方法论（为什么后来不反复踩）

1. **先查版本矩阵再动手**：ABI tag（cp310/cp311）、cu126/cu128、torch.jit 存亡——装大包前先 `--dry-run`/查 wheel 元数据。
2. **驱动先行**：渲染崩溃第一步查驱动（nvidia-smi）和虚拟显示，而不是怀疑 Isaac 版本/代码/改 DLL。
3. **隔离变量做对照实验**：580.88 隔离测试只改宿主图形环境，脚本一行不改 → 用最小变量锁定根因。
4. **防复发手册化**：《防重复踩坑手册-Isaac对齐.md》每条 = 现象→根因→防复发，加 11 条一票否决硬规则。
5. **内存纪律制度化**：跑 Kit 前查 Free RAM、串行化 git 操作、清理残留、单 agent 运行。
6. **先落盘再退出**（os._exit）、**EULA 环境变量化**、**d3d12 显式化**——所有 Windows Isaac 入口统一补丁模式。
7. **py-spy 抓死锁**比猜快得多；**日志风暴**先看 logger 传播链。
