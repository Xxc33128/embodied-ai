### 2.3 armature 结果

固定隔离条件下：

| 指标 | elbow native | elbow matched | Isaac |
|---|---:|---:|---:|
| 对 Isaac 轨迹 MAE | 0.006752 rad | 0.001704 rad | — |
| t50 | 0.17743 s | 0.16329 s | 0.16382 s |

MAE 改善约 74.8%。同时：

- G0 证明 elbow native/matched 模型只改变目标关节 armature `0.0685 → 0.01`。
- elbow 隔离资产的 FK、COM、质量和等效惯量门禁通过。
- hip native/matched 资产哈希相同，轨迹逐点差为 0。
- hip MuJoCo–Isaac MAE 约 `0.000494 rad`。
- 无非目标关节漂移、root 漂移异常、接触或 torque saturation。

在最终 gate 与原始证据同步后，可以形成以下结论：

> 在当前右肘固定初态、0.1 rad 阶跃、冻结 Kp/Kd、无接触且资产等价的确定性隔离基准中，将 MuJoCo 的目标关节 armature 从 0.0685 调整为与 Isaac runtime 一致的 0.01，使其相对 Isaac 的轨迹 MAE 从 0.006752 rad 降到 0.001704 rad，下降约 74.8%，且 t50 从 0.17743 s 接近到 0.16329 s；三次独立运行逐点一致。

不能外推为：

- armature 解释了完整 `dance_9` 的全部差异。
- 所有关节或其他初态/幅值也改善 74.8%。
- 三个完全相同的确定性重复等价于跨随机条件统计验证。
- 某个引擎更接近真实机器人。

## B2-3：修复 Isaac 视频可视性门禁

### 当前结果

Isaac `frame_first/mid/last.png`：

- 背景约为 RGB 109 灰色。
- 与背景差大于 10 的像素只有约 193–196 个，占整张图约 `0.021%`。
- 亮点包围盒约 16×16 像素。
- 人眼看不到机器人，只看到灰底白点。

因此“0% 黑帧、max=255”不是有效的视频 PASS 判据。

### 代码原因

初始化时使用了 `set_world_poses_from_view`，但主循环每帧又执行：

```python
camera.set_world_poses([[0.0, -2.9, 1.2]], [[1.0, 0.0, 0.0, 0.0]])
```

这会覆盖正确的 look-at 姿态。`.copy()` 已解决缓冲复用黑帧，但相机朝向仍错误。

### 修改方法

主循环不要再使用固定 identity quaternion。每次 capture 使用：

```text
target = current root position + [0, 0, 0.70]
eye = current root position + 合理的侧后方偏移
camera.set_world_poses_from_view(eye, target)
```

如果机器人不需要水平移动，也可以只在启动后设置一次固定 `eye/target`。

### 新的视频门禁

除黑帧检测外，加入：

```text
robot/non-background bounding-box height >= 250 px
robot/non-background bounding-box width >= 80 px
non-background pixel fraction >= 1%
首/中/尾三帧头、脚、双臂均在画面内
```

MuJoCo 首帧已经能看到大部分机器人，但头顶略被裁切，建议将 distance 稍增或 lookat 稍降低，确保全身完整。

只重录 10 s 视频即可；数值 trace 无需重跑。如果只能在线录制，则重新运行后确认数值与旧 10 s 一致。
