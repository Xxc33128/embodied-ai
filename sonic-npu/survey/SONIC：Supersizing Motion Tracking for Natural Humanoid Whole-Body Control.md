# SONIC 论文精读笔记

> 一句话：**把人形机器人的「运动追踪」做成可规模化的基础任务** —— 用 100M+ 帧动捕数据、42M 参数策略、21k GPU 小时的训练，得到一个能零样本跟踪未见动作、且能作为通用接口对接 VR 遥操作 / 视频 / 文本 / 音乐 / VLA 模型的人形控制基础模型。

## TL;DR

- **核心论点**：人形控制迟迟没有像大模型一样享受 scaling 红利，根源是**任务选择**——逐任务手写奖励不可扩展，判别式模仿学习（AMP/ASE）在大而多样的数据下会 mode collapse。作者提出 **motion tracking（运动追踪）** 作为可缩放的基础任务：动捕数据提供**逐帧密集监督**，无需奖励工程。
- **三条缩放轴**：模型 1.2M → 16M → **42M** 参数；数据 4M → 10M → 22M → **100M+ 帧**（611h 动捕，50Hz）；算力 2k → 9k → **21k GPU hours**（128 GPU × 7 天）。三条轴都持续提升性能，**OOD 泛化增益最大**。
- **两大配套贡献**：① 实时**生成式运动规划器**（自回归 in-betweening，<5ms 推理），把用户意图变成短视界参考运动，支撑导航 / 拳击 / 蹲跪爬等交互控制；② **通用 token 空间**（FSQ 量化 + 多编码器对齐），统一机器人运动、人体 SMPL、混合遥操作三种输入，让 VR 遥操作、VLA 模型、生成式运动模型（视频/文本/音乐）共享一个策略。
- **VLA 落地**：GR00T N1.5 通过预测 64 维通用 token + 14 维手部关节角驱动 SONIC，5 个真实世界 loco-manipulation 任务平均 **75%** 成功率；token 动作空间比直接预测 SMPL 姿态平均高出 **+42pp**（68% vs 27%）。
- **Sim-to-real 差距极小**：真实机器人 124 段动作 99.2% 成功率（sim 100%），MPJPE-L 25.7mm（sim 22.3mm），差距最大在脚部（53.7 vs 29.0mm）。

## 1. 背景与动机

### 1.1 为什么人形控制还没"scale"？

| 领域 | 规模 | 人形控制现状 |
|---|---|---|
| GPT 等 LLM | 25,000+ GPU，万亿 token | 控制策略通常是 **3 层 MLP**，几块 GPU 训练单任务 |
| 视频/图像生成 | 数千 GPU，数十亿图像 | 逐任务手写奖励，不跨行为泛化 |

**根因是任务选择**：
- 行走的奖励函数对"跳舞"毫无信号 → 每个新能力都要重新设计奖励和目标；
- 生成式模仿方法（AMP / ASE / CALM）用判别器统一目标，但已有工作指出**数据集变大变多样后判别器信号会 mode collapse**（[19,20]）；
- 即便找到可缩放目标，还要回答第二个问题：怎么支撑多样化的真实应用（遥操作、导航、视觉语言指令……）。

### 1.2 为什么选 motion tracking

- 动捕数据提供**密集的逐帧监督**，不需要奖励工程；
- 人形领域已有**几十年动捕积累**（AMASS、BABEL、AIST++ 等），步行/跑步/跳舞/运动/物体交互数据天然存在于规模；
- 前人工作（PHC、HOVER、OmniH2O、BeyondMimic、GMT、Any2Track 等）大多只展示训练集上的追踪效果，**没有展示追踪之外的下游任务**。

> 💡 **核心 insight**：dense supervision 让"数据越多信号越强"，而判别器任务随多样性变难、奖励工程随行为数量爆炸——所以 motion tracking 是唯一能顺着 scaling 曲线走的任务。

## 2. 方法总览

### 2.1 系统架构（论文 Fig. 6）

```
        ┌──────────────── 任务层 ────────────────┐
        交互手柄控制     VR 3点遥操作   全身遥操作    视频/多模态控制
              │              │            │              │
        ┌─────┴──┐     ┌─────┴─────┐  ┌───┴────┐   ┌─────┴─────┐
        运动规划器 │     │ PICO VR   │  │ PICO   │   │ GEM 生成器 │
        (机器人运动) │     │ 工具包     │  │ VR     │   │ (人体运动) │
              │        │ 混合运动   │  │ 全身SMPL│   │            │
        ┌─────┴────────┴─────┬─────┴──┴────┬───┴──────────────┘
        │   机器人编码器 E_r  │ 混合编码器 E_m │ 人体编码器 E_h     │
        └─────────┬──────────┴──────┬──────┴─────────┬──────────┘
                  └─────────────────┴────────────────┘
                              │ 共享隐空间
                        ┌─────▼──────┐
                        │  FSQ 量化器  │ → 通用 token z
                        └─────┬──────┘
              ┌───────────────┴───────────────┐
        ┌─────▼───────┐                ┌──────▼───────┐
        │ 机器人控制解码器 │                │ 机器人运动解码器 │
        │ D_c(z, s_p)→动作 │               │ D_r(z)→重建参考 │
        └─────┬───────┘                └──────┬───────┘
              │                              │ 辅助重建损失（隐式 retargeting）
        ┌─────▼──────────────────────────────┐
        │      通用控制策略 (PPO 训练)          │
        │     PD 控制器 → 29 关节目标位置        │
        └────────────────────────────────────┘
```

**设计哲学**：专用编码器吸收异构输入 → 统一量化成 token → 共享解码器控制。换输入模态 = 换编码器，**无需重训**。

### 2.2 三轴缩放设置

| 轴 | 配置 | 说明 |
|---|---|---|
| **数据** | 4M / 10M / 22M / 100M 帧（20k / 50k / 110k / 317k 片段） | 小子集按子类别均匀采样，保持分布多样性 |
| **模型** | 1.2M / 16M / **42M** 参数 | 越大越好，OOD 上差距最明显 |
| **算力** | 2 / 4 / 16 节点（16 / 32 / **128** GPU），各训 50k iter | 21k GPU hours = 128 GPU × 7 天；大 batch 优化更稳定 |

- 全部在 **Isaac Lab** 训练，评价用 **MuJoCo**（与基线统一协议）。
- 缩放结果：最大模型 test-content 上 **99.6% 成功率、23.8mm MPJPE-L** vs 最小模型 98.0%、27.7mm（Welch t 检验，全部 P ≤ 0.011）。

## 3. 数据：人形运动数据集

- **来源**：~700 小时专业动捕，男女演员均衡，覆盖日常行为、手势、大量格斗动作；单片段 1–180 秒。
- **Retargeting**：GMR + PyRoki 重定向到 Unitree G1，滤除物理不可行动作（爬楼梯、坐姿等）→ 训练数据 **611 小时 / 100M+ 帧 @50Hz**。
- **33 个大类、8,447 个子类别**（训练集）：基础/高级步态、街舞/拉丁/vogue/fila 舞蹈、手势、格斗（剑术、武术、魔法）、单/双手物体操作、工具使用（阀门、杠杆、电锯、扫帚）、受伤步态、醉酒/僵尸/潜行等风格化动作、角色扮演等。所有动作多人采集 + 镜像，得到左右成对变体。
- **划分**（关键：严格的 train/test 隔离）：
  - `test-content`：7,016 片段 / 15h，**182 个子类别完全没出现在训练中** → 测 OOD 泛化；
  - `test-repetition`：9,395 片段 / 12h，子类别与训练重叠 100%，但具体片段不同 → 测新表演/重复的鲁棒性；
  - `PHUMA`：6.8 万条外部数据集（视频姿态估计 + 不同 retargeting 流程）→ 测跨流程泛化。
- **公开数据**：已发布 **BONES-SEED**（HuggingFace，142,220 段 / 288h / 522 名演员，SMPL + G1 格式，带自然语言描述）。

## 4. 通用运动追踪策略

### 4.1 公式化

- **MDP**：ℳ = ⟨𝒮, 𝒜, 𝒯, ℛ, γ⟩，PPO 最大化折扣回报。
- **状态** s_t = 本体感知 s_p（10 步历史：关节位姿 q、关节速度 q̇、根角速度 ω、根系重力向量 g、上一步动作 a）+ 运动指令 s_g（机器人运动 g_r / 人体运动 g_h / 混合运动 g_m 三选一）。全部在**机器人局部坐标系**，6D 旋转表示（旋转不变性）。
- **动作**：策略输出**目标关节位置**，由每关节 PD 控制器执行（29 个驱动关节，Unitree G1）。
- **奖励** r_t = 追踪项（根/连杆位姿与速度 + 头/腕/踝末端项）+ 惩罚项（动作率、关节限位、非期望接触、防抖、脚部加速度），详见 Table S3。
- **Domain Randomization**：物理参数（摩擦、恢复系数、COM 偏移）、周期根速度扰动（模拟外力推搡）、目标运动指令扰动，见 Table S4。

### 4.2 多编码器 + FSQ 通用 token

| 模块 | 输入 | 说明 |
|---|---|---|
| **机器人编码器 ℰ_r** | 未来 F=10 帧关节位置+速度，间隔 Δt=0.1s | 交互手柄控制 |
| **人体编码器 ℰ_h** | SMPL 3D 关节位置（未来 10 帧，间隔 0.02s）| VR 全身、视频/文本/音乐 |
| **混合编码器 ℰ_m** | 稀疏上半身关键点（头+手，当前帧）+ 下半身机器人运动 | VR 3 点遥操作，实时性要求高 |
| **FSQ 量化器** | 共享隐空间 → **2 个 token，各 32 维、32 个量化级别**（FSQ-32-32） | 比 VQ-VAE 稳定，无 codebook collapse |
| **控制解码器 𝒟_c** | token z + 本体感知 s_p → 关节动作 a_t | 训练/部署同一输入表示 |
| **运动解码器 𝒟_r** | 仅 token z → 重建机器人运动参考 ĝ_r | 辅助监督 + **隐式人体→机器人 retargeting** |

- 多帧输入 → 策略具备**预判能力**（anticipatory behavior）。
- FSQ 优于 VQ-VAE 的原因：无需 commitment loss / EMA codebook 更新，straight-through 梯度估计干净，适合和 PPO 联合优化；且避免 codebook collapse（8,447 个子类别下是真实风险）。

### 4.3 损失函数（联合端到端训练）

```
ℒ = ℒ_ppo + ℒ_recon + ℒ_token + ℒ_cycle

ℒ_recon = ‖D_r(z_r) − g_r‖² + ‖D_r(z_h) − g_r‖² + ‖D_r(z_m) − g_r‖²   (2)
ℒ_token = ‖z_r − z_h‖² + ‖z_r − z_m‖² + ‖z_m − z_h‖²                  (3)
ℒ_cycle = ‖E_r(D_r(z_h)) − z_r‖²                                       (4)
```

- **ℒ_recon**：当输入是人体运动时，编码器-解码器就构成"人→机器人"retargeting 管线，这条重建损失让策略能直接从**人体数据**学习（形态差异被隐式解决）；
- **ℒ_token**：三编码器两两对齐，同一动作无论从机器人/人体/混合输入进来都应产生相似 token（**VLA 数据分布一致性**的关键前提）；
- **ℒ_cycle**：循环一致性，人→机器人→再编码回 token 要保持本质运动特征；
- **训练细节**：asymmetric actor-critic（critic 见特权信息，actor 只用部署可观测信息）；梯度经 FSQ straight-through 反传；**bin-based 自适应采样**（按失败率加权，针对性练习困难动作）；分布式训练用 Accelerate + TRL。

### 4.4 关键超参数（Table S2）

4096 envs/GPU × 24 steps，γ=0.99，GAE λ=0.95，clip=0.2，熵系数 0.013，actor LR 2×10⁻⁵（自适应 1e-5~2e-4），critic LR 1×10⁻³，自适应采样 bin=1s，失败率上限 β=200，混合系数 α=0.1。

## 5. 生成式运动规划器（交互控制层）

- **任务**：把高层用户意图（速度/方向/风格/技能）转成短视界运动参考，规划器负责"生成"，追踪策略负责"执行"。
- **公式**：自回归 **motion in-betweening**——连接当前位姿到目标关键帧的中间运动。上下文关键帧 = 历史机器人状态；目标关键帧 = 导航指引关键帧（由速度/方向/风格命令生成）或技能目标（蹲/跪/爬/拳击）。
- **运动表示**：骨盆相对关节位置 + **全局关节旋转**（全局旋转对蹲、爬这类"朝向无定义"的动作至关重要）。
- **潜空间生成**：连续运动先编码为潜 token 序列（下采样率 4），用 **masked token prediction** 迭代生成：每次只确定置信度最高的一批 token，从 100% mask 逐渐补全到 0%（训练时 mask 比例均匀采样；推理用余弦调度确定每轮 finalize 比例），借鉴 MaskGIT / MoMask / MMM。
- **关键帧根轨迹弹簧模型**：用**临界阻尼弹簧模型** x(t) = [x_T − x_0 + (v_0 + (c/2)(x_T − x_0))t]·e^(−ct/2) 从命令生成骨盆位置和朝向的目标关键帧（位置阻尼系数 5·ln2，朝向 20·ln2）。既能过滤不现实命令（如 6 m/s 瞬间反向），又因规划器变长生成 + 强 in-betweening 能力而对阻尼系数取值鲁棒。
- **性能**：单段生成 0.8–2.4s（时长自动决定）；笔记本 <5ms、Jetson Orin ~12ms 推理；**100ms 级重规划**，用户命令更新立即触发。
- **关键能力**：25+ 种技能/风格，**每种只需 1 段代表性运动片段，零重训**。技能都是训练后指定的（specified after training）。
- **下游应用**（全部无重训）：
  - 导航：0–6 m/s、360° 任意方向、风格切换（醉酒/受伤/开心/潜行/奔跑……）；
  - 拳击：连续出拳/格挡/步伐，无停顿无切换感（对比学术方案要切专家模型/动作标签）；
  - 蹲/跪/爬：骨盆高度 0.3–0.8m 连续可控；肘膝爬行 0–0.5 m/s 全向移动。

## 6. 多模态控制与遥操作

### 6.1 视频 / 文本 / 音乐（基于 GEM）

- **GEM**（Generalist Model for human motion）把运动估计当成受限生成，支持视频/文本/音频混合时变条件，输出扩散式人体运动序列；
- 集成方式：滑窗 + 重叠 + inpainting 过渡，低延迟生成；生成的人体运动经 ℰ_h 进 SONIC；
- 视频遥操作：≥60fps 单目视频姿态估计，无需专用动捕硬件；文本：自然语言任意时刻改指令；音乐：按旋律/节奏/速度生成舞蹈；**模态之间可实时切换**（视频精细控制 → 文本一般控制 → 音乐表演）。

### 6.2 VR 遥操作（两套接口）

| | 全身遥操作 | 3 点遥操作 |
|---|---|---|
| 硬件 | PICO 头显 + 踝部追踪器 + 手柄 | 仅头显 + 双手柄（无踝部追踪器）|
| 输出 | 87 维/帧：SMPL 全身关节位(63) + 根朝向四元数(4) + 手腕关节角(6) + 灵巧手关节位(14) | 3 个上半身 SE(3)（头+双腕）+ 手关节角 + 腰高 + 导航命令 |
| 编码器 | ℰ_h | ℰ_m（下半身由规划器生成）|
| 用途 | 复杂全身技能 | 轻量便携、可扩展的数据采集 |

- 采集的遥操作数据用于训练 VLA 基础模型 → **形成"追踪 → 遥操作数据 → VLA"完整闭环**。

## 7. VLA 驱动的 Loco-manipulation（GR00T N1.5）

- **接口**：VLA 预测 **78 维动作 = 64 维通用运动 token + 14 维手部关节角**，token 经通用控制策略解码执行；
- 5 个任务平均 **75%** 成功率（10–20 次试次，严格二值判定，无部分得分）：

| 任务 | 接口 | 训练数据 | 试次 | 成功率 |
|---|---|---|---|---|
| Apple to plate | 3 点 | 300 条轨迹 | 20 | **90%** |
| 物体拾取（胡萝卜） | 全身 | 3,900 条（300/物 × 13 物） | 20 | 75% |
| 物体拾取（scrub） | 全身 | 同上 | 20 | **95%** |
| 踩踏板开垃圾桶 | 全身 | 200 条 | 10 | 70% |
| 易拉罐→垃圾桶（5 段技能链）| 全身 | 1,000 条多物体 | 10 | 60% |
| 电钻+纸箱搬运 | 全身 | 300 条 | 10 | 70% |

- 踩踏板任务要求**闭环 VLA 控制下精确脚部落点 + 动态单腿平衡**（脚当操作器用）；易拉罐任务同一动作序列里同时要手操作、脚操作、动态平衡——这是把上下半身解耦的动作空间难以实现的。

### 7.1 动作空间消融：token vs SMPL 姿态

| 任务 | FSQ token | SMPL 姿态 | Δ |
|---|---|---|---|
| 胡萝卜拾取 | 75% | 60% | +15 |
| 踩踏板开垃圾桶 | 70% | 20% | +50 |
| 易拉罐→垃圾桶 | 60% | 0% | +60 |
| **平均** | **68%** | **27%** | **+42** |

> 原因：token 是低维离散动作空间，VLA 从遥操作示范里学起来容易；高维连续 SMPL 空间会把小预测误差放大成大追踪失败（SMPL 预测还产生抖动、方向失控的不安全行为）。

## 8. 实验关键结果

### 8.1 与运动追踪基线对比（MuJoCo 统一协议，Fig. 2D–G）

| 指标 | SONIC | BeyondMimic | Any2Track | GMT |
|---|---|---|---|---|
| 成功率 content/repetition/PHUMA | **98.5 / 99.2 / 97.2%** | 82.0 / 85.4 / 73.8% | 61.6 / 69.4 / 78.5% | — |
| MPJPE-L | **23.7mm**（比 BeyondMimic 低 42%） | 40.9mm | — | — |

- PHUMA 97.2% 尤其说明问题：它来自**视频姿态估计 + 不同 retargeting 流程**，比自留 OOD 划分还更远离训练分布（注：基线训练数据不同，该对比主要反映跨数据集泛化与缩放效应，非完全数据匹配基准）。

### 8.2 与专精控制器对比（OpenHomie，Fig. 2H–J）

| 指标 | SONIC | OpenHomie |
|---|---|---|
| 综合存活率（0–5 m/s 速度追踪） | **98.5%**（197/200） | 43.0%（86/200） |
| 稳定性维持 | ~4 m/s 仍接近 100% | ~2 m/s 后崩溃，2.5 m/s 后 <20% |

- 讽刺点：OpenHomie 是专为走路训练的 SOTA 单任务控制器，却被"杂食"通用策略在**速度追踪**本职上碾压 → 数据多样性的收益 > 专精化的收益。
- 补充（Fig. S6）：OpenHomie 在 **8 GPU 就性能饱和**（0.18 m/s 误差、95% 存活），32 GPU 反而变差（0.29 m/s、91.2%）；SONIC 持续随算力提升 → 任务奖励工程有天花板，密集监督没有。

### 8.4 鲁棒性

- **25 磅（~11kg）重物从头顶砸下**：机器人吸收冲击、保持平衡、继续追踪，无恢复模块、无策略调整（Fig. S5）。
- 失败案例分析（Fig. S3）：僵尸爬（超出运动学极限的贴地动作）、盘腿坐（需要持续地面接触的静态姿势）→ **持续/复杂地面接触仍是短板**。

## 10. 部署架构（真实机器人）

- **平台**：Unitree G1（29 驱动关节），板载 **Jetson Orin**，TensorRT + CUDA Graph（预热录制执行图 → 低方差回放），策略前向 **1–2ms**，运动生成 ~12ms。
- **多速率四循环**（Fig. S1）：
  - 控制环 **50Hz**（组装观测 → 编码器+策略 → 关节目标；与训练仿真步长一致）
  - 命令写入 **500Hz**（独立高率进程，不阻塞策略环）
  - 输入接口 **100Hz**（键盘/手柄/VR/网络流无缝切换）
  - 规划器 **10Hz**（30fps 轨迹，最长 64 帧 ~2s，8 帧 160ms cross-fade 新旧轨迹）
- **统一运动接口**：所有运动源（预录片段/规划器/外部流）共用一个 MotionSequence 结构；切换运动源 = 原子指针交换 + 帧计数归零；**编码器模式是运动序列的一个字段**，自动选择，操作员无需管理。
- **观测由 YAML 配置驱动**：启动时把命名观测函数注册表编译成 (函数, 偏移, 维度) 扁平列表 → 换一个配置文件即可换策略架构，无需重新编译。
- **安全机制**：三段式启动（3s 插值到站立 → 等待就绪 → 激活策略）；关节速度看门狗；数据源不可用时自动降级到下一个编码器；停机时纯阻尼模式（Kp=0, Kd=8）；所有电机命令带 **CRC32 校验**。
- **朝向对齐**：新动作开始时取 IMU yaw，用纯旋转把参考运动初始朝向对齐到机器人朝向，运行时可注入朝向修正。
- **Token 直通流**：外部进程可绕过板载编码器，直接发送预计算的 latent token 注入观测向量（ZMQ/ROS2 流）。

## 11. 讨论

### 11.1 为什么 motion tracking 能 scaling（论文的核心论证）

1. **密集逐帧监督**：每帧都是显式目标姿态，数据越多样信号越有用；
2. **对比判别式模仿（AMP/ASE）**：判别器要在全分布上分辨真假，多样性增加 → 判别任务变难 → 反馈信息量下降 → mode collapse；
3. **对比奖励工程（OpenHomie）**：每个行为都要定制目标，且**专精奖励会饱和**（8 GPU 后 OpenHomie 不再提升），motion tracking 的密集监督不饱和；
4. **数据多样性收益 > 专精化收益**：通用追踪器在速度追踪上吊打专用控制器（98.5% vs 43.0% 存活率）；
5. **token 空间覆盖全身 → VLA 能控制整条运动链包括脚**。

### 11.2 局限

- 无形式化的**安全性**与**能量效率**处理；
- 训练期靠运动指令 DR + 部署期弹簧模型过滤，能容忍噪声规划器输出，但**极端条件或非常动态的动作下可能失去平衡**；
- 持续/复杂地面接触类动作（僵尸爬、盘腿坐）仍失败。

## 13. 我的思考

1. **"任务选择"视角值得迁移**：选任务的标准应是——监督密度不随数据多样性稀释（密集 vs 判别器）、不随行为数量爆炸（无奖励工程）、且下游能复用（token 空间）。这解释了为什么 RL 里很多领域卡在"8 GPU 饱和"，而它没有。
2. **通用 token 空间是工程的胜负手**：FSQ + 三损失对齐 + 多编码器，本质是给"异构控制接口"做了一次**表示对齐**，让数据（人体动捕、遥操作、机器人运动）和下游（VLA）都能在同一个离散空间里交互。VLA 学 token 比学 SMPL 高 42pp 的消融是全文最有力的一刀。
3. **对华为实习工作的关联**：本机 huawei实习/GR00T-WholeBodyControl 就是论文官方代码库。可对照：①部署多速率架构（50/500/100/10Hz）与 YAML 观测配置的实现；②FSQ 量化器与三损失在训练代码中的落点；③data loader 的 bin-based 自适应采样实现；④TensorRT/CUDA Graph 板载推理管线。
4. **可质疑/待验证的点**：
   - 与基线对比非"数据匹配"（基线用 LaFAN/AMASS 训练），作者自己也承认主要反映跨数据集泛化；严格公平对比仍需同数据重训基线；
   - 成功率定义是**局部追踪**（根/末端高度偏差 <0.25m 判成功），比全局根位置误差（0.5m）严格，但 99%+ 的高成功率在超大规模 OOD 下仍有"评价器本身宽松"之嫌（配 14 连杆 MPJPE-L 缓解）；
   - 5 个 VLA 任务每种任务训练数据从 200–3900 条不等，任务间成功率差异大（60%–95%），"平均 75%"的解读需谨慎；
   - 公开数据只占一部分（BONES-SEED 288h / 训练 611h），完整复现仍有数据门槛。
