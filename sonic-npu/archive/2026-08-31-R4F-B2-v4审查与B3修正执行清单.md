## 3. Step B3-1：修正 `n5_r_summarize.py`

### 3.1 YAML 解析必须明确失败

当前代码在没有 PyYAML 时捕获异常并返回 `_parse_error`，后续却把它报告成 `xml_used_sha256 missing`，容易误诊。

必须满足以下任一方案：

- 方案 A：在包内增加 `requirements.txt`，明确包含 `numpy`、`matplotlib`、`PyYAML`，运行前验证 `import yaml`；
- 方案 B：实现与 `compare_repeats.py` 一致、经过测试的 YAML fallback parser。

无论采用哪种方案，YAML 无法解析时必须输出：

```text
manifest_parse_error=<文件路径和真实异常>
```

并使 final gate 失败，不能伪装成普通 hash 缺失。

### 3.2 读取真实 runtime readback

`initial_state_readback_<joint>.json` 已经包含：

```json
{
  "runtime_dof_count": 1,
  "runtime_joint_name": "right_elbow_pitch_joint"
}
```

`g_root_runtime_gate()` 必须优先从 readback JSON 读取这两个字段，再回退到 manifest。

final 模式下：

```text
runtime_dof_count 缺失       -> FAIL
runtime_dof_count != 1       -> FAIL
runtime_joint_name 缺失      -> FAIL
runtime_joint_name != target -> FAIL
```

不能再只打印 WARN 后继续 PASS。

### 3.3 实现真正 fail-closed 的退出码

当前脚本即使 `validity=false` 仍返回退出码 0。必须修复。

建议增加：

```text
--evaluation-mode smoke|final
```

规则：

```text
final:
  validity_pass == true 且 all_pass == true -> exit 0
  其他任何情况                            -> exit 1

smoke:
  G6 == NOT_EVALUATED 且 smoke_pass_excluding_g6 == true -> exit 0
  其他任何情况                                          -> exit 1
```

如果不增加 mode，也至少保证本次 final gate 命令在 `all_pass=false` 时退出 1。

### 3.4 不改变科学阈值

本次不能修改：

- G0 FK/COM/mass/Ieff 阈值。
- G1 q0/dq0、step time、step amplitude 阈值。
