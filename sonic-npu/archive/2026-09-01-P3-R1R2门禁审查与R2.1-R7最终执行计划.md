## 4. 正式运行前必须修复的问题

以下 P0 项必须在正式 Isaac 10 秒运行前修复。

### P0-1：actuator group 汇总需要 fail-closed

现有 runner 在组长度不等于 4 时会 `continue`，缺少 instrumentation 时还会用 `q_des` 回填 requested/effective，并把 compute count 写成 4。该逻辑可能掩盖缺组、漏关节和 instrumentation 失效。

修改要求：

1. 构造 29 关节 ownership 表；
2. 每个 runtime actuator group 都必须是 `P3InstrumentedDelayedImplicitActuator`；
3. 每个 group 每个 control 必须恰好产生 4 个 requested 和 4 个 effective；
4. tensor shape 必须严格等于 `(1, group_joint_count)`；
5. 每个 policy joint 必须被覆盖一次且只能一次；
6. 缺关节、重复关节、未知关节、组长度错误立即抛异常并非零退出；
7. 删除 `count == 0` 和异常分支中的 `q_des` 回填；
8. 运行失败时不得生成带 PASS 含义的 trace/manifest。

新增字段：

```text
actuator_group_names
actuator_compute_count_by_group      shape=(n_control,n_groups)
actuator_joint_coverage_count        shape=(29,)
actuator_joint_owner
```

保留：

```text
actuator_compute_count_per_control
```

该标量只能在所有 group 的真实 count 都相同且等于 4 后写入。

### P0-2：physics-step 序号必须来自 actuator 的真实 compute counter

现有 `physics_time_substep` 由循环变量 `t + 0.005 × substep` 合成，它只能证明公式正确。

修改要求：

1. actuator 在每次真实 `compute()` 中记录递增的 physics-step index；
2. runner 从各 group 读取 index，并检查所有 group 完全相同；
3. trace 新增：

```text
actuator_physics_step_index_substep   shape=(n_control,4)
```

4. `physics_time_substep` 由该真实 index 与 `physics_dt` 计算；
5. 在每个 control 末尾把最后一个 index 与仿真 control 边界时间交叉检查；
6. manifest 明确记录：

```text
physics_time_source=actuator_compute_counter_x_physics_dt
```

### P0-3：runner 不得把 requested 配置复制成 measured 结果

现有 runner 直接执行：

```text
measured_delay_steps = requested_delay_steps
measured_delay_ms = requested_delay_ms
```

修改要求：

- runner manifest 中只写 `requested_delay_*`；
- runner 的 `measured_delay_*` 写 `null/NOT_EVALUATED`，或者完全删除；
- measured steps/ms 由在线 checkpoint 和最终 `p3_validate.py` 从 requested/effective trace 搜索得到；
- measured 值与 requested 值分别展示；
- 无唯一 shift、多个 shift 同样匹配或 target 激励不足时返回 `NOT_IDENTIFIABLE`，不能给 PASS。

### P0-4：补齐正式 provenance

当前 R1 manifest 中：

```text
runner_sha256(top-level) = null
isaac_lab_commit = unavailable
isaac_lab_dirty = null
Isaac model hash 缺失
```

虽然 `hashes.runner` 有值，正式包仍需统一修复。

修改要求：

1. 用 `Path(__file__)` 计算 top-level 和 `hashes.runner`，两者必须一致；
2. 从 `env_cfg.scene.robot.spawn.asset_path` 读取实际加载 URDF，写 model path/name/SHA256；
3. Isaac model SHA256 必须为 `c2aa3837...d8eb`；
4. policy/motion/canonical/runner/actuator/model 均写完整 64 位 SHA256；
5. 记录 Humanoid Lab commit 和 dirty state；
6. Kit Python 找不到 `git` 时，在普通 PowerShell 先生成 `repo_state.json`，runner 读取并绑定其哈希；
7. `repo_state.json` 至少含 commit、branch、dirty、dirty file list 和生成时间；
8. provenance 缺失时在线 checkpoint 失败。

PowerShell 侧可以先获取：

```powershell
git -C E:\humanoid-lab rev-parse HEAD
git -C E:\humanoid-lab branch --show-current
git -C E:\humanoid-lab status --porcelain
```

不要继续把 `unavailable/null` 写入正式 manifest。

### P0-5：统一实现名称和证据说明

当前 position delay 使用 Python `deque` 实现的显式 repeat-first FIFO，没有调用 Isaac `DelayBuffer.compute()`。该设计可用于两引擎的受控等时延实验，但文件注释和 JSON 不能继续写成“Isaac DelayBuffer 实测”。

统一表述为：

```text
P3 explicit per-physics-step position-target FIFO
implementation=collections.deque
prehistory=repeat-first-q-des
```

同时记录：

```text
position_delay_backend=explicit_deque
native_position_delay_buffer_bypassed=true
native_velocity_effort_delay_buffer_used=true
```

最终结论应描述“受控等时延注入”，不要描述成 Humanoid Lab 原生 DelayBuffer 的鲁棒性验证。
