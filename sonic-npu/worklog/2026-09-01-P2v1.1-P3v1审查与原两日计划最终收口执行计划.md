## 6. P3 的阻塞问题

### 6.1 P0：Isaac 没有有效 target 实测

Isaac D20 trace 缺少：

```text
q_des_requested(29)
q_des_effective(29)
q_des_effective_substep
fifo_index_substep
physics_time_substep
```

现有 `actual_processed_q_target(29)` 来自 action manager 的 `processed_actions`，位置在 actuator delay 之前。它不能证明 PD/PhysX drive 实际接收到的 target 已经滞后 4 个 physics step。

`01_delay_gate/isaac_integration_probe/probe.json` 也明确写着：

```text
inferred from actuator config
```

该证据属于配置推断，尚未达到原计划要求的实测门禁。

### 6.2 P0：两侧 prehistory 没有证明一致

MuJoCo runner 显式使用第一个 `q_des` 填充 10 个 FIFO 槽。

Isaac runner 只设置：

```text
g.min_delay = g.max_delay = 4
```

随后调用 `env.reset()`。当前 Humanoid Lab 的 `DelayedImplicitActuator.reset()` 只调用 buffer reset，runner 没有执行 first-q-des prefill。因此 `README_P3.md` 中“两侧都是 first-q_des prefill”的声明缺少代码和 trace 支持。

### 6.3 P0：P3 没有正式 validator

包内不存在：

```text
04_analysis/p3_validate.py
```

`p3_summarize.py` 只计算少量指标并生成图，不承担 fail-closed validation。

### 6.4 P0：八个负测试为 mock

`run_p3_negative_tests.py` 中的 `run_validate()` 对任何临时目录直接返回：

```python

```

所以八个 tamper case 无论改了什么都会显示 PASS。当前 `8/8 PASS` 没有验证门禁判别能力。

### 6.5 P0：分析脚本硬编码结论

这些字段没有全部从 manifest、summary 和 trace 重新计算。脚本还没有 `--root` 参数。

### 6.7 P1：指标解释和图表需要修订

当前 `q_rmse_20_vs_0` 描述 20 ms 轨迹相对 0 ms 的变化幅度。该指标属于 trajectory sensitivity，不能单独证明性能退化。

## 10. Step R1：创建可观测的 Isaac 延迟执行器

### 10.1 创建独立实现文件

建议新增：

```text
00_inputs/p3_instrumented_delayed_actuator.py
```

实现 `P3InstrumentedDelayedImplicitActuator`，继承当前 `DelayedImplicitActuator`。功能要求：

1. `reset()` 后设置 `primed=false`；
2. 第一次收到有效 position target 时，用该 target 填充完整 delay history；
3. 每次 `compute()` 保存 requested position target；
4. 每次 `compute()` 保存 DelayBuffer 输出后的 effective position target；
5. 记录 episode physics-substep 计数；
6. 支持 runner 在一次 `env.step()` 前清空本周期 debug history；
7. 支持 runner 在 `env.step()` 后读取本周期 4 个 substep；
8. 只把 position target 作为 P3 的研究对象；velocity/effort 保持原执行链默认值；
9. 0 ms 配置不改变原轨迹。

建议使用 DelayBuffer 的公开 `compute()` 接口完成 first-target priming，避免直接写私有 `_buffer`。如果必须访问私有成员，需要在 manifest 中记录 Isaac Lab 版本、对应源码哈希和私有字段名。

### 10.2 runner 需要记录的字段

Isaac trace 必须增加：

```text
q_des_requested(29)                  shape=(n_control,29)
q_des_effective(29)                  shape=(n_control,29)
q_des_effective_substep              shape=(n_control,4,29)
q_des_requested_substep              shape=(n_control,4,29)
physics_time_substep                 shape=(n_control,4)
actuator_compute_count_per_control   shape=(n_control,)
```

`q_des_effective(29)` 建议定义为该控制周期最后一个 physics substep 的 effective target。分析时以 substep 数组为权威来源。

多 actuator group 需要按 runtime joint name 合并到 policy 29 关节顺序。缺关节、重复覆盖或 group 之间 substep 数不同应立即退出。

### 10.3 manifest 必需字段

```text
engine
physics_dt=0.005
control_dt=0.02
decimation=4
requested_delay_steps=4
requested_delay_ms=20
measured_delay_steps
measured_delay_ms
prehistory_mode=repeat-first-q-des
actuator_compute_calls_per_control=4
policy/motion/model/canonical/runner/actuator_source hashes

```

`measured_delay_*` 必须由 trace 分析脚本生成，runner 不能直接把配置值复制为 measured 值。
