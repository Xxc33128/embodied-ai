# Codex 初始输入审计与精简实测

版本：v1.0 · 日期：2026-09-29

## 结论

〔E1／实测〕在本机 `codex-cli 0.158.0-alpha.2.1`、请求模型 `gpt-6-astra / medium` 下，基础指令与用户消息均为 `1`。沿用当前环境的首请求输入为 **13,111 Token**；使用独立配置目录、关闭附加能力、关闭会话环境访问并禁用/压缩 Skills 清单后，为 **3,763 Token**，减少 **9,348 Token，约71.3%**。两者均使用内置 `openai` provider。这是输入开销测试，不是机器人效果或速度基准。

〔E1〕本次捕获了 app-server 实际出站 JSON 和 `response.completed.usage.attribution.items`。下表是服务端逐项归因，不是根据字符数分词估计。`baseInstructions="1"` 确实作为单独 developer 消息进入请求；大头来自工具定义、Skills 等自动附加内容，不能统称为默认基础提示词。

## 五次新会话的结果

〔E1〕每次都是独立 ephemeral 会话，不带前一次对话、不传图片、不设置输出 Schema。所有测试均使用相同模型名和 medium 档位，记录首请求输入与完整 turn 累计输入。

| 条件标识 | provider | 首请求输入 | 完整 turn 累计输入 | 实际模型请求数 |
|---|---|---:|---:|---:|
| current_capture：当前环境 | openai | 13,111 | 26,321 | 2 |
| current_http：当前环境、显式 HTTP 转发 provider | audit | 11,045 | 22,179 | 2 |
| clean_http：隔离目录、关闭附加能力 | audit | 5,760 | 5,760 | 1 |
| clean_noenv：再设 `environments=[]` | audit | 5,560 | 5,560 | 1 |
| clean_noenv_noskills：再禁用/压缩 Skills | openai | 3,763 | 3,763 | 1 |

〔E2〕`audit` 是此次定义的本机转发 provider，仍将请求转发到原 OpenAI 服务，不是另一个模型服务。自定义 provider 本身会改变客户端提供的能力，所以不把13,111到11,045的差值归给某一条优化。主比较使用两次内置 `openai` provider；中间三个条件用于观察逐步变化。每项仅一次，不评价统计稳定性或缓存性能。

〔E1〕本次 current_capture 的第二次模型请求已经查明原因：第一次产生 `exec` 工具调用，查询可用工具列表，收到空列表后再生成最终回复。因此两次用量更新不是同一个计数重复上报。此结论仅针对本次抓包；之前13,061 Token 那次没有出站正文，不能据此断言其内部路径完全相同。

## 哪些初始输入可以避免

| 内容 | 此次结论 | 机器人实验中的处理建议 |
|---|---|---|
| 自定义基础指令 | 传 `baseInstructions` 可替换为自己的内容 | 保留必要的机器人控制规则，不应在正式实验中改成 `1` |
| 用户级 MCP、插件与部分工具 | 独立配置目录及关闭附加能力后明显减少 | 使用专用运行目录，不继承日常办公工具环境 |
| Skills 目录描述 | 本次精简后基本移除，包装仍存在 | 对专用实验禁用已发现 Skills，并核查实际出站请求 |
| 推荐插件 | 本次精简后消失 | 实验不需要时关闭应用/插件发现能力 |
| 本机环境上下文 | `environments=[]` 后显著缩短 | 若机器人由外部 Python 主机执行、GPT 只回 JSON，可评估不用 Codex 环境访问 |
| 内置函数/agent 工具及控制说明 | 本次所试配置没有完全去掉 | 不声称已实现“纯1输入”；该版本实际请求仍有2,767 Token工具定义 |
| 任务、图像、proprio、动作候选、JSON Schema | 本次未发送，不属于可省掉的冗余证据 | 正式机器人控制应保留，后续单独衡量其成本 |

〔E2〕精简运行只对子进程设置独立 `CODEX_HOME`，沿用认证完成原服务调用，退出后删除临时认证副本。不修改用户原 `config.toml`、认证文件、现有报告或主实验代码。独立目录中不复制用户 MCP/插件配置；另在该进程关闭 Shell、Apps、浏览器/计算机使用、图像生成、workspace dependencies、工具搜索等能力；`project_doc_max_bytes=0`、`web_search="disabled"`；thread/start 设置 `environments=[]`，对27个发现的 Skill 目录设 `enabled=false`，并将 `skills.max_context_tokens=1`。具体覆盖值在本地各条件的 `result.json`，不应不经核验直接套到正式任务。

〔E1/E3〕虽然传入了 `features.multi_agent=false`，实际请求仍含 collaboration 命名空间与相关说明，故不能仅凭配置名断言它已关闭。是否有其他受支持的关闭入口，本次未证实。模型 metadata、插件状态和版本也会影响附加内容，需以最终请求为准。

〔E3／后续方向〕若必须彻底掌控请求组成，可考虑直接调用模型 API，只提交机器人所需的指令、图像、状态和 Schema。该方案需要另行验证模型可用性、认证/计费和决策等价性；此次未测试直接 API，不承诺相同模型、同等效果或具体最低 Token 数。

## 采集方式与限制

〔E1〕本机回环地址监听请求，通过 HTTPS 转发到原 `chatgpt.com/backend-api/codex/responses`，请求正文不删改。只保存正文与服务用量，不保存 HTTP 认证头。内置 provider 首先尝试 WebSocket，转发器未实现 WebSocket，遇到404后回退HTTP并成功；因此本次延迟受采集方式影响，不做TTFT/TPOT比较。显式 audit provider 关闭 WebSocket。完整原始文本含本机路径，只在本地实验目录保存，不发布到公开仓库。

〔E1〕五次会话均完成。核验首请求用量与 app-server 事件一致、逐项归因加总及差额，并扫描输出文件是否含本机认证文件中的凭据值：通过。此检查不能证明服务端不存在未公开内部机制；它证明的是本次客户端发出的正文及服务返回计数。
