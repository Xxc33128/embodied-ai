# LLM、VLA、WAM 融合：三个具体改进方向

版本：v1.1 · 日期：2026-09-29

基于三位子 agent 的分析与交叉讨论，本文收敛为三个方向：主机何时请求 LLM、WAM 预测什么并如何形成训练数据、怎样缩短回复并持续完成恢复。只修改研究方案，尚未实现触发器、启动新实验或训练。

〔E1〕表示源码／记录依据；〔E2〕表示实验配置；〔E3〕表示待验证方案。**下文规则和数字是一组可实现的试点设定，不是已标定阈值，也不是已有实验结论。** 当前九回合没有 WAM 或后训练对照。

## 1. 由主机检查明确事件，再请求 LLM

LLM 不需要一直在线“发现该自己介入”。主机在 VLA 返回候选之后、执行动作之前检查规则；执行后更新状态。没有触发时，试点允许执行最多5步；触发时，把事件、当前图像、机器人状态和候选一起交给 LLM。〔E3〕

当前代码已经拿到候选动作、当前控制步、图像和末端状态；每步动作的第7维是夹爪命令，正值合、负值开，通常执行候选前5步。因此，第一版可以只用已有输入做下面四类检查。〔E1〕

### 第一版：先实现这四条

| 事件 | 主机具体检查什么〔E3〕 | 命中后做什么〔E3〕 |
|---|---|---|
| **首次目标确认** | 回合开始，或任务指令改变；尚无针对当前任务版本的确认记录 | 在任何任务动作前调用 LLM。要求它结合当前图像确认目标对象／部件，并允许回答“看不清”。任务变化时旧确认作废 |
| **准备改变夹爪命令** | 从上一条实际执行的非零夹爪命令开始，顺序检查本次准备执行的前5步；只要出现负→正或正→负，就触发。初始方向未知也触发；零值只在事件比较时跳过，不改写原动作 | 在整段动作开始前审核候选，避免闭爪／释放已经发生后才检查。说明这是“准备开合”，不是已抓住／已释放成功 |
| **有平移命令但末端几乎没动** | 最近3个已执行动作段中，平移命令范数之和≥1.5，而逐步实际末端路程之和<3 mm；同时累计实际转角<0.05 rad，且没有夹爪方向切换 | 暂不执行下一段，发送“运动疑似停滞”事件及这3段的指令和实测变化。请 LLM 判断是否受阻、正常保持或需要观察，不能直接认定失败 |
| **定期复核** | 距最近一次完成审核后，已经执行20个控制步；每段执行长度裁到复核边界，不越过这20步 | 下一段动作前请求审核。用于补捉“运动流畅但目标错了”的情况；20步是1秒仿真时间，不是1秒墙钟 |

停滞规则中的“范数之和≥1.5”是归一化命令强度，不是1.5米；“路程”是每步实测 XYZ 位移长度之和，不是窗口首尾净位移。这样不会把明显来回运动误称为完全没动，但来回振荡也不会被这条规则发现，先由周期复核处理。以上3段、3 mm、0.05 rad和20步均需用回放检验误报与漏报，再冻结用于在线对照。〔E3〕

**不能声称这四条已经覆盖“首次接触前”。** 末端坐标并不告诉主机把手在哪里，夹爪切换也可能晚于接触。尤其开着夹爪碰撞或推动错误部件，第一版可能只能靠周期审核发现；这是要测的盲区。〔E3〕

### 如果要在接触前触发，需要补一项视觉输入

为已确认的目标把手建立图像区域，并跟踪目标与夹爪尖端。一个可测的二维触发规则是：在224×224腕部图像上，夹爪尖端进入“目标区域向外扩12像素”的区域，连续2个控制步成立，就在下一步动作前审核；目标跟踪连续2帧失效，则发“目标丢失”，不能当作没有风险继续跳过。12像素、2帧只是试点值。〔E3〕

这要求新增目标／夹爪定位与逐步检查，当前代码没有该能力。二维邻近也不等于三维接触，必须标注真实接近事件来测提前量、误报和漏报。若只在5步结束后检查，它只能算事后审核，不能写成接触前门控。〔E3〕

### 同一事件怎样避免反复调用

- 同一检查点命中的事件合并为一次请求，例如同时带“准备闭爪”和“定期复核”，不发两次。首次确认、任务变化、目标丢失不被冷却规则压掉。〔E3〕
- 一次放行只对应当前 `observation_id + candidate_id + 获准执行前缀`。若状态或候选变了，旧放行不能直接复用。夹爪仍连续请求同一方向，不算新切换。〔E3〕
- 停滞事件触发一次后保持已上报状态，不在原地每次重规划都重发。若批准一次继续尝试而下一段仍无改善，就进入明确的恢复／终止决定；不能无限放行。开始新的恢复阶段或实测末端路程超过3 mm后才重新计数。参数仍需对照验证。〔E3〕
- 第一版沿用当前阻塞仿真：等待时不执行待审核候选。真机需要单独实现保持当前夹爪状态的控制保持与超时处理，不能把项目的 `DUMMY_ACTION` 当作通用保持，因为它会张开夹爪。〔E1/E3〕

给 LLM 的新增事件字段可以很短，例如：

```json
{
  "observation_id": 42,
  "candidate_id": "c42",
  "events": ["gripper_open_to_close"],
  "switch_at_candidate_step": 3,
  "review_request": "结合当前图像确认：这段闭爪动作是否针对底层把手？"
}
```

实际请求仍携带当前图像、状态与候选；这段只是新字段示意。LLM 的允许回复需区分放行、恢复、无法确认和结束；“无法确认”必须接到真实可执行的观察／保持流程，不能继续沿用含义是结束回合的 `stop` 来冒充观察暂停。〔E3〕

为什么值得先试：抽屉首次接管已经到第125／300步，接管前中层被拉开约11.31 cm；但未标注最早可辨认错误的画面，因此不能把125步全算成漏检延迟。应在旧日志上先检查上述规则会在哪一步触发，再用新在线回合验证是否提前发现错层、是否增加误干预，以及实际省了多少等待。离线回放无法证明介入后的轨迹会成功。〔E1/E3〕

## 2. WAM 比较少量动作的后果，后训练就围绕这些真实结果做

对抽屉问题，先让 WAM 回答一个具体问题：**执行这段动作后，移动的是中层还是底层，还是只让机械臂脱离了接触？** 不先要求它生成长视频。它预测的是结果，不是最终执行指令。〔E3〕

在触发疑似错层／停滞后，比较最多三个候选：继续 VLA、执行已有恢复控制器支持的脱离动作、执行已实现的观察动作。后两个候选当前未必存在，需先构造合法可执行动作，不能只给 WAM 一个“退开看看”的文字标签就认为能执行。第一版先预测5步后果，随后用真实执行检验。〔E3〕

| 输入 | 希望获得的预测〔E3〕 |
|---|---|
| 当前双视角图像、proprio、任务目标、带单位／控制频率的实际候选 | 哪个对象／部件可能变化、接触或遮挡可能如何变化、是否有目标进展，以及预测不确定性 |

若 WAM 预测继续动作只会移动中层，主机把该冲突交给 LLM 判断是否恢复；若目标本身没认清或预测不可靠，就重新观测／回退原审核。WAM 不能依据自己的预测宣布任务成功。动作数组简单求和也不能当作真实未来轨迹。〔E3〕

**同一批分叉数据，可以分别训练三个模块：**

- 审核器／LLM 学“什么时候应该拒绝、观察或交还”，标签来自独立图像标注与实际后果，不直接抄原 GPT 决定。闭源模型不能直接后训练时，可训练小审核器；prompt 改动另列。〔E3〕
- VLA 学“从错层接触恢复到正确把手”的动作序列，需要真实成功正例。当前13次接管虽使末端平均移动约34 mm，底层却没动，不能当成功恢复示范。〔E1/E3〕
- WAM 学候选对应的对象后果；预测误差和不确定性要单独校准。仿真真值可以作为明确声明的训练标签或独立评分，不能悄悄加入部署侧输入。〔E3〕

具体采集方式是从同一可完整恢复的失败状态分叉，实际执行各候选，再记录后续观测与结果。必须恢复模拟器、控制器、策略随机状态和必要历史；分叉后重新调用策略。现有π未执行的后5步没有后果标签，不能从原日志后续轨迹拼接出来。训练／测试按初态和完整回合分开，避免相邻帧泄露。〔E3〕

是否加入 WAM，比较轻量触发器基线与“相同触发器＋WAM”，其他配置不变。记录新增预测耗时、少调用的 LLM 次数、错误对象操作和预算内成功；只有减少的等待／恢复成本超过新增成本，且质量约束满足，才值得保留。当前报告没有证明这个净收益。〔E3〕

## 3. 让有效决定尽早交付，但恢复不能只维持五步

Hybrid 当前每轮输出约330个可见 Token，可见 Decode 约9.3–9.6 s；GPT 往返占整轮76%–82%，π推理与同步仅2.3%–2.8%。因此先比较短完整回复，比先加速π内核更直接针对当前瓶颈。〔E1/E3〕

放行回复可以只保留请求／观测／候选身份、`mode`、`steps`和必要目标核对结果；拒绝或恢复时再带短证据和该模式动作参数。删除未启用动作分支和每轮重复任务清单，主机仍需收到完整 JSON 并校验后执行。不能一看到 mode 就执行，原记录已有废弃流后重发的情况。〔E1/E3〕

恢复则作为主机保存的持续状态，例如“重新确认并操作底层把手”。每次仍执行不超过5步，再用最新观测闭环检查，但不会因为一段动作结束就清掉恢复目标。交还前需要确认正确部件和有效进展，不能只检查末端到位或 GPT 说 `recovered`。这些视觉验证器也需要实现与评估，当前不能称已有。〔E3〕

交还后的保护可以先具体设为：接下来2个 VLA 动作段仍逐段审核，只要目标再次不明确或动作意图偏离，就撤销交还、重新进入恢复；两段均通过后才恢复事件触发模式。2段是试点窗口，需要与1段、3段对照，不能保证不再失败。这样可以分别测恢复成功率、交还后再失败率以及保护窗口增加的等待。〔E3〕

建议分三次对照，不一次改完：先固定输入与审核频率，只改回复格式；再加主机触发器，看调用减少后是否漏检；最后改恢复交还流程。WAM及模块后训练另作增量实验。全部以原生任务结果、错对象操作和完整回合墙钟共同验收；不能靠早停失败或把保存移到末尾来制造提速。〔E3〕

时间口径仍保持原报告：TTFT不是纯Prefill，可见Decode不是服务端纯解码，“含推理TPOT”只是同一Decode时间换分母，不能衡量隐藏推理阶段速度。〔E1〕
