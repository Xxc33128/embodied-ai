# 具身智能测试项目与数据汇总

版本：v1.1 · 更新日期：2026-10-16

本汇总只列三个已开展的实验项目：机器人抓放评测、GPT-as-Policy 和 RPent。RPent 中的 DeepSeek 性能专项单独列出，便于查看模型对照和计时实验。实验结果依据已有配置、日志和报告记录〔E2〕；架构与指标定义依据源码核查记录〔E1〕；解释和比较边界标为〔E3〕。

## 1 各项目测什么及项目架构

### 1.1 机器人抓放评测

**测什么**：让不同模型观察同一个机械臂场景，独立决定怎样抓起红块、搬到碗口并释放，比较任务完成情况、动作决策过程与成本。环境是 robosuite Panda 仿真，模型使用前方、侧方和腕部三路图像，以及末端位姿、夹爪和关节状态。〔E2〕

**项目架构**：

> 三路图像＋机械臂状态 → 大模型输出目标位姿／夹爪指令 → inspect-robots 工具适配与 OSC_POSE 控制器 → Panda 仿真执行 → 新图像与状态返回模型。〔E1〕

这一项目由大模型直接通过 `move_to` 等工具控制机械臂，没有 π0.5 学生策略。标准预算为每次任务最多20次模型决策、900个控制步。〔E1／E2〕

### 1.2 GPT-as-Policy 三路线对照

**测什么**：在相同任务和初态下，比较纯 VLA、纯 GPT，以及 GPT 审核 VLA 动作三种控制方式。场景来自 MuJoCo／LIBERO，使用外部相机、腕部相机和机器人状态。〔E2〕

**项目架构**：

- **Student，纯 VLA**：图像＋状态＋任务 → π0.5 生成动作块 → 执行前几个动作 → 更新观测。〔E1〕
- **Direct，纯 GPT**：图像＋状态＋任务 → GPT 输出动作决策 → 合法性检查 → 仿真执行。〔E1〕
- **Hybrid，GPT＋VLA**：π0.5 先生成候选动作 → GPT 选择接受、修改或接管 → 合法性检查 → 仿真执行。〔E1〕

GPT 使用 Astra／medium，VLA 使用 π0.5。π0.5 每次输出10×7连续动作值，逐轮实验最多执行前5步，再获取新观测；Hybrid 中出现 GPT 调用，不代表一定发生了动作修改。〔E1／E2〕

### 1.3 RPent 任务规划与技能执行

**测什么**：让大模型把较长的机器人任务拆成工具／技能调用，比较不同大脑、不同任务套件和运行模式的完成情况与耗时。〔E2〕

**项目架构**：

> 任务＋观测＋冻结任务记忆 → LLM planner 选择工具／技能 → SAM3 提供目标定位，π0.5 技能或非π运动原语执行 → LIBERO 仿真返回观测与结果 → planner 决定下一步。〔E1〕

普通模式使用 GLM、Astra 或 Sol 作为大脑。Flash 模式使用冻结记忆回放和 Molmo2-8B，省去在线 LLM 规划；它仍有模型推理和机器人执行计算。〔E1／E2〕

### 1.4 RPent 中的 DeepSeek 性能专项

**测什么**：在 RPent 中换用 DeepSeek 大脑，比较开／关思考，并测清请求等待、可见思考、输出生成、载荷上传和本地执行的耗时。〔E2〕

**项目架构**：

> RPent API planner → DeepSeek API → 工具／技能调用 → π0.5／SAM3／LIBERO → 执行结果进入下一轮上下文。〔E1〕

非流式批次先记录整请求耗时；流式补测通过 transport shim 捕获响应分片，再重组响应交还 planner，以取得 TTFT、可见 thinking 窗口和 TPOT。Astra／Sol 的 Codex 接入批次与此 API planner 不同，分开比较。〔E1／E2〕

### 2.2 GPT-as-Policy 三路线实验

本表“三路线”指 Student＝π0.5，Direct＝Astra／medium，Hybrid＝π0.5＋Astra／medium。Ori 为原条件，Pos 为位置变化；18格的 Task 条件分别改成酒瓶放盘、奶酪与番茄酱入篮，并向三路线提供对应的新指令。〔E1／E2〕

| 做了什么测试 | 使用模型 | 测试场景 | 结果 | 统计的关键数据 |
|---|---|---|---|---|
| 18格条件对照 | 三路线 | 碗放盘／两罐入篮 × Ori／Task／Pos；init 0 | 原生Student 4/6、Direct 1/6、Hybrid 3/6 | 成功、控制步、回合耗时、Token、动作来源 |
| 单格独立复跑 | Hybrid | Goal task 8／Ori，碗放到盘上 | 仍提前stop，0控制步、失败 | stop调用、终止原因、Token、用时 |
| 三路线逐轮对照 | 三路线 | 两罐入篮／Ori，init 0，各1次 | 三路线均成功 | 每轮输入输出、π候选、Token、TTFT／TPOT估算、轨迹 |
| 三路线逐轮对照 | 三路线 | 杯入微波炉并关门／Ori，init 0，各1次 | Student和Hybrid成功；Direct失败 | 决策轮次、执行步、阶段耗时、Token、轨迹 |

**数据覆盖**：原18格记录5,432个控制步并完成完整性核验；后续三任务九回合独立记录610轮决策、3,008个控制步，其中428轮GPT、344轮π输入输出关联。〔E1／E2〕

**结果口径**：原18格的原生统计为8成功／10失败；展示版按人工裁定记为9成功／9失败，两者分开。九回合采用新的逐轮JSON协议，不替换旧18格；每格一个初态，不能给总体可靠性排名。微波炉Hybrid全程接受π候选，不能把该次成功称为GPT动作纠错收益。〔E2／E3〕

**另有基础设施探测**：8个π0.5 worker使用随机图像和固定状态／指令，共32次合成请求，32/32返回有限值的10×7动作；24次稳定态往返0.5137–0.6100秒。这是推理并发检查，没有运行八路机器人任务。〔E2〕

## 3 关键数据分别表示什么

| 关键数据 | 用途与口径 |
|---|---|
| 任务结果 | 原生环境成功、人工展示裁定、盲评阶段、recipe和进程退出码分开，判断完成任务不能只看进程正常退出。〔E1／E3〕 |
| 决策与执行量 | 模型请求数、工具次数、π采样块数、控制步、接管次数和失败类型，用于描述实际工作量。〔E1〕 |
| 输入输出与上下文 | 输入图片、任务／状态、工具Schema、π候选、模型动作输出及历史长度，用于核对模型实际看到了什么、执行了什么。〔E1〕 |
| Token与缓存 | input、output、cached input、reasoning；cached是input子集，reasoning是output子集，不能重复相加。〔E1〕 |
| TTFT与TPOT | 按对应协议定义的客户端首事件延迟及输出Token平均时延代理，不等于服务端纯prefill／decode。〔E1〕 |
| 分阶段耗时 | 模型等待、工具、π／SAM、物理、渲染、RPC、加载；父子区间可能嵌套，不能重复加总。〔E1〕 |
| 轨迹与视频 | 末端／关节状态、动作来源、视频帧及终态，用于复核抓取、放置、误操作和提前停止。〔E1／E2〕 |
| 配置与完整性 | 模型／档位、seed、初态、资产／文件哈希、attempt与排除记录，用于确保比较对象和统计分母明确。〔E1／E2〕 |

本汇总中的表格只统计已有实验记录。报告重构、旧数据再分析、计划与调研不另计实验；不同任务、接入协议和统计判据的结果不合成跨项目成功率。〔E3〕
