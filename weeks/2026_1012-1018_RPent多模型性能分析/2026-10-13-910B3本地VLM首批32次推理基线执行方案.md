## 0. 决策、证据与范围

**主模型选择 Qwen/Qwen3.8-27B，BF16，TP=2 起步。**它在 2026-08-14 发布，满足“优先较新模型”的要求；官方已有 Ascend 适配说明，但该说明明确聚焦 text serving。因此“910B3 上多图路径可运行”仍是部署前置门槛，不能把文本服务支持写成多模态已验证。[M1][M1]、[D1][D1]〔文献／E3；本机多模态兼容未核实〕

### 1.3 内存估算与 hybrid 架构

HF 元数据列出 27,781,427,952 个 BF16 参数，权重约 **51.75 GiB**；TP=2 理想均分约 25.87 GiB/rank，但视觉模块、embedding、workspace 和通信 buffer 不保证同样均分。[M3][M3]〔文献与推断／E3〕

该 checkpoint 的 decoder 有 **64 层：16 层 full attention＋48 层 Gated DeltaNet**，不是 MoE。full-attention 部分 KV heads=4、head_dim=256；BF16 的理论 KV 下界：

~~~text
KV bytes/token = 2(K,V) × 16 layers × 4 heads × 256 × 2 bytes
               = 65536 bytes = 64 KiB
262144 tokens  → 16 GiB（所有 full-attention 层合计）
TP=2 理想均分 → 8 GiB/rank（仅这些 KV）
~~~

这不含 Gated DeltaNet 的卷积／recurrent state、padding、chunk buffers、激活、临时内存和 allocator 预留。因此不能仅凭“权重＋KV 能放下”宣布部署通过；也不能将全注意力模型“每一层都读取完整历史 KV”的公式套给 64 层。[M4][M4]〔文献与推断／E3〕

为此，分阶段 profile 必须把 **full attention** 和 **Gated DeltaNet state update／gating／conv** 分开。小矩阵、Vector 与状态更新慢，可能与传统 attention 的 KV 带宽瓶颈不同。〔推断／E3〕

## 3. 任务二：制作 8 个真实固定请求

**输入：**获准的脱敏请求导出，或在同一 RPent adapter 中新采集的 t0/t9 仿真请求。当前还没有制作这些 fixture。
**产物：**fixtures/requests.jsonl、图像文件、manifest；不能用报告里的“平均 9 张图”合成替代真实请求。

| 请求 ID | 场景 | seed／独立初态 | 位置 |
|---|---|---|---|
| t0-s0-early / t0-s0-late | t0 | 合法初态 0 | 早／晚各一次 |
| t0-s1-early / t0-s1-late | t0 | 合法初态 1 | 早／晚各一次 |
| t9-s0-early / t9-s0-late | t9 | 合法初态 0 | 早／晚各一次 |
| t9-s1-early / t9-s1-late | t9 | 合法初态 1 | 早／晚各一次 |

这里 0/1 是该任务的两个合法独立初态编号；若项目种子映射不同，manifest 记录实际映射，不能将同初态不同 RNG 名称当两个独立状态。每个源 episode 固定取**首个带完整观测的决策**和**按请求序号到达 75% 位置的决策**（索引 ceil(0.75×R)−1，R 为该 episode 带完整观测的决策数）。R<2 时该 episode 不合格，记录原因后重新采集；取样不按是否成功或时延大小筛选。〔推断／E3〕

上一步容器已设 VLLM_SERVER_DEV_MODE=1，以注册 cache reset 接口；服务仅绑定 loopback。另一个终端进入同一实验容器后运行客户端。启动失败、算子不支持、图像 processor 报错或两卡内存不足都属于**部署结果**，不产出推理加速结论。[P2][P2]〔文献与推断／E3〕

功能门槛：

- [ ] 先测 text-only，再测单图，再测冻结集合中最多图／最长输入。核查输出不是空串／报错，trace 中视觉 encoder 确实执行。
- [ ] 用两张内容明显不同的受控图各提同一视觉问题，人工确认输出依赖图像；这仅查基本视觉通路，不证明空间推理能力。
- [ ] 所有 8 个正式输入各做 2 次预热，确认输入无截断、完整执行，输出 token IDs 接口工作且为 128。
- [ ] 对全部 fixture 记录 processor 输出 shape／image grid。若框架现成 trace 不暴露该信息，先在独立诊断轮加形状日志；不得用“总 token 数”冒充视觉 token 数。
- [ ] 若 BF16 TP2 因内存不通过，先诊断权重／KV／激活阶段；统一改 TP4 后重启整个 cohort。若模型的多图算子不支持，则记录阻塞项；辅助 8B 单独建立 cohort，不悄悄替换主模型结果。

## 5. 任务四：32 次计时与可复制客户端

### 5.1 计数与缓存协议

| 批次 | 数量 | 是否计入 32 |
|---|---:|---|
| 功能检查 | text、单图、多图及视觉依赖检查，按门槛需要 | 否 |
| 形状预热 | 8 请求 × 2＝16 次 | 否；全部留日志 |
| **正常计时** | **4 个 block，每 block 将 8 请求随机排列一次＝32 次** | **是** |
| profile 服务重新预热 | 重启服务后 8 请求×2＝16 次 | 否；不沿用旧进程的预热状态 |
| profile | 最短与最长实际输入，各连续 2 次＝4 次起步 | 否；用于检查重复请求是否仍执行视觉编码 |
| 后续自由生成 | 当前实现 8 次；优化实现再 8 次 | 否；属于 H1 总预算的 16 次自由生成 |

**完整首轮执行预算为 16 次基线预热＋32 次计时＋16 次 profile 服务预热＋4 次 profile＝68 次，另加功能检查；32 只指核心计时组。** 后续若增加测量开销标定另记次数。

每次请求前，在无在途请求时重置 prefix、MM processor 和 encoder cache；权重与运行环境仍热。mm-processor-cache-gb=0 只关闭相应 processor cache，不代表全部缓存清空。reset 接口源码不保证 HTTP 200 就代表 reset 成功，需 profile 中看到重复请求仍走视觉路径，并检查实际 prefix hit／残余重算。**未经确认的“冷缓存”只能标为 cold_requested，不标为 cold_verified。**[P2][P2]、[P3][P3]〔文献与推断／E3〕

正常计时不开 profiler。四个 block 的顺序预先固定并存档，未来优化方案沿用同顺序；发生错误保留原行并停止，不静默重试直到凑满 32。需要重跑时开新批次目录，注明旧批次为何无效。32 次只能报告每个固定输入的中位数、范围和原始四点，不用于稳定估计 p99。〔推断／E3〕

### 5.2 客户端脚本

将以下完整代码保存为实验目录的 pilot32.py。依赖 requests（容器通常已带；缺失时只在独立实验环境安装并记录版本）。该客户端记录 **server 返回的 token IDs**；不能对最终文本重新 tokenize 代替。stream 的 token_ids 是逐 chunk 的增量，prompt_token_ids 只在首 chunk 返回。[P1][P1]〔文献／E3〕

~~~python
import argparse, base64, copy, hashlib, json, mimetypes, pathlib, random, time
import requests

def canonical(x):
    return json.dumps(x, ensure_ascii=False, sort_keys=True, separators=(",", ":")).encode()

def digest(x):
    return hashlib.sha256(canonical(x)).hexdigest()

ap = argparse.ArgumentParser()
ap.add_argument("--fixtures", required=True)
ap.add_argument("--out", required=True)
ap.add_argument("--phase", choices=["warmup", "timed", "profile"], required=True)
ap.add_argument("--profile-ids", nargs=2)
ap.add_argument("--baseline-refs", help="后续实现使用主基线的 warmup-refs.json，不重新定义跨实现参考")
args = ap.parse_args()
root = pathlib.Path(args.fixtures).resolve().parent
out = pathlib.Path(args.out)
out.mkdir(parents=True, exist_ok=True)
rows = [json.loads(x) for x in pathlib.Path(args.fixtures).read_text().splitlines() if x.strip()]
expected = {f"t{s}-s{k}-{p}" for s in [0, 9] for k in [0, 1] for p in ["early", "late"]}
assert len(rows) == 8 and {r["id"] for r in rows} == expected
items = {}
for row in rows:
    body = copy.deepcopy(row["body"])
    assert set(body) == {"messages"}, "先完成并冻结输入适配"
    nimg = 0
    for msg in body["messages"]:
        if not isinstance(msg.get("content"), list):
            continue
        for c in msg["content"]:
            if c.get("type") != "image_url":
                continue
            nimg += 1
            u = c["image_url"]["url"]
            if u.startswith("file:"):
                p = (root / u[5:]).resolve()
                assert p.is_relative_to(root)
                mime = mimetypes.guess_type(p.name)[0]
                assert mime in {"image/png", "image/jpeg", "image/webp"}
                c["image_url"]["url"] = "data:" + mime + ";base64," + base64.b64encode(p.read_bytes()).decode()
            else:
                assert u.startswith("data:image/"), "禁止计时中拉取远程图片"
    assert nimg > 0
    items[row["id"]] = {"body": body, "input_sha256": digest(body), "images": nimg}

session = requests.Session()
session.trust_env = False
base = "http://127.0.0.1:8018"
logpath = out / (args.phase + ".jsonl")
assert not logpath.exists(), "批次已存在；保留它并选择新目录，或只运行尚未执行的 phase"
refpath = out / "warmup-refs.json"
refs = json.loads(refpath.read_text()) if args.phase != "warmup" else {}
master = json.loads(pathlib.Path(args.baseline_refs).read_text()) if args.baseline_refs else None
if args.phase == "warmup":
    assert not refpath.exists()

def post_admin(path):
    r = session.post(base + path, timeout=600)
    r.raise_for_status()

def reset_caches():
    for path in ["/reset_prefix_cache", "/reset_mm_cache", "/reset_encoder_cache"]:
        post_admin(path)

def request_one(key, block):
    item = items[key]
    rid = f"chip32-{args.phase}-{block}-{key}"
    body = copy.deepcopy(item["body"])
    body.update(model="chip-vlm-baseline", stream=True,
                stream_options={"include_usage": True}, return_token_ids=True,
                temperature=0, top_p=1, top_k=-1, seed=20261013,
                max_tokens=128, min_tokens=128, ignore_eos=True,
                chat_template_kwargs={"enable_thinking": False}, request_id=rid)
    payload = canonical(body)  # JSON 与 base64 准备均不计入请求时延
    rec = {"request_id": rid, "fixture": key, "block": block,
           "input_sha256": item["input_sha256"], "images": item["images"],
           "http_body_bytes": len(payload), "cache_state": "cold_requested",
           "phase": args.phase, "status": "started"}
    ids, prompt_ids, events = [], None, []
    first = last = first_text = None
    usage, finish, done = None, None, False
    try:
        t0 = time.perf_counter_ns()
        with session.post(base + "/v1/chat/completions", data=payload,
                          headers={"Content-Type": "application/json"},
                          stream=True, timeout=(30, 3600)) as response:
            response.raise_for_status()
            assert "chunked" in response.headers.get("Transfer-Encoding", "").lower(), "需核实非 chunked SSE 的读取行为"
            for line in response.iter_lines(chunk_size=None, decode_unicode=True):
                if not line or not line.startswith("data:"):
                    continue
                data = line[5:].strip()
                if data == "[DONE]":
                    done = True
                    break
                now = time.perf_counter_ns()  # 当前完整 SSE 行到达后、JSON 解析前
                obj = json.loads(data)
                if obj.get("error"):
                    raise RuntimeError("stream returned error")
                if obj.get("prompt_token_ids") is not None:
                    prompt_ids = obj["prompt_token_ids"]
                if obj.get("usage") is not None:
                    usage = obj["usage"]
                for choice in obj.get("choices", []):
                    assert choice["index"] == 0
                    token_ids = choice.get("token_ids") or []
                    if token_ids:
                        first = now if first is None else first
                        last = now
                        ids.extend(token_ids)
                        events.append({"ms": (now - t0) / 1e6, "tokens": len(token_ids)})
                    delta = choice.get("delta") or {}
                    if first_text is None and any(delta.get(k) for k in
                                                   ["content", "reasoning", "reasoning_content", "tool_calls"]):
                        first_text = now
                    if choice.get("finish_reason") is not None:
                        finish = choice["finish_reason"]
        tend = time.perf_counter_ns()
        assert done and prompt_ids is not None and usage is not None
        assert len(ids) == 128 and usage["completion_tokens"] == 128, "不满足固定长度"
        assert first is not None and last is not None
        rec.update(status="ok", output_token_ids=ids, output_sha256=digest(ids),
                   prompt_ids_sha256=digest(prompt_ids), prompt_ids_count=len(prompt_ids),
                   usage=usage, finish_reason=finish, token_events=events,
                   ttft_client_token_ms=(first-t0)/1e6,
                   ttft_client_text_ms=None if first_text is None else (first_text-t0)/1e6,
                   last_token_client_ms=(last-t0)/1e6, response_complete_ms=(tend-t0)/1e6,
                   tpot_client_proxy_ms=(last-first)/1e6/127)
        sig = {k: rec[k] for k in ["input_sha256", "prompt_ids_sha256", "output_sha256"]}
        if master is not None:
            rec["same_input_and_sequence_as_master_baseline"] = sig == master[key]
        if args.phase == "warmup" and block == 0:
            refs[key] = sig
        else:
            rec["same_input_and_sequence_as_reference"] = sig == refs[key]
            if args.phase == "warmup":
                assert sig == refs[key], "两次预热不一致；先诊断，再决定等序列配对是否可行"
        return rec
    except Exception as e:
        rec.update(status="error", error_type=type(e).__name__, received_tokens=len(ids))
        raise
    finally:
        with logpath.open("a") as f:
            f.write(json.dumps(rec, ensure_ascii=False) + "\n")

if args.phase == "profile":
    assert args.profile_ids and all(x in items for x in args.profile_ids)
    order = [(i, k) for i, k in enumerate(args.profile_ids) for _ in range(2)]
else:
    order = []
    for block in range(2 if args.phase == "warmup" else 4):
        keys = sorted(items)
        random.Random(20261013 + block).shuffle(keys)
        order.extend((block, k) for k in keys)
(out / (args.phase + "-order.json")).write_text(json.dumps(order))
for ordinal, (block, key) in enumerate(order):
    reset_caches()  # reset 及等待不计入请求计时；200 仍须 trace 复核
    if args.phase == "profile":
        post_admin("/start_profile")
    try:
        rec = request_one(key, ordinal if args.phase == "profile" else block)
        print(key, rec["status"], round(rec["ttft_client_token_ms"], 2), flush=True)
    finally:
        if args.phase == "profile":
            post_admin("/stop_profile")
if args.phase == "warmup":
    refpath.write_text(json.dumps(refs, indent=2))
~~~

## 6. 任务五：如何采集各层指标

### 6.1 正常计时：32 次能直接得到什么

| 指标 | 获取方式 | 可说明什么 | 不能说明什么 |
|---|---|---|---|
| 客户端 TTFT | 发 HTTP 前至第一批非空 token IDs；另存首文本 delta 时间 | 本地完整请求首 token 延迟，含传输／排队／前处理 | 不是纯 prefill，更不是 HBM 时间 |
| 末 token／响应结束 | 两个时间分别保存 | 固定 128 tokens 的完成延迟与尾部协议开销 | 不是自然工具决策完成时间 |
| TPOT client proxy | (最后 token 事件−第一 token 事件)/127 | 在等长串行条件下筛选 decode 问题 | SSE 可一次携带多 tokens，不是真实逐 token device latency |
| 输出与输入一致性 | 真实 IDs、SHA256、usage、fixture manifest | 是否具备同输入、同长度／同序列比较条件 | 文本重新 tokenize 不能补造真实 IDs |
| 请求波动 | 每 fixture 四点、median/min/max，保留 block 顺序 | 是否存在明显漂移、长短请求差异 | 32 次混池的 p99、微小差异显著性均不可靠 |
| HBM 占用／设备状态 | 请求前后 npu-smi；高频状态采样放诊断轮 | 常驻预算和外部干扰线索 | 前后快照不是精确 peak；占用百分比不是有效带宽 |

**观测开销边界：**return_token_ids 会额外在首个 SSE chunk 回传完整 prompt IDs，长上下文会增加服务端序列化、传输和客户端解析。脚本已避免逐字节读取，并在解析当前行前打时间戳，但无法消除前一行解析及服务端开销。因此这里报告的是**带 token-ID 观测的客户端时延**，不是默认生产 API 时延；不能用其随上下文增长的斜率推导芯片 KV 成本。芯片归因依赖设备 trace／kernel 测量。若另要原生服务时延，需同 fixture 关闭 return_token_ids 做配对诊断并单独报告，该组不提供实际 token 序列相同的证据，也不能从其均值简单扣减一个“固定观测税”。[P1][P1]〔文献与推断／E3〕

循环外保存 /metrics 前后快照及服务日志，以 request_id 对齐可用的 queue／prefill／decode 信息；聚合 histogram 没有 request ID 时只能称全轮统计。不要相减两个 p99 得到“阶段 p99”。〔推断／E3〕

### 6.2 另开 profile：分解慢在哪里

执行顺序固定为：**停止本次实验服务 → 保存原件并打诊断补丁 → 启动诊断服务 → 重新预热 → profile**。不操作现有 RPent 服务。

**shape 采集补丁只用于独立诊断环境：**固定版本的 Ascend wrapper 默认未传 record_shapes，且 op_attr／record_op_args 关闭；只加上游 profiler-config 的 shape 开关不能保证该 wrapper 读取。下面在停止的实验服务环境中修改 profiler wrapper，保存原件和 SHA256；正常 32 次仍使用未修改版本。[P7][P7]〔文献与推断／E3〕

**进程覆盖范围：**服务的 start_profile 主要控制 model workers，不能假设同时覆盖 API server 的图片解码／processor／tokenizer。CPU 前处理需在实际执行它的进程另开 CPU profiler 或加单调时钟区间，并将 request_id 关联到 worker；缺少这份记录时相应阶段填 NA，不能把 worker 的 CPU gaps 当成图像前处理时间。〔推断／E3〕

分别保存所有 TP ranks 的 trace。优先分析 trace_view.json、kernel_details.csv、operator_details.csv、step_trace_time.csv 等实际产物；文件名／导出方式以容器内 profiler 版本为准。接口存在不代表 NPU trace 已成功采到；只有 CPU trace 时标注缺设备证据，先修采集。[D4][D4]〔文献与推断／E3〕

| 阶段／指标 | 采集方法 | 面向芯片的解释 |
|---|---|---|
| image decode／resize／normalize、tokenization | CPU profiler 范围＋输入 bytes／pixel shape；处理函数缺 range 时在独立诊断副本加 record_function | CPU 关键路径明显：先优化前处理／DVPP 可用路径，不能因此要求更大 Cube |
| H2D、D2D、layout conversion | trace 中 copy／转换 kernel 的 bytes、dtype、shape 和依赖 | 判断 DMA、布局、通路与重叠是否值得研究；不能将客户端上传时间计作 H2D |
| vision encoder＋projector | 模型函数 range 对齐设备 kernel；逐图 patch／grid、GEMM、attention、Norm 形状 | 大矩阵未饱和先查 tiling；Norm／Softmax／往返搬运重则查 Vector、融合、片上 buffer |
| text/multimodal prefill | 输入 token 数、chunk 数、每 chunk 的 full-attention／GDN kernel | 区分长 prompt 算力与 chunk／调度限制；不能把全部 TTFT 归此阶段 |
| decode：QKV／MLP／logits | 每步实际 M/N/K、权重 dtype、kernel 时间、必要权重字节估算 | B=1 小 M 是否需要更高效 GEMV／小矩阵执行；先排除实现没使用已有能力 |
| decode：full attention | 16 层实际 KV 长度／layout／读取量、Softmax／reduction、split 数 | 检验带宽、并行切分和跨核归约；不能只按低 FLOPS 利用率说算力不足 |
| decode：Gated DeltaNet | 48 层 gating、conv、state read/write/update 的真实 shape 和 kernel | 检验小状态驻留、Vector、局部数据通路及 kernel 融合；不要按全历史 KV 解释 |
| HCCL／rank 等待 | 各 rank collective、持续时间、与计算重叠和关键路径 | 检验跨卡通信代价；TP2/4/8 的同模型对照是后续实验 |
| CPU launch／设备空洞 | host API→enqueue→kernel 的相关事件与依赖 | graph／launch 优化优先；未排除软件调度前不提新执行单元 |
| 内存与执行单元 | msOpProf 的可用 ArithmeticUtilization、PipeUtilization、Memory、MemoryL0、L2Cache 组 | 配合 bytes/time 和 shape 判断 roofline；缺失计数标 NA，不填 0 |

最后一行的计数器依据 [msOpProf 数据说明][D5]。**910B 不承诺支持 950 才有的 PipeTimeline／instrTimeLine／PcSampling**；计数器组可能需独立运行。msOpProf 默认 kernel replay 会清 L2，其流量／时延不可冒充完整模型暖权重下的实际状态；application replay 与多设备支持也需按版本核实。〔文献／E3〕

record_function 的 CPU 范围不是异步 NPU kernel 耗时。按 correlation／stream 对齐设备事件；多 rank、多流水有重叠，报告关键路径与并集，不把所有 kernel 时间、rank 时间相加当端到端时长。不能靠 TTFT−encoder−H2D 简单相减补出不存在的精确 prefill。〔推断／E3〕

## 7. 每种结果对应什么芯片问题

下表是**判断规则，不是预报结论**。必须先补齐相应 trace／计数器，32 次 HTTP 数据单独不足以完成所有归因。〔推断／E3〕

| 观察到的结果 | 当前能说的 | 必须补的对照 | 可能支持的芯片方向 |
|---|---|---|---|
| decode 小 M 线性层占主路径，实效流量接近相同 shape 的带宽基线 | 权重供数可能主导 | 同 dtype 的 GEMV／现有矩阵模式，真实 bytes vs 必要 bytes；低层带宽标定 | HBM 有效带宽、权重供数、适合小 M 的 GEMV 数据路径 |
| 小 M 很慢但带宽与执行单元都低，launch gaps 多 | 先怀疑软件／并行度 | eager vs graph、融合、tiling；保持数值／输入 | 若最优实现仍受限，再讨论低开销 dispatch、细粒度同步 |
| 长 KV 的 full-attention 变重，归约／Softmax 主导 | KV 和归约可能是瓶颈 | 控制 shape 的长度扫；split-KV 与非 split，含中间结果成本 | reduction 单元、Vector 吞吐、片上带宽／buffer；未必只加 HBM |
| GDN 更新占 decode 主要时间 | hybrid 的状态处理值得单独研究 | state layout／融合／片上驻留，排除 fallback kernel | 低延迟状态更新、Vector／小矩阵配合及片上存储端口 |
| 多图 ViT 占 TTFT 大头 | 视觉计算是优先热点 | 同输入做 GEMM／Norm／Softmax／layout 分解 | vision encoder 的 GEMM＋Vector＋搬运协同；不是直接宣称需专用“空间芯片” |
| 图像 CPU 前处理／上传占大头 | 当前系统没有把时间花在目标 NPU 核心 | 本地 bytes→tensor 与 encoder 输入就绪边界计时 | 先做图像解码、DMA／前处理协同；只有有效卸载证据才谈专用单元 |
| 多卡 collective／等待占主路径 | TP 可能损害 B=1 latency | 同模型 TP2 vs TP4；通信与计算重叠，固定卡对 | 低延迟片间互联／collective；不能宣称用满八卡会更快 |
| 重复图像 cache 组明显改善 TTFT | 存在精确复用价值 | cold_verified vs hit_verified，记录 hash、残余计算和内存代价 | encoder feature／prefix 存储与访问；收益先属于缓存策略，不全归新芯片 |
| 各阶段比例随重复漂移，队列／外部任务波动 | 当前测量受到干扰 | 独占时间窗、温度／功耗／时钟和 CPU 抢占记录 | 先不做芯片缺陷结论 |

必要字节估算除以 kernel 时间应标 **estimated required-byte rate**；只有计数器给出实际读写 bytes，才称 measured HBM traffic／bandwidth。roofline 的算力和带宽分母应优先来自本机同 dtype、同类形状的标定，不拼接不同 SKU 的宣传峰值。〔推断／E3〕

### 7.1 首轮结果表与验收

每个 fixture 一行，另附四次原始测量：输入 tokens、图像数／视觉 tokens、128 输出是否满足、输入与输出 hash 是否一致、TTFT median/min/max、TPOT proxy median/min/max、完成时延、cache 验证状态。profile 另表：CPU 前处理、视觉、prefill、full-attention decode、GDN decode、MLP/logits、HCCL、空洞；无法分开的项目写 NA／inclusive。〔推断／E3〕

首轮通过条件：

- [ ] 8 个冻结 fixture、32 个完整结果，失败记录无丢失；实际 token IDs、usage 与 128 长度一致。
- [ ] 权重、dtype、processor、输入、并行度、版本和顺序均可复现；没有图像／上下文静默裁剪。
- [ ] 冷路径有重复请求的视觉执行证据；未确认时只报告 cold_requested。
- [ ] 正常计时与 profile 分开；设备 trace 能定位至少两类主要耗时，不能只拿一张 npu-smi 占用截图。
- [ ] 若同一 fixture 的 max/min>1.2，作为**排查提示**核对外部干扰；不是显著性阈值，也不删离群值。
- [ ] 选出下一阶段最多两个热点，并用关键路径占比估算 Amdahl 上限；未定位则继续修测量链，不能任选两个硬件单元立项。

## 8. 后续实验清单与预算关系

**对原 H1 的协议修订：**原报告把 96 次写成“定长 token 重放”。当前可执行 vLLM 路线改为 **96 次等长生成＋实际序列一致性核查**，即 3 条路径×8 请求×4 次；本次 32 次是其中“原实现冷路径”一组。另有 16 次自由生成，共 **112 次计时调用**。严格 teacher-forced replay 留给后续 kernel／增量 forward harness，不能宣称由标准 chat API 已实现。〔推断／E3〕

| 顺序 | 实验 | 最小工作量／产物 | 解决的问题 |
|---|---|---|---|
| **现在准备** | H1 第一组 | 本文 32 次＋独立预热／profile | 近期本地 VLM 的首批瓶颈证据 |
| 下一步 1 | H2 真实 shape 热点 kernel | 从前两大热点取 shape；B=1 主测，B=2/4/8 诊断；每条件预热后至少 20 次 | GEMV、小矩阵、KV reduction、GDN、Vector／搬运中哪条通路限制性能 |
| 下一步 2 | H1 补齐 | 优化实现冷路径 32 次＋精确缓存命中热路径 32 次；原／优化各 8 次自然生成 | 分开已有软件优化、精确缓存与实际任务输出收益 |
| 下一步 3 | 同硬件控制 | eager vs graph、chunk budget、TP2/4（必要时8），一次只改一项 | 消除把框架／部署问题误判为芯片缺陷的可能 |
| 下一步 4 | H3 硬件反事实 | 经 kernel 标定后，对两类主限制逐项扫 1×/1.5×/2×资源 | 先给性能敏感性／反事实；面积与功耗仅在取得经校准架构模型、RTL／综合或可信参数后评估；不以简单比例当已造出芯片 |
| 闭环验收 | H4 | 入选两个实现×两场景×5 独立初态＝20 集独占，再20集共置，共40集 | 提速是否保留任务效果，是否影响 VLA 控制 deadline |

自然生成使用原生 EOS／停止条件、足够输出上限和可用工具 parser；恢复原任务输出协议，另报工具合法性、自然输出长度与结果。强制输出 128 tokens 后半段可能已越过自然回答结束，不可用其判定任务成功率。〔推断／E3〕

**四个问题的最小实验仍各自独立：**Q1 先本文32次，再补 H1/H2/H3/H4；Q2 64集两组主比较＋30困难状态短分支；Q3 200集评测；Q4 50集调度筛选。完整冻结条件见 [四问题清单 §6](2026-10-13-VLM-VLA双脑架构与推理优化调研.md#6-四个问题的最小实验清单)。不能把同一 fixture 的四次重复当四个独立任务，也不能将推理调用数与 episode 数相加。〔推断／E3〕
