# Motus 与 910B3 联合端到端 RL 实验预注册

> v1.0 · 2026-10-14 · 状态：设计与执行方案；未修改模型代码、未部署训练环境、未启动训练。

**目标：在昇腾 910B3 上，让真实物理仿真任务回报同时更新 Motus 内部 VLM、世界模型和动作模块的指定参数，并验证联合更新是否优于 action＋understanding 连接参数基线。**所有模型训练从第一版起就在 NPU 上进行。CPU 用于物理仿真、渲染、数据处理和小张量数值参考。

具体代码任务、接口、命令契约和资源验收见[执行方案](../../docs/superpowers/plans/2026-10-14-motus-910b3-joint-rl.md)。本文件保存研究问题与实验判据；执行清单不在周目录重复维护。

## 2. 已确认设计与范围

### 2.1 严格端到端定义

使用内部特征融合：`真实观测与指令 → Qwen3-VL 特征 → understanding/video/action joint attention → 动作概率 → 执行动作 → 环境回报`。

同一个 **task-RL loss** 必须使以下三个参数集合发生更新：VLM 内部 LoRA、参与控制的 video/WAN 参数、action 参数。Understanding adapter/expert 单独记录。不能用外接 adapter 更新代替 VLM 本体更新，也不能用 video SFT 梯度证明世界模型收到了任务 RL 信号。

第一版采用部分参数联合更新，不要求所有参数全量训练。VLM内部语言侧LoRA参与RL，视觉encoder首版冻结。Qwen 的未使用 `lm_head`、冻结 VAE/T5 和仅用于展示且不影响动作的输出不纳入“必须有 task-RL 梯度”的集合。视频输出头若通过前一去噪步影响后一动作分布，应纳入对应路径检查；不能笼统宣称每个 head 都被 RL 更新。

三模块都可训练不意味着环境可微。环境仅提供任务回报，策略梯度穿过模型内部确定性计算。其依据为[随机计算图](https://arxiv.org/abs/1506.05254)与[ReinFlow 路径策略梯度](https://arxiv.org/html/2505.22094v2)；把这些原理用于 Motus 是待验证的新适配。

### 2.2 首版算法

每个物理动作块独立采样 video/action 初始 Gaussian 噪声。视频采用确定性 Euler 递推，动作每个去噪步骤采用固定非零方差的 Gaussian transition。每步的两种速度从同一个起点状态计算，遵循 Motus 的 `noise → clean` 下降时间轴。

轨迹保存完整 raw action chain、初始噪声及旧 log-prob。更新时固定 action 样本，从头可微重算 VLM 特征和视频内部状态；不复用旧 video cache，不使用跨物理动作块的预测 KV cache。对完整动作生成路径计算 log-prob，不声称它等于最终动作 marginal likelihood。

首版使用 **REINFORCE＋前序批次 baseline**，每批 fresh rollout 只进行一次累计后的 optimizer step。正式比较的主版本关闭辅助 BC/FM，便于归因；若预试验显示遗忘，新增明确版本的辅助目标实验，不能在比较途中静默加损失。PPO、GRPO、learned noise、imagined rollout 和异步训练不属于首版必做范围。

### 2.3 任务与暖启动

第一环境为 CPU MuJoCo/LIBERO，OSMesa 渲染；使用独立实验轨迹，不读取既有敏感评测会话。基准任务候选为 LIBERO-Spatial 官方 task 0，执行前按冻结的 LIBERO 版本解析其任务名、BDDL 与初态哈希；若缺少合法且独立的训练/评估初态，停止该任务的数据准备。

从 Motus Stage 2 预训练共享权重出发，重建 7D action 输入输出与独立 proprio encoder，用该任务演示做监督暖启动。动作顺序为末端平移增量、旋转控制分量、夹爪；具体坐标系、旋转约定、单位及符号必须由环境版本和单轴探针验证，不能从“7D”推断。

候选采样协议为：两路真实图像各 128×128，固定拼接为 128×256 的 WAN 输入；当前帧加未来 4 帧，分别对应动作步 0、2、4、6、8；动作块预测和正常执行长度均为 8。协议改变须重新做暖启动和基线，禁止仅为了通过内存门槛而静默裁剪输入。

## 3. 研究假设与对照

**H1：**在相同初始权重、任务反馈和环境交互预算下，联合更新 VLM/video/action 比 action＋understanding 连接参数基线更能提高未见初态成功率。

**H2：**联合更新的收益没有以明显破坏世界预测为代价。成功率提升但 held-out video 指标退化时，只能报告控制收益与表征退化，不能宣称世界建模能力增强。

H2的首版操作指标为固定held-out完整clip上、仅在未来预测位置计算的video latent velocity MSE，排除当前观测条件帧及padding。动作输入使用held-out真实动作加固定噪声；观测/VLM条件、两路噪声/时间和mask对所有checkpoint一致，不使用各模型自行生成的动作。同一clip使用四组预先冻结的噪声/时间，先按有效维度和episode内平均，再按episode等权平均。逐训练seed计算D/A的MSE比值；比值≤1.10表示该固定指标处于预设可接受退化范围，超过则该seed不支持H2。另报action velocity MSE和按held-out episode重采样的区间；三训练seeds不作普遍无退化结论。全部评估输入清单在首次RL前冻结。

| 实验臂 | RL 更新范围 | 共享设置 |
|---|---|---|
| A | 全部冻结，使用同一随机采样器 | 同一 SFT checkpoint、观测、采样步骤与噪声、环境和评估初态 |
| B | action＋understanding 连接参数 | 不删去 video/VLM forward；参数白名单固定 |
| C | B＋VLM 内部 LoRA | 与 B 相同交互预算、baseline规则；优化次数按实际episode长度据实报告 |
| D | C＋video/WAN 指定 LoRA | 主方案；三模块均受 task-RL 更新 |

原始确定性采样器仅作采样退化诊断，不冒充 A。第一版验收分为“工程正确性”和“效果证据”，D 不优于 B/C 也应作为完整实验结果报告。

## 4. 预算与统计口径

- 工程烟测：1个训练seed，32条训练episode完成一次更新，另加1条更新后验证rollout检查新policy版本（不参与优化、成本单列），合计最多33条；不得据此声称RL收益。
- 探索性对照：B/C/D各3个训练seeds，每seed每臂硬上限 **25,600个实际物理交互步**，包含中断/丢弃成本；A不训练。预算尾部未完成episode标记 `budget_truncated`，不当作200步任务失败、不用于Monte Carlo更新；最后一批只用完整episode。分别报告raw attempted steps与valid training steps。基础设施错误丢弃步数超过预算5%则停止该run，修复后新run的失败历史和成本不得抹去。
- 评估：每臂每个匹配 seed 使用 100 个预先冻结的未见初始化状态，共 **4×3×100＝1,200 次评估 episode**。训练、dev 与评估的初态及衍生轨迹分组隔离。没有 100 个合法独立初态时，先生成并验证新的初态清单；不能把同一初态换随机数后写成 100 个未见初态。
- 训练计数合计为 **3×3×25,600＝230,400 个物理步**，不包括 SFT、调参/dev、烟测和评估；分别记账。每 episode 上限 200 个控制步，因此评估上界为 240,000 个物理步，实际可因成功提前结束而减少。
- 每个训练 seed 独立报告成功率，比较时按相同评估初态配对，并保留训练 seed 层级。三 seeds 只能支持探索性结论；不能把 300 个 episode 当作 300 次独立训练。
- 若episode大多跑满200步，每run的25,600步仅约128集、4次更新；该首轮预算用于工程成本和初步趋势，不承诺收敛，未见收益也不能据此排除联合RL。后续确认实验须依据实测吞吐和更新曲线另外冻结更大的步数预算。
- 工程验收不要求 D 必须获胜。若要宣称联合方法收益，后续确认实验至少 5 个训练 seeds，并在运行前固定最小有意义提升为 10 个百分点及配对/分层区间规则；本轮不据小幅均值领先作普遍结论。

## 5. 分阶段验收与停止条件

| 门槛 | 核心证据 | 失败时处理 |
|---|---|---|
| G0 环境与资源 | 分配卡号、驱动/容器兼容、软件 lock、CPU OSMesa、权重 revision | 不升级原服务或主机驱动来绕过；登记阻断 |
| G1 NPU 算子与数值 | attention、mask、RoPE、BF16/FP32 前反向；固定容差的 CPU 小张量参考 | 修复算子/精度路径，不能用前向成功替代 |
| G2 接口与 SFT | 7D 动作/独立 state 归一化、同步视频、显式权重迁移清单；dev 有非零成功率 | 修数据或控制语义，不能将失败归因 RL |
| G3 联合策略梯度 | 同参数路径重放、纯 RL 三模块梯度、玩具梯度验证、冻结负对照 | 不进行效果实验 |
| G4 NPU 完整更新 | 指定参数更新、FSDP 同步、峰值与恢复、零优势不更新 | 修分布式/优化器/资源问题 |
| G5 闭环烟测 | 新 episode 的 rollout→replay→update→下一版本 rollout | 只报告工程状态 |
| G6 四臂比较 | 固定 seeds/初态/预算、完整失败留痕、效果与世界预测并报 | 按实际结果回答 H1/H2 |

数值容差必须在正式RL之前，通过固定小张量参考与NPU重复运行校准并写入协议；达到容差上限仍失败则阻断，不按结果临时放宽。零优势测试关闭辅助损失和weight decay；全批advantage精确为零时跳过optimizer/scheduler step，检查参数与step计数不变，另用fresh optimizer检查零梯度，避免Adam历史动量造成误判。

## 6. 资源与边界

Motus文档的四模块参数近似合计8.025B，BF16计算权重约14.95GiB。首版FSDP候选的canonical参数统一FP32，均摊前约29.90GiB，计算时另有BF16权重；两者用途不同。以上均未包含所有冻结编码器、训练状态、激活和通信。910B3上完整联合更新峰值必须实测。

执行次序为：1 卡小张量算子检查 → 2 卡完整模型最小 microbatch → 必要时 4/8 卡。采用同卡分时 rollout/update，旧 log-prob 随轨迹保存，第一版不常驻第二份旧模型或 KL reference。保留视频递推梯度，使用 activation checkpointing 降低激活占用；不得通过 detach 改变联合目标。

首版不迁移物理仿真到 NPU，不做从零大规模预训练，不做真机部署，不读取或复用受保护会话，不推送公开仓库，不启动任何训练。本方案的下一步产物应是通过门槛的实现与证据；执行授权单独发生。
