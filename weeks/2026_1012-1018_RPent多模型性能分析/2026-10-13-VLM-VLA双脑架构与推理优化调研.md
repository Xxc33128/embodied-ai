## 0. 系统理解、证据规则与结论边界

### 0.1 系统理解

当前研究对象是单机器人、串行 episode 的 RPent 操作栈：云端 VLM 通过 OpenAI-compatible API 规划、诊断和调用工具；π0.5 在昇腾 NPU 上执行局部控制，SAM3/Molmo 提供感知。已讨论的模型包括 GPT-6 Astra、GPT-6 Sol、DeepSeek-V4.1-Flash 和 GLM-5.3，但各批计时与结果不能跨模型合并。〔范围确认／E3；项目背景与既有报告转引〕

两场景分别为 t0“双罐入篮”和 t9“杯子入微波炉并关门”；场景目标以环境定义为准，不以模型自报 finish 为准。[场景目标证据][R4]〔实测〕

用户已澄清两点：目前只有实际运行的**仿真日志**，没有独立物理机器人数据；“无 VLA”对照重点是**保留 VLM、移除 VLA，改用传统动作原语**。纯 VLA 组另行保留，用于识别 VLM 的贡献。〔范围确认／E3；不是实验结果〕

尚未核实的系统假设：

- 等待云 VLM 时，当前仿真是否持续推进；这决定异步执行能隐藏多少等待。〔推断／未核实〕
- 本地代理模型现选择 Qwen3.8-27B BF16，结构与原生上下文依据已补入 [32 次执行方案](2026-10-13-910B3本地VLM首批32次推理基线执行方案.md)；910B3 上完整多图兼容、实际可运行长度及质量仍待验证。API 兼容不代表能获得原云模型权重。〔文献与推断／E3；本机部署未核实〕
- “1–4B”是指语言骨干的名义规模，还是包含 vision encoder 的总参数；本文按严格总参数预算讨论，并标出超预算案例。〔推断〕
- 感知各组件的具体部署位置、调用频率与资源隔离方式，需在共置实验前冻结。〔推断／未核实〕

## 1. Q1：推理时间如何指导芯片设计

### 1.1 负载到硬件属性

现有负载更直接支持研究长上下文的有效访存、小 batch 完整决策延迟、缓存复用与控制资源隔离，不能直接推算需要多少 TFLOPS 或几张卡。〔推断〕

| 负载 | 对硬件／系统的需求〔推断〕 | 应实测的量 |
|---|---|---|
| 长上下文 decode，TPOT 随上下文上升 | 权重与 KV 的 HBM 带宽；KV 容量；长序列 attention；跨卡通信 | batch=1、固定输出长度的 TPOT、HBM 流量、attention 时延 |
| 重复多模态图像 | CPU 解码／缩放、vision encoder、视觉 token prefill；分层缓存 | processor、encoder、LM prefill 各自时延和 cache hit |
| TTFT 拟合截距 7.04 秒及同体请求波动 | 连接、队列、编排、host/device 调度、首段输出机制 | 请求与服务分段、完整 tool-call 延迟分布 |
| 每集几十次串行工具循环 | 短 burst 调度、低 launch overhead、快速上下文恢复、小 batch 效率 | 工具返回后的恢复延迟、完整决策 p50/p95，而非只有持续吞吐 |
| 未来 VLM 与 VLA／感知共置 | HBM 驻留、带宽争用、优先级与资源隔离 | 控制 deadline miss、抖动、峰值内存、并发退化 |

小 batch Transformer decode 经常受到权重和 KV 搬运限制；prefill 通常有更高计算强度，但 attention 的 IO 与实现仍然重要。[Transformer inference 分析][W1]、[FlashAttention][W2]〔文献〕

分别对 processor、vision encoder、prefill、decode 建模：

$$
T_{\mathrm{stage}}\gtrsim
\max\left(\frac{F}{C_{\mathrm{eff}}},\frac{Q_{\mathrm{HBM}}}{B_{\mathrm{eff}}}\right)
+T_{\mathrm{launch}}+T_{\mathrm{comm,nonoverlap}}.
$$

其中有效算力和带宽来自目标 dtype、shape 与算子的实测，不使用厂家峰值代替 batch=1 性能；该式是条件下界模型，不是完整延迟预测。〔推断〕

### 1.2 KV 容量、层次与图像复用

标准全上下文 attention、未压缩 KV 的容量预算为：

$$
M_{\mathrm{KV}}=
2L\,S\,n_{\mathrm{KV}}\,d_{\mathrm{head}}\,b_{\mathrm{KV}}\,B.
$$

这里使用 KV heads，而非 query heads；MLA、滑窗、稀疏 attention、KV 量化及元数据开销需另算。〔推断；参数化模型〕

**假设演算，不是云模型结构实证：**32 层、8 个 KV heads、head dimension=128、BF16 KV、batch=1，则 50k token 约需 6.55 GB，230k 约需 30.15 GB。若再假设 8B BF16 权重，长上下文下权重与 KV 合计约 46.15 GB，尚未包含 vision encoder、activation 与 workspace。此处 GB 为十进制单位。〔推断〕

片上 SRAM 用于算子 tile 与短期复用，HBM 保存活跃权重和 KV，主机 DDR 可存较冷数据；DDR／SSD 扩容需要付出回迁成本。〔推断〕PagedAttention 能减少 KV 分配浪费并支持共享，但不会消除模型必需的数据量。[PagedAttention][W3]〔文献〕

重复图像涉及三个独立缓存：文件／传输缓存、vision embedding 缓存、LM prefix KV 缓存。相同图片不保证相同前缀位置；模板、历史顺序与模型身份改变会影响 KV 复用，新相机帧也不能无条件复用旧视觉结果。〔推断〕

背景给定载荷与有效速率下，5.9 MB÷1.80 MB/s≈3.28 秒，只是传输量级估算。它可能已包含在 TTFT 中，不能再次相加，也不能从 7.04 秒截距中精确扣出纯计算时间。同请求体 TTFT 波动也不能单独归因于 HBM 或计算核心不足。〔推断；基于背景实测摘要〕

### 1.4 下一步最小实验

按同日澄清后的固定计算负载目标，采用 [硬件专题 H1–H4](2026-10-13-具身VLM推理的芯片加速单元与验证路径.md#7-下一步最小实验清单)：冻结两场景×两 seeds×早／晚阶段的 8 个请求，原实现冷路径／优化实现冷路径／优化实现精确缓存热路径各重复 4 次，形成 **96 次等长生成并核对实际 token IDs**；另加两实现各 8 次自由生成，共 **112 次计时推理**，预热和缓存填充另计。〔推断〕

第一步执行 [Qwen3.8-27B 首批 32 次基线方案](2026-10-13-910B3本地VLM首批32次推理基线执行方案.md)，这是上述 96 次的原实现冷路径组。标准 chat API 不等于强制 token replay，序列不一致的结果不能作严格同序列对照；严格重放另建增量 forward harness。〔推断〕

先定位 vision encoder、prefill、decode 的热点，再抽取实际 shape 对照 GEMV、attention、归约和 DMA 数据路径；Qwen3.8 的 Gated DeltaNet 层另行统计。入选实现再做 20 集独占＋20 集共置回归；这些是筛选预算，不足以证明 p99 或成功率非劣。该方案替代 v1.0 的 80 次通用请求扫描，不叠加预算。〔推断〕

## 2. Q2：双脑架构优越性的证明路径

### 2.1 要证明的命题

现有 Astra／Sol 比较是在同一双脑框架中更换上层模型，没有检验 VLA 或 VLM 是否必要。[120 集结果][R1]〔实测〕

应分开检验四个命题：加入 VLA 是否优于 VLM＋传统控制；加入 VLM 是否优于 VLA＋本地规则；事件触发是否优于固定降频；将同样投入用于 VLA 微调能否获得相同收益。〔推断〕

### 2.2 消融矩阵与每格数量

以下为〔推断：实验设计〕。筛选阶段每组 **32 集＝两场景各 16 个独立初态**；确认阶段先预算每组 **160 集＝两场景各 80 个新初态**。每阶段一半正常条件、一半预定义扰动；每个初态只分配一种条件，各方法共享相同的初态—条件配对。pilot、调参和确认集互斥；已有 seed0/1 的重复不能充作新的独立初态。

| 组 | 架构与控制变量 | 集数：筛选→确认 | 主要比较与区分指标 | 最可能的混淆 |
|---|---|---:|---|---|
| A：移除 VLA | VLM＋传统动作原语；保留感知与高层规划 | 32→160 | 对比 D：抓取／接触成功、恢复、总任务成功与成本 | 脚本成熟度、技能 API 表达能力 |
| B：移除 VLM | VLA 直接接任务；必要时使用冻结状态机 | 32→160 | 对比 D：长任务完成、对象选择、语义恢复 | checkpoint 是否支持完整任务 |
| C：规则基线 | 状态机＋本地进展监测＋VLA，无云调用 | 32→160 | 对比 E：超出固定规则的恢复增益 | 规则含人工答案或隐藏状态 |
| D：当前双脑 | 每个既定决策边界调用 VLM＋VLA | 32→160 | 主参照：成功率、成本、完成时间曲线 | 工具轮数、重试、云端时变 |
| E：事件触发 | 正常执行交给本地；异常／歧义时调用 VLM | 32→160 | 对比 C/D/F：恢复率、触发价值、调用数 | 漏检、监测成本、阈值过拟合 |
| F：固定降频 | 每 k 个检查点调用；保留共同急停机制 | 32→160 | 对比 E：选对时机相对单纯少调用的收益 | 实际调用预算不匹配 |
| G：成本匹配微调 | 相同预算用于 VLA 数据、微调与验证 | 每训练 seed 32→160，建议 3 seeds | 对比 D/E：训练替代收益与摊销成本 | 数据泄漏、训练随机性、预算口径 |

A／D 提供语义一致的技能接口，如同样的 pick(object)，只替换低层实现；感知输入、动作限幅、成功反馈一致。否则差异不能全部归给 VLA。若某个传统技能尚未实现，应明确记录实现缺口，不用不完整基线支持架构优越性。〔推断〕

若 checkpoint 只支持原子子任务，B 应命名为“固定状态机＋VLA”，不能以复杂指令适配失败代表纯 VLA 的能力上限。E／F 应匹配实际 VLM 调用预算，避免把额外云计算当成事件选择优势。〔推断〕

扰动按预先规定、与方法无关的环境事件注入，不按固定墙钟秒数；同时规定未达到触发事件的 episode 如何计分。若官方初态资产不足，应从声明的合法分布采样并保存完整状态，不能仅换随机种子名称重复同一初态。〔推断〕

### 2.3 本地监测与混淆控制

[“GPT 何时介入”][R5]提出阶段目标、前置条件、预期效果与实际进展的本地检查；该文将其明确列为待验证设计。〔E3：本地设计文档转引，未验证〕

沿用这一思路：对象错误和阶段前提失效时进入本地中止／重新判断；短暂无进展先重观测或本地恢复，超过阶段校准窗口再请求 VLM；释放物体等难撤销动作前检查条件。不能用机械臂移动或模型自报信心代替任务效果。〔推断〕

各组使用相同可观测信息。仿真 ground truth 用于评测和离线标签，不能仅向某组在线决策开放；本地监测成本也需计入。随机交错执行方法，以减轻云服务时段混杂。〔推断〕

G 的成本匹配预先列明数据收集、标注／脚本开发、调参、训练计算，以及按多少部署 episodes 摊销；另报边际推理成本。三个训练 seeds 分别报告，按初态与训练 seed 的交叉层级分析，不能合并成 480 个独立初态。〔推断〕

### 2.4 指标、功效与结论强度

主指标采用固定 wall-clock 截止时间下的任务累计成功比例：

$$
P(\text{success by }t).
$$

同时报告固定仿真步预算成功率，分离策略质量与等待代价。终止失败保留为失败，不能作为普通右删失来夸大完成概率。〔推断〕

辅助指标包括官方目标合取成功、阶段完成率、恢复成功率、错误对象操作、无进展时长、全部 attempts 成本、云调用／token、控制步数、总成本÷成功数。共同成功样本耗时只作补充，不能作为唯一效率证据。〔推断〕

配对二元比较的样本量依赖两方法的结果不一致率。[McNemar 功效分析][W4]〔文献〕若不一致率 q=20%–40%，双侧 α=0.05、power=80%，用未作连续性校正的正态近似：

$$
n\approx
\frac{(1.96\sqrt q+0.842\sqrt{q-d^2})^2}{d^2}.
$$

| 目标成功率差 d | 近似所需配对数〔推断：功效演算〕 |
|---|---:|
| 15 个百分点 | 68–138 |
| 10 个百分点 | 155–312 |
| 5 个百分点 | 626–1254 |

这些数值未计多重比较、子组分析和额外相关性，不保证每场景／扰动子组都有功效。160 集仅是确认阶段起始预算；正式数量按 pilot 的 q、目标效应与检验结构重算。预注册 A／D 为主比较，其他比较采用层级检验或多重校正。识别优势的功效不等于证明 5 个百分点非劣界的功效。〔推断〕

需要自适应停止时，可参考有统计保证的序贯政策比较框架；不能看到显著就任意停止或不断追加样本。[STEP，RSS 2025][W5]〔文献／推断〕

### 2.5 下一步最小实验

先完成 **A 与 D 各 32 集，共 64 集**，直接检验移除 VLA 的影响。同时从 t0/t9 各选 5 个困难状态，分别执行继续原策略、本地恢复、请求 VLM，形成 **30 条短分支**，诊断高层调用价值。〔推断〕

分叉应恢复物理状态、随机数、观测历史、控制器状态、action chunk 和相关规划状态；无法完整恢复时，短分支只作机制诊断。主比较若失败类型主要源自基线技能未实现，先修复实验接口，不能据此宣称架构优势。〔推断〕

## 3. Q3：中等模型学习空间推理

### 3.1 文献路线与参数规模

先学习可核验的对象、参考系、空间关系和子目标，再增加后果预测与恢复，是比直接模仿长篇解释更可诊断的研究起点。〔推断〕

### 3.2 三元组能否形成差异化贡献

仅对“图像、可见解释、结果”做 SFT，不能凭三元组形式主张新方法。更有判别力的命题是：**执行结果校验过的空间监督，能否让小模型在固定 π0.5 下，比普通 teacher 模仿更可靠，并减少云调用？**〔推断〕

当前是仿真日志，可利用对象几何、状态转移与重放建立标签、比较替代子目标。建议至少补齐：

$$
(\text{task},o_t,\text{proposed subgoal},\text{executed action},
o_{t+\Delta},\text{local outcome},\text{terminal outcome},\text{failure type}).
$$

缺少实际动作和局部结果，就难以区分空间判断错误与低层抓取失败；整集成功不保证每一步正确，整集失败也不能把全部决策作为负例。〔推断〕

可见解释不保证忠实反映决策过程，已有偏置和干预研究展示了这种不一致。[可见解释偏差研究][S11]、[CoT faithfulness 研究][S12]〔文献〕因此将其视为待核验监督候选，抽取对象、数量、坐标系、关系和计划，与观测及后果核对；不声称蒸馏了真实内部思考。〔推断〕

值得逐项验证的贡献包括：结果校验是否优于仅按 teacher 输出格式筛选；结构化空间证据是否优于同预算自由解释；失败恢复是否提供额外泛化；固定执行器后，学生是否改善闭环成功率和云替代率。〔推断〕

### 3.3 数据与部署风险

- 同初态不同 teacher、同 seed 重跑和近邻帧必须在同一 split；不能逐帧随机切分。帧多不等于独立状态多。〔推断〕
- 未来图像和最终结果可用于离线标签，不能进入学生决策时的输入。仿真真值可作标签，不自动成为在线输入。〔推断〕
- 固定 π0.5、技能参数、action horizon 与 fallback 规则；分别统计规划、感知、控制和 API／超时失败。〔推断〕
- 加入未见物体、布局、相机，以及盲图／打乱解释对照，检查是否只学模板。两场景适合 pilot，不能证明通用空间智能或真机迁移。〔推断〕
- 保留失败恢复，但未经纠正的失败动作不能直接作为正向 SFT；整集结果不足以支持逐动作归因。〔推断〕
- 昇腾算子兼容、峰值内存、图像前处理与真实低延迟尚待测，参数小不保证端到端快。〔推断／未核实〕

权重许可须单独核对。例如 Qwen2.5-VL-3B 当前官方许可证为 Qwen Research，包含非商业限制；衍生模型卡标签不能自动替代上游条款。[官方 LICENSE][S13]〔文献〕云 API 输出用于训练和再分发的权限则取决于供应商合同，当前未核实。〔未核实〕

### 3.4 下一步最小实验

固定一个约 2B 学生，可从 [Qwen3-VL-2B][S14] 开始验证；冻结 π0.5、调用频率、输入尺寸和 fallback 规则，比较四组：原始学生；图像／任务→正确子目标 SFT；同数据加原始可见解释；同数据改用校验后的结构化空间证据与局部结果。匹配样本、训练 token 与更新预算。〔推断〕

先做独立空间 QA／point error，再每场景 10 个新初态闭环筛选。原始学生评测 20 集，三种微调配置各做 3 个训练 seeds、每实例 20 集，共 **20＋3×3×20＝200 集**；同一初态重复评测按配对／层级数据处理，不能称 200 个独立初态。原始学生基线可共享，采样设置须冻结。〔推断〕

若结构化结果校验组不能优于普通子目标 SFT 和自由解释组，就不能支持该差异化贡献。课程学习随后单独加组，RLVR 再后置；各组同时报告空间错误、闭环成功、云调用、输出 token、NPU 时延和内存。〔推断〕

## 4. Q4：VLM／VLA 异频调度

### 4.1 文献启发与接口边界

| 工作 | 已核实机制〔文献〕 | 对本栈的边界〔推断〕 |
|---|---|---|
| [Helix][A1] | S2 约 7–9 Hz、S1 200 Hz；独立进程／GPU 异步运行，并在训练中考虑时延 | 多速率结构可借鉴，频率不能直接移植到十秒级云 API |
| [Hi Robot][A2] | 高层输出原子语言子任务，低层 VLA 执行；论文实现每秒或新语言反馈时重跑高层 | 更细粒度多层异步在论文中仍是后续方向，不能称已验证事件触发 |
| [RTC][A3] | 执行旧 action chunk 时生成新 chunk，处理已承诺前缀与重叠区间 | 主要处理 VLA 连续控制延迟，不直接消除云等待 |
| [DeeR-VLA][A4] | 模型内部动态早退 | 需要模型内部能力，不等于关闭 HTTP 连接 |
| [Spec-VLA][A5] | speculative action-token 起草／验证 | 机器人动作不可像 token 一样回滚 |

英文检索未定位到“YOLO-LLM”对应的早退论文，保留为**未核实引用**，不据名称补写机制；确认题名、作者或链接后再增补。〔未核实〕

以下四种调度均为〔推断：待验证设计〕。共同前提是本地控制约束优先、在合法 chunk 边界更新任务、完整可执行输出通过检查后才使用。

### 4.2 方案一：阶段契约＋事件触发

每个 subgoal 保存 goal、preconditions、expected effect、timeout、recovery。正常阶段由 VLA 执行；错对象、前提失效、局部恢复无效或任务变化时调用 VLM。

| 项目 | 设计〔推断〕 |
|---|---|
| 阈值 | 在校准集按阶段统计有效进展时间，扫 Q90/Q95/Q99；加入重观测和去抖，阈值冻结后测新 seed |
| 收益量级 | 少调用 25% 约少 11–20 次；用 TTFT 中位 10.4 秒粗估是约 114–208 秒首输出等待量级，不是平均净节省 |
| 两场景验证 | 当前策略、调用预算匹配的固定降频、事件触发，使用 t0/t9×相同初态 |
| 失败判据 | 漏检导致更晚恢复、错误阶段切换、监测成本抵消收益，或固定预算成功率下降 |

净收益应按完整请求计算：

$$
\Delta T=
\sum_{j\in\mathrm{skipped}}L_j
-T_{\mathrm{monitor}}
-T_{\mathrm{extra\ recovery}}.
$$

监测优先复用已有观测与跟踪，不能默认每帧 SAM3／Molmo 免费；也不能把 TTFT、7.04 秒截距和上传估算重复相加。〔推断〕

### 4.3 方案二：独立 actor＋latest-only 队列＋AoI 门控

低层执行与云请求分离；最多一个 in-flight 请求和一个可覆盖 pending 槽，新观测替换未发出的旧观测，避免 FIFO 积压。〔推断〕

AoI 从观测生成时间计算，而非响应到达时间。[AoI 综述][A6]〔文献〕

$$
\Delta_w=t_{\mathrm{wall}}-g_{\mathrm{obs,wall}},
\qquad
\Delta_s=t_{\mathrm{sim}}-g_{\mathrm{obs,sim}}.
$$

若等待期间仿真冻结，wall AoI 增长而 sim AoI 几乎不变，两者必须分别报告。〔推断〕

| 项目 | 设计〔推断〕 |
|---|---|
| 门限 | 延迟注入校准阶段允许的年龄与状态偏移；回复携带 episode／目标／阶段版本，执行前重新检查前置条件 |
| 上界 | 只有采样周期 P、确定性延迟上界等条件成立时，才可给出类似 Δmax≤P＋Lmax 的界；云 p95/p99 不是硬上界 |
| 执行规则 | 超龄后不继续采用旧高层指令；停车不让 AoI 归零；不要求每个 physics tick 版本完全相等 |
| 收益量级 | 每轮最多隐藏 min(Lj, Ej)；30 秒云等待只有 2 秒独立动作，就最多隐藏 2 秒 |
| 两场景验证 | 同步、异步 FIFO、latest-only＋AoI；在 t0/t9×相同 seed 注入 0/5/15 秒附加延迟 |
| 失败判据 | 陈旧回复覆盖新目标、队列增长、动作不连续、控制 deadline miss，或成功率下降 |

先确认 actor 能在云等待期间推进仿真；仅将同步函数改成 async 不产生重叠收益。AoI 门控限制旧命令继续使用，不等于证明闭环稳定或真机安全。〔推断〕

### 4.4 方案三：按阶段分配思考预算＋请求中断

常规阶段使用较低 reasoning budget，对象歧义、恢复失败或关系冲突时升级；过期请求结果作废，服务支持正式取消接口时再发送取消。〔推断〕

| 项目 | 设计〔推断〕 |
|---|---|
| 期限 | 用完整可执行结果的延迟分布和阶段余量校准 deadline，并保留恢复预算；TTFT 不是动作就绪 |
| 收益依据 | 历史 69.8% 是生成窗口内思考占比中位数，不能乘整集时间；请求减少与轨迹改变须另计 |
| 两场景验证 | 固定 medium、固定最低档、事件驱动预算；先冻结观测验证决策质量／完整 JSON，再闭环 |
| 失败判据 | 错误决策、升级／重试增加、截断无有效输出、账单与恢复成本抵消收益 |

共同成功两集关闭思考快 20.57%，同时 63→57 轮，不能解释为同轨迹纯思考时长收益。[审计说明][R3]〔实测〕

断开 stream 不代表服务端停止计算／计费，未闭合 tool JSON 和半截解释不能执行。当前黑盒接口下，可做的是完整决策边界重观测，或作废后重新请求；token 级环境在环解码需要服务端额外能力。〔推断／取消语义未核实〕

本地开权重服务可第二阶段实验“生成中检测环境变化→中断→以新观测重新编码”，测浪费 token 与陈旧决策减少量；不能将其写成云 API 已有能力。〔推断〕

### 4.5 方案四：VLA 有限前缀执行＋VLM 异步校验

在已确认 subgoal 内，VLA 先执行有限且可恢复的动作前缀，VLM 后台检查对象、阶段与效果。先 shadow mode 记录是否会否决，再逐步放行。

$$
\mathbb E[\Delta T]\approx
\mathbb E[\min(L,W)]
-\Pr(\mathrm{reject})C_{\mathrm{recovery}}
-C_{\mathrm{monitor/verify}}.
$$

| 项目 | 设计〔推断〕 |
|---|---|
| 阈值 | 从 0/1/2 个 chunk 起扫；释放、不可逆接触等阶段设为 0；用否决率、错误执行距离和恢复成本选择 |
| 收益量级 | 云验证 30 秒、允许前缀 1 秒，最多隐藏 1 秒；总在动作完成后到达的验证只是事后审计 |
| 两场景验证 | 同步验证、shadow、有限前缀；t0/t9×相同 seed，保持共同低层约束 |
| 失败判据 | 否决到达已越过恢复边界、错误前缀增加、恢复成本超过隐藏等待 |

物理动作不能像 token 回滚；仿真 reset 也不代表未来真机拥有回滚能力。该系统设计不等于直接复现模型内部的 speculative decoding。[Spec-VLA][A5]〔文献／推断〕

### 4.6 下一步最小实验

先补统一 trace：观测产生、请求发送、首 delta、完整动作结果、动作提交、chunk 结束和仿真推进，带 wall/sim 时间与语义版本。确认计时、状态隔离和 chunk 切换门禁后，每个方案固定一个保守配置，再运行 **（基线 1 组＋方案 4 组）×2 场景×5 个新初态＝50 集**，随机交错执行。〔推断〕

这是筛选规模；比较固定预算成功率、完成时间、完整决策延迟、AoI、过期丢弃、恢复次数与总成本。版本错配动作直接判实现失败；未通过并发／中止门禁的方案先保留 shadow，不为凑样本放行动作。成功率非劣性需按 Q2 重新计算确认预算。〔推断〕

| **Q1 硬件瓶颈** | **先做 [32 次本地基线](2026-10-13-910B3本地VLM首批32次推理基线执行方案.md)**；完整 H1 为 **112 次计时推理**＝96 次等长生成／序列核查＋16 次自由生成；之后热点 kernel 与硬件反事实；入选实现 **40 集**独占／共置回归，见 [硬件专题 §7](2026-10-13-具身VLM推理的芯片加速单元与验证路径.md#7-下一步最小实验清单) | 同权重、dtype、batch=1、必需图像／文本；分阶段 trace、cache hit、HBM、完整结果延迟 | 区分已有单元未用好与真正资源限制；少量重复不支持 p99 或采购加速比承诺 |
