# EmbodiedEvo 分析与 RPent 经验复用实验建议

版本：v1.0 · 日期：2026-10-15

分析对象：[EmbodiedEvo: Self-Evolving Coding Agent For Physical Intelligence][P1]，论文固定 arXiv:2610.18867v2；公开源码固定提交 `470278c478bdb5e4b6f17dde1ea0393761f230f0`。关注经验如何积累、冻结与迁移，以及与 COAP、GPT-as-Policy、RPent 的区别。

近期建议保留 RPent 的 π0.5、感知与伺服工具，借鉴 EmbodiedEvo 的 Skills／Lessons 表示、适用条件和证据状态，先检验经验复用是否改善 t0 抓持与 t9 阶段衔接。该路线与减少高层调用、替换动作模型或芯片加速属于不同实验因素。〔E3：本文判断〕

关联：[本周索引](readme.md) · [COAP 分析与实验建议][R1] · [EmbodiedJev 对比][R2] · [两场景深测][R3] · [DeepSeek 性能审计][R4]。

## 1 方法与证据范围

EmbodiedEvo 在 Playground 中探索、修改和执行程序，将可复用操作保存为 Skills，将适用条件、失败迹象及恢复指导保存为 Lessons。Test 继承冻结经验，但仍由在线 Agent 根据反馈编写、执行和修正当前场景的程序；模型权重不更新。〔E3：[P1] §3；[项目说明][P2]〕

| 材料 | 可支持的结论 | 等级与边界 |
|---|---|---|
| 论文 v2、项目主页 | 作者方法、评测及成本记载 | E3；未独立复现成绩 |
| 固定提交的执行、冻结与 recipe 源码，以及 task 配置 | 具体机制及配置入口 | E1／E2；代码存在不证明性能收益或历史部署一致 |
| Skills／Lessons 模板、源码范围说明 | 经验格式与公开交付范围 | E3；模板不是已验证技能或经验 |
| 既有 RPent 脱敏报告 | t0／t9 问题线索及历史验收范围 | 本文按 E3 转引，保留来源原有 E2／验收口径 |
| 本文实验建议 | 对照、指标与实施顺序 | E3；未修改执行栈或启动新实验 |

沿用工作区 E1–E4：E1 为源码行号实证，E2 为配置实证，E3 为文档记载或逻辑推断，E4 为外审转述未复核。公开代码核查只覆盖本报告引用的机制；不把静态检查写成完整运行验收。〔E3：[证据定义][EV] §3〕

## 2 在线适配与跨场景经验

### 2.1 Playground 和 Test 的分工

| 阶段 | 当前场景内允许什么 | 跨阶段或跨场景携带什么 |
|---|---|---|
| Playground | 观察、修改程序、执行、重置同一场景 | 结束时冻结 Skills／Lessons |
| Test | 观察、复用经验、在线修改当前程序和恢复 | 每场景全新 Agent、工作区和模拟器；禁止 reset 与跨 Test 经验更新 |

表内阶段协议为 E3：[协议说明][D1]。源码的冻结路径只复制 `skills/` 和 `lessons/` 并记录哈希；Test 将这两项只读挂载。宿主 session 与程序执行层分别检查 reset 的阶段权限。〔E1：[S1] 第 181–196、674–680 行；[S2] 第 213–214 行；[S3] 第 47–50 行〕

“经验库冻结”和“策略程序冻结”必须分开。当前场景的 Python 定义和变量在提交之间保留，Agent 可以改写下一段程序；新 episode 才清空执行命名空间。代码异常不会回滚此前物理动作。〔E1：[S3] 第 32–43、93–119 行；E3：[D1] Persistent code sessions〕

这使 EmbodiedEvo 同时包含两种适配：当前场景内的反馈修正，以及探索经验对后续场景的帮助。实验需隔离这两者，不能把一次 Test 中的调试效果全部归为跨场景进化。〔E3：机制分析〕

### 2.2 Skills 与 Lessons 保存的内容

| 经验 | 建议内容 | 解释范围 |
|---|---|---|
| Skills | 目标、机器人与动作模式、参数、坐标和单位、前置／停止条件、执行证据、已知失败 | 参数化操作程序；是否适用当前场景仍需判断 |
| Lessons | Signature、Instead、Evidence、Status | 观察到什么、下一次如何调整、依据在哪里、结论有多强 |

上述为仓库模板记载 E3：[T1]、[T2]。Lessons 的状态包括 `verified / scene-specific / hypothesis`；其中 verified 只表示在当前 Playground 场景中复现过，不证明跨场景有效。

对本工作区，状态应进一步区分“开发场景复现”与“留出场景验证”，避免将局部经验当成普适规则。比如“目标没有随夹爪抬升”属于观察，“接近高度错误”可能仍是解释；二者分别记录。〔E3：迁移建议〕

## 3 与 COAP 和现有路线的区别

| 路线 | 在线主要决策 | 动作生成或执行 | 跨场景复用 |
|---|---|---|---|
| GPT-as-Policy Direct／Agentic | GPT 根据观测决定短段动作 | 末端目标与数值控制 | 模型能力、提示；Agentic 保留同集历史 |
| GPT-as-Policy Hybrid | GPT 审查学生候选，必要时修正或接管 | π0.5 候选及短段修正 | 学生策略与审查规则 |
| RPent 普通模式 | LLM 编排定位、接触、搬运、恢复等工具 | VLA 接触技能和解析原语 | 任务记忆、全局规则与工具 |
| RPent Flash Mode | 预定流程、锚点重绑定与有限恢复 | 视觉模型、VLA 和解析原语 | task card 与预定检查 |
| COAP | 冻结程序根据显式状态闭环决策 | 程序化感知、规划与控制 | 可执行共享库 |
| EmbodiedEvo | 在线 Agent 读取经验并编写、执行、修正程序 | 原生动作接口与程序组合 | 冻结 Skills／Lessons |

GPT-as-Policy 与 RPent 的实现锚点及证据边界见 [R1] §3–§4；本文对这些材料按 E3 转引，不重新声明活动部署状态。EmbodiedEvo 在线程序执行机制为 E1：[S3]；其方法与 COAP 的比较为 E3：[P1] §3、[C1] §3。

### 3.1 EmbodiedEvo 与 COAP

两者均将代码作为经验载体，但 Test 中决策者不同。EmbodiedEvo 保留在线 Agent，不能据此获得免模型决策等待的性质。COAP 的严格无模型执行条件见 [R1]；将 EmbodiedEvo 的经验格式接到 RPent，不等于实现 COAP。〔E3：比较判断〕

信息条件也不同。EmbodiedEvo 的公开原语手册未开放深度和相机标定，没有现成 grasp 原语；COAP 使用已知几何先验。不能把两者的成绩差值单独归为“在线 Agent 和离线代码谁更强”。〔E3：[T3] 第 18–26、65–75 行；[R1] §2；归因边界〕

### 3.2 EmbodiedEvo 与 GPT-as-Policy

共同点是 Agent 在线看反馈、决定控制并恢复。EmbodiedEvo 额外安排独立 Playground，将操作和诊断经验冻结给新的执行者；程序可组合多次原生动作，而不是只按固定短段输出协议生成下一动作。因此，若与 GPT-as-Policy 对照，需要固定观测、动作语义、预算与已有知识，再改变经验条件。〔E3：[P1] §3、[D1]；实验判断〕

### 3.3 EmbodiedEvo 与 RPent

RPent 已有记忆、局部 π0.5 闭环及手写控制，迁移重点是经验的结构和证据，而非重新实现一套底层控制。保留这些组件能检验：经验是否改善技能选择、前置条件判断和失败恢复，收益是否覆盖读取经验的成本。〔E3：[R1] §3、[R2] §3–§5；迁移判断〕

Flash 可提供固定流程的整体系统对照。EmbodiedEvo 风格的在线适配、Flash 的有限分支与 COAP 的完整程序策略，属于不同自主程度；比较时分别计量规划、感知和动作模型调用。〔E3：设计判断；[R1] §4〕

## 4 成绩与成本口径

作者全量评测为 42 任务各 50 场景，共 2,100 集，报告类别均衡平均 SR 为 37.82%；不能视为全部 episode 直接相除的微平均。主要配对分析使用每任务 5 场景的开发集。论文 §4.1 中 Sol／Luna 分别写为 GPT-5.6-sol／GPT-5.6-luna，不能自动替换为我们评测的 GPT-6 Sol。〔E3：[P1] §4.1–§4.2、附录 B〕

| 经验条件 | 类别均衡 SR | 每集 Test 费用 |
|---|---:|---:|
| No Experience | 8.50% | $4.058 |
| Raw History | 29.78% | $12.203 |
| Skills／Lessons | 30.17% | $5.732 |

表内为作者配对开发集结果，含失败，排除 Playground 经验获取费用。Skills／Lessons 相对 Raw History 省 53.0%，相对无经验却贵约 41.3%；总 token 仅省约 11.3%。费用含缓存计价影响，属于固定费率估算而非账单；相近成功率不构成正式等价性证明。〔E3：[P1] §4.5–§4.6、附录 E；百分比复算〕

项目结果显示 Memory SR 为 69.67%，Precision 为 13.25%。其排行榜对照固定于 10 月 9 日快照，不能解释为后来全部方法的实时排名。〔E3：[P2] Results〕

对我们而言，这些数据支持“结构化经验比原始历史更经济”这一研究问题，而不支持“经验进化使总费用减半”“延迟减半”或“高精度接触已解决”。原始历史压缩、缓存变化与执行策略变化需要分别测量。〔E3：分析〕

### 4.1 我们应采用的费用账本

以下为 E3 验收设计。

| 成本 | 应包含什么 | 不应如何解释 |
|---|---|---|
| 获取经验 | Playground 模型、仿真、失败尝试与验证 | 不因最终得到可用技能就抹去失败成本 |
| 在线执行 | 全部 Test 集的模型、感知、VLA、控制与通信成本 | 不只保留成功集 |
| token | 普通输入、缓存写入、缓存读取、输出；reasoning 为输出子集 | 累计输入不是单次上下文，缓存命中不是免费 |
| 时间 | 实际墙钟、调用分段及局部执行；失败与重试分列 | token 降幅不直接换算时间降幅 |

经验摊销可写为：

\[
\text{每集摊销成本}=\frac{C_{\mathrm{acquisition}}}{N}+\overline{C}_{\mathrm{Test}}.
\]

其中 N 是冻结经验实际服务的测试或部署 episode 数；公式仅作账面分析，不保证每个新场景都适用同一经验。每次成功的成本另用“全部尝试总成本／成功次数”，不能直接用类别均衡 SR 代替实际成功数计算。〔E3：计算口径〕

### 4.2 成本归因与公平性

Raw History 与 Skills／Lessons 应来自同一次冻结探索，保留相同预先提供的任务知识。读取更多信息可能改善决策，也可能增加调用与缓存流量；既要统计内容体量和缓存，也要记录是否实际调用技能、是否改变动作路径。CPU／NPU 优化、模型换档与经验表示分别设组。〔E3：实验设计〕

与前一份 Astra 报告的“成功回合平均费用”比较时，也要先对齐失败是否计入、计价快照、模型身份、场景和接口。本文不据跨报告美元数额排列系统经济性。〔E3：边界〕

### 5.2 recipes 与学到的经验分开

公开 tasks 与 baseline 均可预先提供任务 recipes；是否启用是受控输入，而不是 Agent 学到的经验。比较组必须使用相同 recipe 设置，并分别记录 recipe 哈希、探索生成的经验哈希和当前执行程序。不能把“包含公开任务知识”写成没有任何任务先验。〔E1：[S4]；E3：[D1] Playground to Test、设计边界〕

### 5.3 公开仓库不包含全部成绩产物

## 6 t0 与 t9 的迁移建议

本节为 E3 实验设计，承接 [R1] §5–§7 的抓持验收、阶段诊断与留出评测。所有组保留同一 RPent 执行栈，先改变经验表示，不同时引入新的动作模型或控制预算。

### 6.1 t0 双罐入篮

既有深测记录出现“局部 pick 未满足判据但整集成功”，也出现大量重复 pick 后失败。它们提示经验应区分物体抓持、工具返回与官方目标，不能把一个 false 直接写成“未抓住”。历史样本与数字的权威入口见 [R1] §5、[R5] `scenes[task=0]`。〔E3：既有记录转引〕

适合保留的 Skills 包括带抓持检查的抓取、搬运后的保持检查，以及带异常出口的放置程序；先复用现有 π0.5 和伺服，不另写完整机器人控制器。Lessons 记录何时应重新观察、哪些证据支持重抓、旧定位何时失效，以及什么情况下应交回高层。

| 经验条目示例 | 必须保留的证据 | 不能直接升级的结论 |
|---|---|---|
| 抬升后目标没有随夹爪运动 | 同步观测、相机和本体状态、目标关联 | 不能仅据末端抬升断言已抓住 |
| 搬运中疑似滑落 | 前后物体／夹爪关系，遮挡与相机运动处理 | 单次疑似事件不证明固定速度上限普遍有效 |
| 局部 false 后仍有任务进展 | 工具结果、后续观测与环境评分分离 | 不直接删除原判据或放宽所有阈值 |

先以 shadow 方式验证诊断，不让新 Lessons 自动触发恢复。按 episode 划分开发和验证片段，避免邻近帧跨集合；冻结阈值后再进入主动经验对照。额外稳定性条件只作工程分析，不改官方 In 目标判据。

### 6.2 t9 杯子入微波炉并关门

既有 t9 四集均失败，且没有独立保存杯子 In／门 Close 子谓词结果，因此第一项工作仍是阶段诊断。不能把反复到位调整全部归为碰撞，也不能将整任务 false 当成门动作完全无效。〔E3：[R1] §6；[R5] `scenes[task=9]`〕

失败任务可以产生局部经验，但每项需要独立证据：

| 阶段 | 可保存的 Skill／Lesson | 必须继续检查什么 |
|---|---|---|
| 抓杯 | 经过检查的接近与抬升流程 | 当前仍抓着正确杯子 |
| 送入 | 保留预算和受阻返回的搬运程序 | 杯子与炉腔的空间关系；末端移动不等于杯子进入 |
| 释放与撤手 | 有条件释放与撤离顺序 | 杯子是否随释放改变位置、手臂是否退离 |
| 关门 | 接触前置条件与门运动反馈 | 门运动、杯子位置及未知状态分别处理 |

只读经验指导当前判断，不替代当前观测。环境子谓词可用于独立评分或事后验证，不进入普通视觉策略的观察、终止器或 Lessons 查询接口。未解释的失败保持 hypothesis；不能把整任务未完成当成所有局部操作无效，也不能反过来用局部成功代替整任务成功。

## 7 最小经验表示对照

为避免与 COAP 报告中的 A–D“执行机制”组混淆，本报告使用 K0–K3 表示经验条件。它们是独立实验轴，暂不与复合技能、局部恢复的所有组合做全因子扩展。以下为 E3 设计。

| 组别 | 相对当前冻结 RPent 增加什么 | 回答的问题 |
|---|---|---|
| K0 | 无新增探索经验，保留当前基线记忆 | 新批次基线 |
| K1 | 来自开发探索的 Lessons | 适用条件与诊断是否有用 |
| K2 | 同源 Lessons 与经过验证的 Skills | 可执行技能在已有 Lessons 上的增量 |
| K3 | 同一探索的完整公开历史，替代新增 Skills／Lessons | 结构化经验相对原始历史的效果和成本 |

K0 的“无新增经验”不等于删除 RPent 已有记忆；各组共有的记忆和任务说明保持一致。K2−K1 衡量 Skills 的条件增量，不能独立证明二者不存在交互；K2−K3 比较经验表示，不能混入不同探索来源。必要时另增 Skills-only 组，但不在第一轮同时扩展。

原始历史条件只能在受控私有实验区构造，禁止读取或转存工作区受保护的既有会话目录。公开发表只保留白名单统计、哈希、脱敏经验和必要证据索引。不能将本文建议作为遍历原始日志或公开完整会话的授权。

### 7.1 冻结与留出

开发使用已指定的开发场景；不复制旧场景坐标作为通用技能参数。冻结经验文件、检索规则、提示、recipe／记忆和模型配置后，再在未用于调参、技能验收或经验筛选的初态上配对运行。每个 Test 使用独立会话和仿真，经验只读，禁止跨测试更新。

既有 t0／t9 各两个初态只作开发线索，不足以宣称泛化。原 COAP 方案的留出试点规模可作为执行预算参考，但本次换成经验条件后应另建批次与配置标签，不复用原 A–D 成绩。

### 7.2 验收指标

| 类别 | 同时报告 |
|---|---|
| 任务质量 | 官方成功、阶段诊断、抓持／进展误报与漏报、unknown 比例 |
| 经验使用 | 读取哪些条目、是否调用 Skill、前置条件是否成立、因经验产生的误操作 |
| 在线成本 | 全部集和全部 attempt 成本、逻辑请求、缓存读写、输出、感知与 VLA 调用 |
| 时间 | 全部 episode 墙钟、共同成功配对、局部恢复及预算耗尽 |
| 获取与维护 | Playground、验证、被拒经验、更新后的回归成本 |

模型造成的普通失败保留；基础设施重试另记 attempt。报告经验来源、冻结哈希和实际执行模型，不仅记录模型别名。小样本相近成功率不能写成等价或非劣性；更快失败、少 token 和更高缓存命中也不能单独写成整集收益。

### 7.3 强模型获取经验与较便宜模型执行

可在主对照完成后，让 Astra 获取并验证经验，再由 Sol 在相同冻结库和留出初态上执行。固定执行模型时比较自身经验与 Astra 经验，固定经验时再比较不同执行模型，以区分经验获取与使用能力。探索费用、模型版本和推理档位分别记录，不能引用论文 Sol／Luna 名称替代实际模型身份。此项是后续 E3 设计，不预设节省幅度或成功率。

## 8 实施顺序与结论

先明确经验条目的证据与适用条件，完成 t0 抓持诊断和 t9 阶段诊断，再冻结同源经验开展 K0–K3 对照。只有经验表示收益得到验证，才进一步组合复合技能、低频高层决策、强模型探索／弱模型执行或芯片部署优化。〔E3：顺序建议〕

EmbodiedEvo 为“将探索转化为可复用程序与诊断知识”提供了实现参考；其在线 Agent、经验获取成本和接触控制限制仍需保留。当前材料不支持总费用减半、实时控制达标、真机泛化、跨项目成功率排名或默认命令复现论文成绩。〔E3：结论边界〕
