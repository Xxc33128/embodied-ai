## 1. 最终裁决

**当前状态：N5-R 的运行工程门禁通过，但科学有效性门禁未通过；N6-R 暂停。**

这不是“armature 实验得到负结果”，也不是“MuJoCo 与 Isaac 的未知引擎机制已经被证明”。真正的问题是：本轮 Isaac 和 MuJoCo 使用的隔离模型在几何结构和关节等效惯量上严重不等价。

因此本轮结果只能支持以下结论：

1. 18 次运行全部完成，执行链路可用；
2. 当前错误资产下，运行具有逐点确定性；
3. 当前隔离约束、接触和饱和检查通过；
4. 当前数据不能估计 armature 对 Isaac–MuJoCo 差异的贡献；
5. 当前数据也不能把剩余差异归因于 frictionloss、求解器、PD 时序或其他引擎机制。

处理决定：

- 保留本包，标记为 `INVALID_FOR_CAUSAL_CONCLUSION_ASSET_MISMATCH`；
- 撤回“armature 只改善 0.17%”和“非 armature 引擎机制主导”两个科学结论；
- 不启动 N6-R；
- 新增 G0 资产等价门禁，修复隔离 URDF 后运行 N5-R2。

## 3. P0 根因：Isaac 隔离 URDF 的 root transform 被重复施加

### 3.1 错误代码位置

包内 `scripts/urdf_isolation.py` 第 112–117 行把 canonical root 世界位姿应用到了**每一个 joint 的局部 origin**：

```python
if fold_root and origin is not None:
    xyz0 = parse_vec(origin.get("xyz", "0 0 0"))
    rpy0 = parse_vec(origin.get("rpy", "0 0 0"))
    origin.set("xyz", fmt_vec(R_root @ xyz0 + t_root))
    origin.set("rpy", fmt_vec(mat_to_rpy(R_root @ rpy_to_mat(rpy0))))
```

URDF joint origin 是“父 link 到子 link”的局部变换，世界 root 位姿只能在树根应用一次。把同一个世界变换施加到每条边，会在关节链上反复累积平移和旋转。

同一脚本第 139–162 行又把 root 世界位姿写入 root link 的 inertial/visual/collision origin。正确做法应是保持 link 内部 origin 为局部量，在 Isaac 场景中只设置一次 articulation 的世界 root pose。

### 3.2 为什么包内 self-check 没发现

`self_check()` 第 207–209 行在计算“官方 URDF 的期望世界位姿”时，同样在遍历每一条 joint edge 时重复施加 root transform。也就是说：

```text
错误的模型生成方法
        与
使用同一种错误公式构造的期望值
```

两者当然可以互相吻合。脚本第 169 行甚至把远端 link 达到约 20 m 当作正常浮点误差背景，这其实正是结构错误的直接警报。

### 3.3 独立正运动学证据

不使用包内 self-check，按标准 URDF 局部变换递推，当前 Isaac 隔离模型得到：

| 项目 | elbow 隔离 URDF | hip 隔离 URDF | 正常 MuJoCo 隔离模型参考 |
|---|---:|---:|---:|
| 目标关节世界高度 z | 20.19 m | 5.03 m | elbow 1.20 m；hip 0.93 m |
| 最远 link 原点距世界原点 | 24.50 m | 24.50 m | 约 2.49 m |
| 目标关节下游最大 COM 力臂 | 5.49 m | 4.14 m | elbow 0.269 m；hip 0.764 m |

机器人并没有 20 多米高，因此这是确定的资产生成错误，不是引擎差异。

### 3.4 独立等效惯量证据

对目标关节下游每个刚体，独立计算：

```text
I_eff = Σ [aᵀ R I_com Rᵀ a + m ||a × (p_com - p_joint)||²]
```

其中 `a` 是目标关节世界轴。结果如下：

| 关节 | Isaac 隔离 URDF刚体惯量 | MuJoCo 隔离 XML刚体惯量 | 比值 |
|---|---:|---:|---:|
| right elbow pitch | 6.8321 kg·m² | 0.075245 kg·m² | 约 90.8× |
| right hip pitch | 11.9176 kg·m² | 1.039145 kg·m² | 约 11.5× |

计入 armature 后：

| 条件 | 估算总等效惯量 |
|---|---:|
| Isaac elbow，armature=0.01 | 6.8421 kg·m² |
| MJ elbow native，armature=0.0685 | 0.143745 kg·m² |
| MJ elbow matched，armature=0.01 | 0.085245 kg·m² |
| Isaac hip，armature=0.0968 | 12.0144 kg·m² |
| MJ hip，armature=0.0968 | 1.135945 kg·m² |

这个量级足以解释当前图中 Isaac 响应慢很多：

- elbow：Isaac 在 0.5 s 只到约 `0.5283 rad`，MuJoCo 到约 `0.5885–0.5905 rad`；
- hip：Isaac 的上升时间也明显慢于 MuJoCo。

所以本轮首先观察到的是“错误力臂造成的巨大刚体惯量差”，armature 从 `0.0685` 改到 `0.01` 的影响自然会被淹没。

## 4. 当前 gate 还需修正的两个问题

### 4.1 G1 没有实际检查 canonical q0

最终 JSON 中三条 trace 的 `q0_maxerr` 都是 `null`，但 G1 仍然 PASS。原因是汇总器调用 `g1_gate()` 时把期望 q0 传成了 `None`。

修复要求：

1. 从 canonical NPZ 读取完整 29 关节 q0；
2. 分别比较 Isaac、MJ native、MJ matched 的第一条 q；
3. 保存 `q0_maxerr_29` 和最大误差关节名；
4. 任一最大误差超过 `1e-5 rad`，G1 FAIL；
5. root pose、root velocity、29 关节 dq0 也要使用真实期望值比较。

### 4.2 G4 把微小数值改善误判成科学 PASS

当前 G4 只判断 matched 的 MAE/RMSE 是否“严格小于”native，没有最小效应阈值。因此 `0.070693 → 0.070573` 这种约 `0.17%` 的变化也能凭 MAE、RMSE 两项得到 `improved_count=2` 并 PASS。

应把“实验有效”和“假设是否支持”拆开：

- `validity_pass`：G0/G1/G2/G3/G5/G6 是否通过；
- `armature_hypothesis_status`：`SUPPORTED / NOT_SUPPORTED / INCONCLUSIVE`；
- 不再让一个真实的零效应结果导致“实验失败”，也不让浮点级微小改善自动变成“假设通过”。

建议预注册 elbow 主指标：

```text
improvement_ratio = (MAE_native - MAE_matched) / MAE_native
```

建议判定：

- `SUPPORTED`：改善率至少 10%，且绝对 MAE 至少减少 `1e-3 rad`，并且 RMSE 或 t50 方向一致；
- `NOT_SUPPORTED`：有效数据下改善率小于 5%，或方向变差；
- `INCONCLUSIVE`：介于两者之间，或 t50 不可用、存在饱和等解释冲突。

阈值必须在看 N5-R2 结果前写入配置和报告。

### 4.3 G6 目前只证明 q 轨迹确定

`compare_repeats.py` 只比较 t 网格和 q(29)。下一版 G6 还应逐点比较：

- dq(29)；
- q_des(29)；
- computed torque、applied torque；
- contact、saturation；
- 每次运行的模型、runner、canonical state、配置 hash。

G6 的 q 逐点差为 0 可以保留为有效结果，但“完整运行确定性”需等上述字段补齐。

## 5. 修订后的执行顺序

## Step A：修复隔离 URDF 生成器

目标：确保 root 世界位姿只应用一次，所有 joint/link origin 始终保持局部语义。

具体操作：

1. 删除对全部 joint origin 施加 `R_root/t_root` 的逻辑；
2. 删除把 root 世界位姿写入 root link inertial/visual/collision origin 的逻辑；
3. 对非目标 revolute joint，只执行局部冻结：

   ```text
   T_fixed = T_joint_origin · Rot(axis, q0)
   ```

   其中 joint origin 的 xyz 保持原局部平移，rotation 右乘 q0 旋转；
4. 目标关节保持 revolute，局部 origin 和 axis 不变；运行初始化时设置该关节 `q=q0`；
5. 在 Isaac 场景中，将 articulation/root Xform 一次性设为 canonical root pose；
6. 设置 fixed base，并确认 fixed-joint merge 不改变目标关节下游质量、COM 和惯量；
7. MuJoCo 隔离 XML 保持相同的 canonical root 世界 pose 和相同的局部冻结语义。

需要保存：

- 修复前后 `urdf_isolation.py`；
- elbow/hip 修复后的 URDF；
- Isaac 导入后的 articulation joint/body runtime 表；
- 生成器 stdout 和 SHA256。

停止条件：任何 joint origin 出现接近 canonical root 世界平移的重复值，立即停止，不进入仿真。

## Step B：新增 G0 Asset Equivalence Gate

G0 必须在启动 Kit 全量运行前离线完成。不要再用模型生成器内部的同源公式作为唯一 self-check。

### B1. 拓扑检查

- 两侧只有一个动态 DOF；
- 动态关节名都是目标关节；
- 其余 28 个策略关节均已真正固定；
- target parent/child 和下游 link 集合一致；
- 下游 link 名、质量逐项一致。

### B2. 独立正运动学检查

用单独脚本解析 URDF/MJCF，不 import 模型生成器中的变换函数。比较：

- 全部同名 link/body 的世界位置与姿态；
- 目标关节世界位置；
- 目标关节世界轴；
- 每个下游 link 的 COM 世界位置和惯性轴。

建议阈值：

```text
max body position error <= 1e-5 m
max body orientation error <= 1e-5 rad
target joint position error <= 1e-5 m
target joint axis angle error <= 1e-5 rad
```

### B3. 质量和等效惯量检查

- elbow 下游总质量应约为 `3.204651 kg`；
- hip 下游总质量应约为 `8.37 kg`；
- 修复后 elbow 刚体 `I_eff` 应接近 `0.075245 kg·m²`；
- 修复后 hip 刚体 `I_eff` 应接近 `1.039145 kg·m²`；
- 两侧刚体 `I_eff` 相对差建议不超过 1%；
- armature 单独列出，不得混入刚体惯量而失去可追溯性。

输出 `asset_equivalence_<joint>.json`，至少包含：

```json
{
  "topology_pass": true,
  "only_dynamic_joint": "right_elbow_pitch_joint",
  "max_body_pos_error_m": 0.0,
  "max_body_rot_error_rad": 0.0,
  "target_axis_error_rad": 0.0,
  "downstream_mass_isaac": 0.0,
  "downstream_mass_mujoco": 0.0,
  "rigid_Ieff_isaac": 0.0,
  "rigid_Ieff_mujoco": 0.0,
  "pass": true
}
```

**G0 任一项失败，不允许运行 N5-R2。**

## Step C：运行 N5-R2 smoke

G0 通过后只跑 6 个条件各一次：

| 引擎 | 关节/条件 | 次数 |
|---|---|---:|
| Isaac | elbow native | 1 |
| Isaac | hip native | 1 |
| MuJoCo | elbow native | 1 |
| MuJoCo | elbow armature matched | 1 |
| MuJoCo | hip native | 1 |
| MuJoCo | hip matched no-op | 1 |

smoke 验收：

1. G0 PASS；
2. G1 的 q0 真实数值不再是 null；
3. G2 隔离、root、contact 全过；
4. G3 无饱和；
5. hip native/matched 逐点差为 0；
6. elbow/hip 的响应量级与 G0 计算的总等效惯量一致，不再出现 10–90 倍惯量才能解释的慢响应；
7. 输出 elbow/hip 的 q、dq、torque 三联图，不只画 q；
8. 保存每个条件的 `runner/model/canonical/config` hash。

smoke 阶段只判断工具和资产是否正确，不根据单次结果宣布 armature 因果结论。

## Step D：运行 N5-R2 全量

smoke 全过后，再执行原矩阵：

```text
Isaac：2 条件 × 3 次 = 6 次 Kit 启动
MuJoCo：4 条件 × 3 次 = 12 次 WSL 运行
```

必须全部使用修复后的同一版本模型和 runner，不能把本轮 v2/v3 的旧重复当作新实验的 rep1。

输出分成两层：

### D1. Validity

- G0 资产等价；
- G1 采样与初态；
- G2 隔离、固定根和无接触；
- G3 无饱和；
- G5 hip no-op；
- G6 完整 trace 和 hash 重复性。

### D2. Scientific result

- elbow native vs Isaac：MAE、RMSE、t10/t50/t90、overshoot、q(0.5)；
- elbow matched vs Isaac：同一组指标；
- 预注册 improvement ratio；
- `SUPPORTED / NOT_SUPPORTED / INCONCLUSIVE`；
- hip 在 armature 已一致时的剩余误差，用作非 armature 基线，但不直接归因。

## Step E：N5-R2 后的分叉

### 情形 E1：elbow 明显改善，hip 误差也显著缩小

说明当前主要问题确实是资产生成错误，armature 可能解释 elbow 剩余差异的一部分。此时：

1. 固化 N5-R2 结论；
2. 再进入 N6-R 的 17 关节分组消融；
3. N6-R 同样必须先跑全模型资产等价表。

### 情形 E2：资产等价后 elbow armature 仍无明显改善

这是一个有效的负结果。此时才进入非 armature 因素消融，建议顺序：

1. MuJoCo `frictionloss: 0.1 → 0`；
2. 对齐 physics dt/control hold，至少比较 MJ 2 ms 与 5 ms；
3. 对齐显式 effort PD 与可能的隐式 drive 语义；
4. 对齐关节 passive damping、solver/integrator；
5. 最后再检查 limit/constraint 参数，因为当前阶跃并未触及关节限位。

每次只改变一个因素，保留 native 与 matched 基线，继续使用 elbow 主实验和 hip negative control。

### 情形 E3：G0 无法通过

停止跨引擎阶跃比较，先回到官方 URDF/XML 的 link 质量、COM、惯性张量和坐标系映射。不要通过放宽 G0 阈值绕过模型不等价。
