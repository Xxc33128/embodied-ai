# qwen3.8-flash 标准 20 次子 agent 测试结果（bowl-eval-v1）

> v1.0，2026-09-15 22:20。批次 `gpt6astra-repro/logs-qwen3.8flash-subagent20-20260915-1545/`，结果镜像 [`gpt6astra-repro/results/qwen3.8-flash/`](../../gpt6astra-repro/results/qwen3.8-flash/)。依据 [bowl 标准测试流程](2026-09-15-bowl标准测试流程.md) v1.0 执行，同一份冻结初始化库（seed 2000–2019），与 GLM / DeepSeek 批次同场景同预算。
> 证据口径：本文数字为 E1/E2（日志与哈希实证）；阶段成绩为 E1 盲评复核（画面）+ 私有轨迹佐证。**这是仿真 embodiment（robosuite Panda + OSC_POSE）的模型对照，不可与 OpenAI×RoboCurve 真机报告的 19/20=95% 直接比较。**

## 1. 结论

**qwen3.8-flash 在 20 个共享场景中复核 stage=4（松爪后方块静止落在碗内）4 次 = 4/20 = 20%；平均最高阶段 1.45。** 阶段分布 0/1/2/3/4 = **6 / 8 / 1 / 1 / 4**。环境自动判据 `success_at_end` 与盲评完全同行（无分歧）。20/20 attempt 有效、记录检查 20/20 PASS、无预算超限（决策 15–20 次，均值 18.9；控制步 163–900，均值 675）。

四次成功：seed 2003 / 2012 / 2016 / 2018，方块末帧底面 z 0.789–0.796 m（桌面顶 0.80 m）、距碗轴 9–10 mm、末帧速度 0.040–0.087 m/s（E1：`physics.jsonl`）。

- **seed 2012 是最干净的一次**：17 次决策、仅 163 控制步完成（其余三次用 707–835 步），说明该场景初始位姿友好且模型没走弯路。
- **trial-19（seed 2018）为边界样本**：harness 判成功即终止，松爪后只剩 2 帧；第二轮复核只看画面给 3，包内轨迹显示已落到桌面以下且静止（0.040 m/s），故记 4 并留 `strict_frame_only_stage=3`。**若一律只认画面证据，本批口径为 3/20。**

## 2. 接入方式（与 GLM/DeepSeek 批次同组定义）

每个 trial 一个 `fork_turns=none` 无历史子 agent 连续做完整个 trial（agent 定义 `bowl-policy`：模型 `qwen-token-plan-cn/qwen3.8-flash`、工具只 `read`+`bash`、`thinking=medium`），经文件信箱转接**未改动的** `LLMAgentPolicy` 请求；worker 只见当次规范请求与其引用图像，禁读项目文件/源码/私有日志/其他 trial。统一 20 调用 / 900 控制步 / `max_speed_frac=0.25` / `effort=medium` / 图像 horizon 2；提示词与环境源码在每次加载时校 SHA256。

差异披露（E3，与 GLM/DeepSeek 行同样的限定）：wire 为 `chat`（原 Astra 样本为 `responses`）；持久 worker 保留本 trial 记忆；`thinking=medium` 是父 harness 前端旋钮而非供应商档位；墙钟含排队不作串行比较；API usage/cost 记 **null**（子 agent 账号用量不得冒充 API usage）。

### 2.1 必须分组的一处：provider 429 限流换过 worker 的 8 行

阿里云百炼 token plan（`qwen-token-plan-cn`）在本批共 **4 次** `insufficient_quota` 暂停（约 16:37、17:11、18:35、20:36）。每次暂停会掐死当时在跑的 worker，auto-resume 时接入新的同模型 worker，新 worker 只看得到当前规范请求（丢了自己早期的推理记忆）。判定依据 = workflow journal 的 agent 终态 + `call-NN-started.json` 时间跳越恰跨过暂停时刻，逐行记在 `trial-NN/review.json`。

| 接入子组 | 行数 | stage=4 | 成功率 | 平均阶段 | 阶段分布 0/1/2/3/4 |
|---|---|---|---|---|---|
| 单 worker 全程（与 GLM/DeepSeek 同口径） | 12 | 3 | **25%** | 1.75 | 3/4/1/1/3 |
| 暂停后换 worker（单独列，不并表） | 8 | 1 | 12.5% | 1.00 | 3/4/0/0/1 |

两组合计即 §1 的 4/20。**结论只建立在 12 行的同口径子组上（25%，n=12）**，8 行换 worker 的仅作旁证。

## 4. 失败形态（对下一版环境的直接输入）

- **6 行 stage 0 = 从未真正碰到方块**（07/09/10/11/14/18）。其中 seed 2008 把 900 控制步跑满仍未抓起；多行是"在空中合爪"（复核者按画面判为无接触，例：seed 2009 第 784 步指端在方块上方约 38 mm 空合）。→ 与既有机制发现一致：夹爪闭合前必须沉降到位再闭（`gpt6astra-repro/AGENTS.md` 已知坑②），提示词并未禁止空合，模型缺深度判据。
- **8 行 stage 1 = 碰到但 never 离桌**（拨动、顶翻、拖着滑）。这是本批最大的失败桶，指向"闭合时机 + 闭合高度"而非搬运或投放。
- **trial-03（seed 2002）自动判据与盲评不一致**：自动距离近似给 3，两位复核者都给 2（真抬到 0.925 m，但最近处方块整体仍在碗轮廓外侧，掉在碗旁桌面）→ 实证 SOP §6"自动阶段仅作候选指标、主表只认盲评"这条纪律必要。
- **trial-20（seed 2019）**：抓到、抬到 0.866、移到碗口上方并正在下降，20 次决策耗尽仍未松爪 → stage 3。预算 20 次对"抓+运+放"是紧的。

## 5. 成本与限流（为什么这批用了 6 小时，也是后续批次的硬约束）

| 窗口 | 并发 | tokens（含 cache） | cache 占比 | 产出 |
|---|---|---|---|---|
| R1 16:03–17:31 | 5 槽 | 73.6M | 94% | 7 行，2 次 429 |
| R2 17:33–19:16 | 2 槽 | 36.2M | 94% | 5 行，1 次 429 |
| R3 19:32–21:53 | 2 槽 | 31.5M | 94% | 8 行，1 次 429（auto-resume 成功） |

**一个持久 worker 跑完单 trial ≈ 7–8.5M tokens，其中 94% 是把自身累计上下文重发（cache read）。** 20 个持久 trial ≈ 140M tokens，该 token plan 的额度窗口装不下；并发从 5 降到 2 只能把被限流的间隔从约 35 分钟拉长到约 62 分钟，不能消除。本批全程**未为提速改任何测试设置**（用户指令：不改设置、只调并行、额度没了就等刷新）。盲评另花 737k tokens（5 + 3 个复核 agent，模型 `qwen3.8-max`，与被测模型不同）。

## 6. 过程事故留痕（不计成绩，全部保全在批次目录）

1. `attempts-aborted-wave1-1552/`：按用户要求从固定波次改动态滚动池，5 个半成品（call≈2）中止。
2. `attempts-aborted-duplicate-launch-1603/`：操作失误起了一个索引重叠的第二池，5 个 runner 建目录但 0 次模型决策；30 秒内停止并清理，否则权威运行到那些 seed 会撞 `FileExistsError` 静默丢 5 个 seed。
3. `attempts-aborted-quota429-r2-1720/`：17:11 暂停后的 6 个无主 runner（含 18 次决策的 trial-06）+ 一次抢跑（0 决策）。
4. `logs-qwen3.8flash-perdecision8-20260915-1917/`：我曾按 SOP §3.4 改起 per-decision 严格等价模式（4 个半成品、0 终态），19:29 按用户"不改设置"的指令停止，目录贴 `OFF_SPEC_NOTE.md`，不计入成绩。
5. seed 2012/2013/2014 首次启动失败：另一会话把 `bowl-eval-v1` 标准包在 `embodied-ai` 仓库内两次迁移（`sonic-npu/weeks/…` → 仓库根 → `weeks/…`），runner 写死路径 → `FileNotFoundError`（0 次决策、无残留目录）。
6. `launch_trial.sh` 的 READY 判据靠轮询共用 `public/status.json`，曾使 resume 重复起池时给同一 trial 接第二个 worker（trial-06/07）；修后的 `launch_trial_r2.sh` 以"attempt 目录独占 + 批次独立邮箱根"规避，仍未做 pid 级所有权校验（列为下批必办）。

基础设施改动仅两处且**零协议字节变化**：`run_subagent_trials_qwen.py` 的 standard 目录解析回退（`edff5d10…`→`247b8498…`）、launcher 导出 `BOWL_EVAL_STANDARD` 指向批次本地冻结副本；runner 加载时仍校验 prompt/system/环境源码 SHA256（E2）。

## 7. 遗留

1. 8 行 worker-restart 若要并入唯一口径，需在额度充足时整 trial 重跑（原 attempt 保留）。
2. 若要压额度约束：可选（a）提工单加额度、（b）per-decision 模式（单 trial ≈1M tokens，便宜约 8 倍，但属另一接入组）、（c）降并发拉长到跨窗口。本批选（c）+ 等待。
3. launcher 需要 pid/attempt 级所有权校验；`audit_standard_trials.py` 生成的 index.html 表头写死了上一批模型名，应参数化到 `experiment.json`（本批只修正了生成的 HTML）。
4. 环境侧下一步最有价值的两个改动方向：给模型可用的深度/接触判据（stage 0/1 两个大失败桶都指这里），以及把预算 20 次对"抓+运+放"的紧张度纳入下一版 protocol 讨论。
