## 0. 总体结论

1. **这是"全栈方法论开源",不是"可立即复现的权重发布"**。五个模块(数据管线/生成器/跟踪器/编排器/闭环系统)的代码全部发布,但:generator checkpoint、tracker 权重、300 小时数据集均不随仓库发布;开源 datagen **只覆盖 SIT 任务的训练数据生成**,其余 4 个技能(GO-TO/DOOR/CRAWL/CROUCH/PUSH)的运动生成与渲染入口不在仓库内(`system/README.md` 自述;`docs/data_pipeline.md:142-143` 列出未发布清单)。
2. **工程注释密度罕见地高**,大量"为什么这样写"的事故记录(NCCL 死锁、ONNX 静默不一致、6.1GB checkpoint 泄漏等),是比论文更有价值的部分。
3. **License 是 Apple 自定义 source-available 许可**(非 OSI 开源):个人可使用/修改/再分发,但**无专利授权**、不得用 Apple 名义推广衍生品(`LICENSE`)。研究/内部复现无碍,商用需法务评估。第三方依赖许可见 `ACKNOWLEDGEMENTS`(Infinigen BSD-3、Kimodo Apache-2.0、Isaac Lab BSD-3 等)。

## 2. datagen/ —— 合成数据管线(仅 SIT 完整开源)

### 2.1 三阶段编排

统一入口 `launch/run_stage.sh <scene_gen|gen|render>`,读 `configs/pipeline/*.env`,支持 `--shard/--num-shards` 分片与 KEY=VALUE 覆盖。所有 I/O 经 `common/storage.py` + `launch/halo_s3`(AWS CLI 封装)走 S3,`PUSH_TO_S3=0` 可纯本地。

- **Step1 场景**:`scene_gen/pod/run_shard.sh` → `gen_scene.py` → `infinigen_style.py`(进程内 monkey-patch Infinigen 后 `runpy` 跑官方入口)→ `prep_and_gt.py`(房间测量+64 视角 GT)→ **`bake.py` 光照烘焙** → `project_gt.py`(GT 投影细化贴图)→ `obj_to_usdc.py` → `analyze_scene`(占据栅格+TPV 候选)。预算保护 BUDGET_S=75600s,GEN_TIMEOUT_S=18000 杀卡死进程。
- **Step2 运动**:`motion_gen/pod/run_kimodo_sit_syn.sh` → `generate_sit_traj.py`(核心,spec 采样 → 关键帧 → best-of-N 生成 → gate → 落盘)。
- **Step3 渲染**:`render/pod/run_render_isaac.sh`(或 mujoco CPU 变体)→ `render_episodes.py` → Isaac/MuJoCo driver;最后 `render/stitch.py` 拼接并做 meta==data==fpv==tpv 四方校验。

**Motion-first 解耦**:运动在"空场景+原点椅子"的 canonical 场景生成,渲染时才 SE(2) 嵌入真场景(`tasks/sit.py::canonical_scene`)——一次生成喂所有场景数消融,episode = seed + placement record,可任意重渲染。

### 2.2 Kimodo 接入(外部依赖)

- pip 安装 `nv-tlabs/kimodo` @ `58e78189`(Apache-2.0);权重 4 个 HF 模型共 ~17.5GB:`nvidia/Kimodo-G1-RP-v1`、2×`McGill-NLP/LLM2Vec-Meta-Llama-3-8B-Instruct-*`、gated `meta-llama/Meta-Llama-3-8B-Instruct`(需 HF_TOKEN)。仓库内 `motion_gen/kimodo/` 只是 HALO 侧封装(约束构造/段拼接/seam blend)。
- **SIT 三段链**(`kimodo/motion_gen.py:15-21`):WALK("A person walks",Root2D 走廊前 85% 的 20 个 waypoint + heading,批 16 候选)→ TURN("turns around slowly",plateau 模式:root hold + 稀疏 heading sweep + 末帧 FullBody)→ SIT("sits on a chair",两端 FullBody 关键帧)。关键帧模板 `kf_world_6772_sit.npy`(5 个 36 维姿态:站/走末/转末/迈步/坐),坐姿取自真机 G1 关节日志。
- 接缝处理:`seam_blend` 线性混合 ±3 帧;`--turn-end-back-cm 20` 把转末关键帧向座椅回移 20cm 折叠后撤步(否则 sit 段倒退过远,0/9 可放置)。
- 根轨迹:`unicycle.py::simulate_corridor` 加速度受限单轮车(V_MAX 0.7、OMEGA_MAX 1.2、A_MAX 1.0);导航 400 spawn 候选 → 圆碰撞筛 → 8 邻接 A* → 简化到 20 waypoint。

### 2.3 几何验证器:与论文有出入(E1 vs 论文)

- 实际注册 **30 项检查**(`motion_check/checks/`:dynamics 10、foot 11、limits 5、collision 2、task_success 2),sit_on_chair 档生效硬检查 **21 项**——论文写 33 项(23 硬),released gate 比论文精简 3/2 项。阈值在 50 条人工标注 episode 上校准(~7/10 好 acceptance、~28/40 坏被标)。
- **gate 场景里没有椅子**:`kinematics.py::_stage_scene` 恒返回 robot-only 平地板,`scene_collision`/`seat_contact` 实际 SKIP,坐没坐上由 `sits_at_end`(末帧 root_z∈[0.35,0.62] 且稳定)间接保证。
- **"过滤"实为软过滤**:best-of-N 全失败时**仍保留分数最高的一条**带失败标记进数据集——50k 中仅 77.3% `final_gen_accepted=true`;tracker 侧吃 `--accepted_only` 子集,generator 侧吃全量。
- 检查器带版本号 `mqc-0.8.0+cfg.<hash>+chk.<hash>`;pyyaml 缺失时阈值**静默回退**代码默认(README 明示的坑)。

### 2.4 场景 staging 与渲染

- **占据栅格**:`analyze_scene.py::build_occupancy`——逐对象 AABB、按工厂名滤非障碍(rug/wallart/mirror/...)、忽略离地 <8cm 与 >1.7m 悬空物、0.10m/格 + 0.30m 墙边距;clearance 图用 scipy EDT。
- **SE(2) 放置**:`robot_placement.py::solve_path_placement`——随机置换 ≤800 个 clearance≥0.35m 格 × 24 yaw,整条 walk 路径(每 3 帧采点)刚体变换后要求全程 clearance≥0.35m、椅子处 ≥ 对角线/2+0.10m;失败 fallback 静态 spawn。种子 = `sha256(RENDER_BATCH::shard::episode)`。
- **光照烘焙在仓库里**(`scene_gen/scripts/bake.py`,Blender/bpy):Cycles COMBINED 128spp 按表面积定 atlas 分辨率(256..4096),Smart Project 建 `uv_bake` 且不破坏原 UV;失败梯度回退 重unwrap→DIFFUSE→平色;烘完换 unlit emissive 材质。MuJoCo/Isaac 渲染时**无引擎灯**。
- **双渲染后端**:Isaac(参考实现,fisheyePolynomial 相机直接匹配 OAK Kannala-Brandt k1-k4 拟合)与 MuJoCo(CPU 变体:1600×1000 针孔 → `fisheye_warp.py` 后处理 warp 成 1280×800 鱼眼)。回放只 `sim.render()` 不 `sim.step()`(执行器会把未匹配关节拉向 0);Isaac 结束 `os._exit(0)` 绕 Kit teardown 挂死。
- **域随机化**(`cam_fx.py`,固定顺序):brightness→contrast→gamma→color_tone→saturation→过曝保护→chroma→**egomotion motion blur(由腰关节角速度推图像光流)**→defocus→noise→salt/pepper→posterize→scanline→vignette。DR 参数在 gen 阶段用独立盐 RNG 抽好写进 spec,渲染只是执行(保证 resume 一致)。场景端 DR = `infinigen_style.py` 的 patch(禁沙发、rug 缩 0.55×、灯泡功率×2、哑光木头、纯色饱和石膏墙等)。

### 2.5 落盘格式

- 运动阶段:`episode_NNNN/{g1_qpos.npy [T,36], episode_spec.json, meta.json, plan.npy}`;episode id = shard*1000+local(有空洞)。
- 渲染阶段:`episodes/<ep>/{oak.mp4, tpv.mp4, traj.npz, meta.json}`,完成判定 = 4 文件齐且 ≥256B;resume 回滚尾部 2 episodes 防截断。
- 训练集:LeRobot 风格 parquet(`action=q[t+1]-q[t]`、`observation.joint_pos`、body_pos/quat **仅 pelvis 槽真值**)+ `videos/observation.images.{fpv,tpv}_cam/` + `meta/{info,episodes,tasks}.jsonl`;`info.json` 带 `codebase_version: egomotion-gen-0.1.0` 与逐关节 features(下游 eval 用它映射)。

### 2.6 可复现性边界(论文没写,E1)

- H100 逐位复现(shards 0-49 验过 10k eps);**B200 只统计相似不逐位**(cudnn.benchmark/TF32/批相关前向)。
- **Infinigen 同 seed 也不是字节确定**(房间壳/尺寸/风格一致、家具不同)→ 重建场景仅 ~80% episode 能复现论文的椅子摆放。
- Isaac RTX 渲染本身不可复现(~36dB Y-PSNR)。
- 未发布:gated/truncate-pad 子集、go_to 与 pick_up 任务、unit/golden 测试、指标脚本、跨引擎烘焙 QA、调试可视化;dual-room(DOOR)场景列表在但无运动/渲染入口。

## 3. generator/ —— 运动生成器

### 3.1 模型

- `MotionGenerator` = 冻结 Qwen3.5-2B encoder + DiT decoder(flow matching),输出 [B,150,36](29 关节 + 3 骨盆位移 + 4 四元数,相对当前帧的 **yaw-only gauge**:`Rz(-yaw0)(p_t-p0)` + 去偏航四元数,**非完整 SE(3)**,与部署侧 `write_gauged_pose` 是隐性合约)。
- Encoder(`vision_language_encoder.py`):`requires_grad_(False)` + 覆盖 `train()` 永远 eval;取 last hidden states,用 `<|vision_start|>/<|vision_end|>` token span 切出**逐图像 token**(64 个,8×8 merged grid)+ 后续文本 token;`state_dict()` 覆盖为只存 trainable 参数(注释记录了曾把 6.1GB 冻结 LM 泄进每个 checkpoint 的事故)。
- Decoder(`motion_decoder.py`,GR00T N1 风格):8 层 × 512 × 8 heads,AdaLN 支持 **per-token timestep**(前缀帧 t=1 的关键);条件位置嵌入 `cond_pos_embed` 默认关但**发布配置全开**——不开时"target on the left/right"产生相同 token multiset、相同输出(左右歧义,注释明示)。输出投影零初始化。可训练参数 49.3M。

### 3.2 Flow matching 与 training-time RTC

- `flow_matching.py`:t ~ **Beta(1.5,1)**(偏噪声端);插值 `noisy = t*clean + (1-t)*noise`,**t=1 是干净样本**(与常见约定相反,读码注意);速度目标 = clean - noise。
- **training-time RTC 实现**(`trainer.py::_apply_prev_chunk_inpainting`):(1) 干净目标前 P=15 帧拷入噪声输入;(2) 前 P 帧 per-token t=1;(3) `flow_mask[:, :P]=0` 剔出 loss。
- 推理(`predict()`):15 步 Euler,每步积分后**硬覆盖前缀**;另有 `predict_rtc()`(inference-time guidance,IIGDM+VJP,beta=5.0)用于旧模型——部署节点对 inpaint 模型禁用该路径。代码里两套 RTC 并存,论文只讲了前者。
- 训练工程:DDP `broadcast_buffers=False`;**双参数组 AdamW**(解冻 VLM 部分单独 lr=1e-5,否则主 lr 1e-5 会毁掉预训练权重);NaN 守卫全局一致跳过(per-rank 跳会挂 all-reduce);eval 走 rank0 子进程 30min 上限,其余 rank barrier 等。
- 三个配置:frozen(论文,batch 80×64GPU=5120,50 epochs)/ finetune(全 VLM 解冻,fp32)/ finetune_vdrop(**30% 样本 RGB 换黑帧**,治"忽略文本指令")。
- 数据:S3 流式双缓冲(每节点 local-rank-0 下载 + 文件哨兵;跨节点 **TCPStore barrier 而非 NCCL**——S3 重试超 NCCL 60min 超时会死锁);`cold_start_augment` 给 inpaint 前缀造冷启动样本。

### 3.3 部署侧(3Hz 异步)

- 节点 `system/halo_system/nodes/motiongen_zmq.py`:生成与观测捕获异步,子任务切换立即触发;`gen_interval` real 默认 0.4s(2.5Hz),sim 默认 0(背靠背);halo_serve 给 generator 注册 **deadline_ms=333(=论文的 3Hz EDF 预算)**。
- 前缀来源:每次生成前 `get_trim()`(5557)拿 tracker 当前剩余参考,转模型格式送 inpaint;`rtc_inference_delay = max(1, int(推理耗时×30))` 动态估计。
- plan #1 `align_anchor="robot"`(落地机器人实际位姿),后续 `"reference"`(连续性);quiet plan(关节活动 ≤0.06 且 XY ≤0.3m)对 sit 类改回 robot anchor;hold/stand 不跑模型(冻结帧补齐);起立特判先前倾 45° 1 秒。
- 反馈:每 plan 在 `g1/gen_status` PUB {joint_activity, subtask, plan_travel} 给 orchestrator 做 settle 判定。

## 4. tracker/ —— 运动跟踪策略(最重的工程资产)

### 4.1 三阶段训练(Isaac Lab 2.3.2 / Isaac Sim 5.1.0)

| 阶段 | 任务 ID(`g1/__init__.py`) | 环境/超参 |
|---|---|---|
| PreRL 特权专家 | `Halo-MotionTracking-{Robot_Only,Robot_Object,Robot_Terrain}-PreRL` | 按技能族分 3 个专家(平地自由/推箱/坐沙发),8192 envs,50k iter |
| 蒸馏 | `Halo-MotionTracking-Distillation-{Proprio,ProprioDepth}` | 4096 envs,30k iter,BC+DAgger(20% 教师驾驶);教师按**运动**路由(同 env 可能播不同技能 clip) |
| PostRL | `Halo-MotionTracking-PostRL-{Proprio,ProprioDepth}` | 4×4096 envs,50k iter,multi-critic PPO |

- 入口 `training/scripts/rsl_rl/train.py`(分布式退出 `os._exit(0)` 防 PhysX teardown 段错误;NaN sanitizer 只置零单 env 不杀训练);导出 `play.py --export_only` → ONNX。
- clip 来源:LAFAN1 重定向(HF 数据集)+ datagen 坐沙发片段;文件名前缀映射资产(`push_v2*`→箱、`labsofa_*`→沙发),每 env 只采兼容 clip;自适应采样 + 失败直方图核平滑采起始帧;5% reset 冻在第一帧练站立恢复。

### 4.2 观测契约(部署硬约束)

- 特权 critic:proprio + 10 帧未来轨迹(+4 keypoint 世界系误差 12 维)+ anchor + 30 帧历史 + **足底相对高度图**(17×11,0.1m,含物体)。
- 学生 actor(= ONNX 输入):`(1,434)` proprio(含 **5 帧**参考 lookahead——故意比 critic 的 10 帧短,减少 sim-to-real 作弊)+ `(1,30,166)` 时序(历史行与未来参考帧交错)+ `(1,1,48,84)` 深度(**25Hz**,clip[0.2,2.5]→log1p)。
- 深度腐蚀 11 步流水线(`mdp/observations.py::depth_image`):合成杂物矩形→stereo 噪声→flicker→5mm 高斯→per-episode scale/bias→5% dropout→延迟 1-3 帧→侧遮挡;相机外参每 reset ±2.5cm/±2.5°。
- anchor:训练用 pelvis(真机唯一有 IMU 的 link),部署切 `odom` 模式。

### 4.3 网络

- 教师:SimBa 768×3 + temporal CNN [64,128,128](带 LN)+ height CNN [32,64,128]。
- 学生/PostRL actor:SimBa 512×2 + temporal CNN [32,64,128](无 norm)+ depth CNN [16,32,64,128](**无 padding**——onnxruntime CPU 上 pads=(1,0) 的 Conv 会算错,导致导出 ONNX 与训练策略静默不一致;深度学生共 ~5.5M 参数,机载预算)。
- 所有模型 `obs_normalization=False`(per-teacher 统计量会在教师间漂移)。

### 4.4 Reward(`mdp/rewards.py` + env cfg 权重)

- 模仿 6 项 exp(-e²/std²) 核(anchor pos/ori、14 body 相对 pos/ori、体线/角速度)+ survival 0.1。
- 物体交互(推箱):object pos/ori 跟踪 × **手-物体邻近门控** exp(-(min_hand_dist/0.3)²)(ResMimic 式)+ 接触引导 +0.3 + 掉落惩罚 -1.0。
- 安全:**膝部负机械功率惩罚**(只罚超 150W deadband 的负功率,权重 -10,保护真机电机过流;蒸馏阶段置 0 因 BC 无奖励梯度)。
- 正则:joint_limit **-100**(clip 10 防单步淹没)、action_rate、PostRL 新增支撑期足底滑移 -0.2 与参考门控接触惩罚(坐/跪要的接触不罚)。

### 4.5 Multi-critic PPO(`rsl_rl_ext/multi_critic_ppo.py`)

- 路由 id 塞进 rollout observation 副本(模型不读);GAE 按各自 critic 估值;**advantage 按 critic 分组归一化**(多 GPU all-reduce)防高回报技能主导;actor 全样本训练,每 critic 只回归自己路由的样本。
- warm start:PostRL 从注册表 strict 加载教师 critic;蒸馏 checkpoint 加载学生 actor 并把探索 std 重置 0.2;checkpoint 内嵌路由元数据可追溯。

### 4.6 Sim-to-real

- **执行器建模**:统一自然频率 10Hz/阻尼比 2.0,`kp=I·ω²、kd=2ζIω`(I 含转子惯量);动作尺度 `0.25·τ_max/kp`;`DelayedPDActuator` 命令延迟 5-25ms,PostRL 换 per-env 重采 U[15,40]ms 抖动延迟。
- sysid:基于**背包 Mac mini + 头相机的 37.56kg 实测 URDF**(`assets/robots/g1/urdf/g1_29dof_macmini_sysid.urdf`)。
- PostRL DR:armature/effort/mass/CoM/payload/关节 stiction(按电机族设上限)+ **compliant 地板**(地毯刚度 4 档 × 阻尼 3 档,脚可陷 2cm,需 `replicate_physics=False`)+ 推箱摩擦/质量加宽。

### 4.7 部署(C++ 真栈)

- `deploy_cpp/`:C++20;RT 线程 mlockall + SCHED_FIFO(prio 80, isolated cpu)+ setcap 免 root;**无锁三缓冲**(单 CAS latest-wins)用于 state/plan/深度;状态机 INIT→MOVING(2s cosine ramp)→CONTROL;安全:60ms stale state / NaN / 100ms stale odom → 阻尼模式;深度 stale ≥500ms 喂 far plane。
- **深度链路**:D435i 关 emitter 取原始 IR 对(Y8 424×240)→ LiteAnyStereo TRT FP16(7.6M)→ 遮挡 mask → clamp → CUDA fused area 降采样到 84×48;片上 Z16 深度仅作 A/B 与 fallback(孔洞偏置量化:0.5m 墙会读成 1.14m)。**不要在部署端遮自遮挡像素**(训练看到了机器人自身)。
- TensorRT:FP32 IO + 内部 FP16;TRT 8.5(JetPack 5)需先 `decompose_layernorm.py` 分解 LayerNorm;`.plan` 绑 GPU SM/CUDA/TRT 版本,须在 NX 上构建。
- Python 双胞胎(`deploy/`):MuJoCo sim2sim + Ethernet 真机 + web 面板,与 C++ 同一观测契约(`observation_builder.py` 由 YAML 驱动)。

## 5. orchestrator/ —— 语言编排

- **12 技能词表**(`skills.yaml`,文件顺序=subtask_id):hold/stand/crouch_under/push_box/follow/sidewalk/go_to_chair/sit/crawl_through/go_to_box/go_to_human;每个技能的 `generator_prompt` **是训练条件字符串,一字不能改**(改写=改变动作分布,多处注释)。
- **两段式**:T1 计划编写(free-form → 编号任务表,reply ≤20 词不带数字)+ Agent 闭环(6 工具:`set_plan/complete_step/retry_step/insert_step/ask_operator/finish_mission`)。
- **代码级安全护栏**(不只靠 prompt):living 目标(跟随人)的 complete/finish 被无条件改写为 retry;complete 需 (a) settle 或直切 (b) 站直 bh≥0.60(sit 例外 0.30-0.60 且倾角 ≤40°) (c) 该步确实动过;`crawl_through` 是 pass_through 禁 retry(重爬会 overshoot)。
- 判定阈值:quiet = 关节活动 ≤0.06 rad **加** XY travel ≤0.3m(慢速侧步活动低但移动 0.9m,operator 2026-10-09 报告);MAX_RETRIES=10。
- **VLM 后端唯一:本地 MLX**(`mlx-community/Qwen3.6-35B-A3B-4bit`,~20GB),没有云 API 实现(接口是 OpenAI chat 形状可换);LLGuidance 语法约束解码保证 JSON;图像前 system prompt 前缀 KV 缓存(LRU 6 槽)。
- 节奏由 generator 决定(每 plan 一帧 obs),"decision rate equals the generator's inference rate"。

## 6. system/ —— 闭环系统

- **消息层 `system/comm/`**:ZeroMQ TCP + protobuf 的 ROS2 风格中间件(Python/C++ 对称);PUB/SUB 默认 CONFLATE(队列深 1);发现走 5560 registry(心跳 TTL 10s,数据路径无 broker);**proto 必须用 protoc 29.x 重生成**(运行时 pin protobuf 5.29,Homebrew 35 会打 gencode 7.x 被拒)。
- **机载调度 `system/serve/`(halo_serve)**:**单 GPU 线程**(注释:"Metal 无跨进程优先级,并发 MLX 线程会损坏语法约束解码");EDF + 层边界抢占(monkey-patch 层 `__call__`)+ hard(policy)可抢占 soft(orchestrator),soft 保底 60% 份额;**"Not hard real time: Metal cannot preempt a kernel"**。
- **DiT 的 MLX 后端**:权重从 torch 逐项转移并断言;AdaLN 写成**手写 Metal kernel**;(3L+1) 个 AdaLN 投影融合成单 matmul;cross-attn K/V 每次 predict 预计算;**整个 15 步 Euler 是一个 lazy graph 一次 eval**;VLM encoder 的 MLX 后端 ~2.5×@B1(MPS dispatch bound)。
- **端口拓扑**:5555 get_state / 5556 put_plan / 5557 get_trim / 5558 g1/state(50Hz)/ 5559 obs / 5560 registry(保留)/ 5561 gen_status / 5564 plan / 5553 depth。
- **C++ 边界**(`system/cpp/transport/tracker_server.hpp`):50Hz 控制环、推理、plan 安装/服务端 yaw 对齐/trim 全在 C++;`put_plan` ack 等控制环真正消费(≤60ms);序列化全部离开控制线程。
- **双机分片**:Mac mini = OAK 采集 + generator + orchestrator(35B MLX)+ web viewer(:8090,纯 stdlib http.server + three.js);Jetson NX(192.168.123.164)= C++ tracker(TensorRT)+ LiteAnyStereo + registry;`setup_real_deployment.sh` 一键(rsync + apt + aarch64 编译 + ONNX→TRT)。Mac mini `HF_HUB_OFFLINE=1`(无外网,模型预拷)。
- 遥控器:Start→默认姿态、A→站起、B→tracker_ready(generator 轮询此标志才开始)、Select 急停。

## 7. 精选"论文没写"清单(全部 E1,注释可查)

1. 论文 33 项(23 硬)检查 → 代码 30 项(21 硬);gate 场景无椅子几何;"过滤"是软过滤(77.3% 硬通过,其余带标记进 generator 数据集)。
2. 论文"3Hz" → 代码是 EDF deadline 333ms + real 默认 0.4s 节流(2.5Hz);sim 默认背靠背。
3. B200 生成不逐位复现、Infinigen 同 seed 家具不确定(场景重建仅 ~80% 对齐)——大规模"仿真数据引擎"的确定性边界。
4. 深度 CNN 无 padding 是为绕 onnxruntime CPU Conv bug;深度 clip 是三处独立声明交叉校验的"训练契约",错配是静默的(far plane=无信息,0 会读成贴脸障碍)。
5. 真机不 decimate 深度(相机异步 30Hz 本身即 hold);imu 字段实际发 odom 四元数(imu↔odom 有 16-20° 恒定 yaw 偏差,字段名为兼容撒谎)。
6. `cond_pos_embed` 不开则左右指令不可分(token multiset 相同);发布配置全开。
7. flow matching 的 t=1 是干净样本(反向约定);两个"RTC"(training-time inpaint / inference-time guidance)并存,部署只用前者。
8. 数据集 body_pos/quat 30 槽只有 pelvis 真值;36 维目标是 yaw-only gauge(保留 pitch,crawl 前倾 ~40° 需要)。
9. checkpoint 曾泄漏 6.1GB 冻结 LM;NCCL 60min 超时 × S3 重试死锁 → TCPStore barrier;MPS pageable async copy 提前复用源内存。
10. Qwen3.5 线性注意力无 flash-linear-attention 时 backward 占 ~70% GPU 算子(transformers pin 单 commit 的原因)。

## 8. 与本工作区主线的接口(评注,E3)

- **对 Motus/VLM+全身控制**:HALO 是分层解耦路线的完整参考实现——"VLM 高层 + 生成式中层 + RL tracker"每一层的接口(plan 36 维、get_trim 前缀回灌、settle 判定)都是可借鉴的工程资产;multi-critic PPO 与三阶段蒸馏配方可直接平移到 Isaac Lab 项目。
- **对 Qwen 昇腾部署**:halo_serve 的"单计算流 + EDF + 层边界抢占 + hard/soft 份额"是对**无抢占 GPU 运行时上混布大小模型**这一问题的成熟答案,与昇腾上混布 35B orchestrator + 小模型的调度问题同构;DiT MLX 后端(手写 kernel + 全循环单 graph)是"把采样循环融进一个 launch"的样板。
- **对 DreamLab 评测**:HALO 的可复现性边界(渲染不可复现、程序化场景非确定)是评测合成数据方法论时必须计量的噪声源;其"验证器软过滤 + 版本化 checker id"是数据质量审计的可借鉴做法。
- **对 SONIC/NPU**:tracker 的 C++ RT 栈(PREEMPT_RT + 三缓冲 + TensorRT + 力矩感知裁剪)与 Isaac→MuJoCo 双后端,与 GR00T WBC 的 sim2sim 路线直接同构。
