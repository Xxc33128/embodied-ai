# 具身大小脑联合后训练：VLM＋VLA／WAM 的 RL 路线调研

版本：v1.0｜检索／核查：2026-10-30（Asia/Singapore）

范围：以机器人操纵为主，覆盖独立 Planner–Executor、VLM Backbone＋Action Expert、World Model＋Policy 三种结构。WAM 在本文指 World Action Model。依据为公开论文、作者项目及官方源码；未运行训练或复现实验。论文效果均为作者报告，不能视为本地复现结果。〔E3〕

证据规则：E1＝锁定 commit 的源码行号；E2＝配置；E3＝论文／官方文档／明确标注的研究推断；E4＝未复核转述，不作为本报告结论。**论文已读不等于 E1。**

## 1. 结论与阅读优先级

**有直接相关研究，但要把三种“联合”分开。** 当前最值得精读的是 Z-1、π_RL、SyVLA、DeepThinkVLA 和 WAM-RL：分别回答选择性更新 VLM＋Action Expert、联合是否优于冻结、真机双系统训练、推理与动作共享任务反馈、世界模型与动作策略协同适配。〔E3；来源见 §3–§5〕

- **想做 VLM＋连续 Action Expert 联合 RL**：先读 **Z-1＋π_RL Appendix F.2**，再审 **SyVLA** 源码。已有联合更新证据，收益随任务而变。〔E3／E1〕
- **想让“大脑推理”真正受执行成败约束**：读 **DeepThinkVLA**，补 **VLA-Thinker**。两者是共享模型内 reasoning–action 联合优化，不能直接等同于两个独立模型的分层 RL。〔E3〕
- **想做 WAM 在线改进**：先读 **WAM-RL＋Motus2**；一个是 World SFT＋Actor RL，另一个冻结 Video Backbone／Evaluator，只更新动作相关参数。〔E3〕
- **想解决长程奖励与信用分配**：补 **HiRoC＋AtomicRL**。它们对分层接口和子任务学习很有用，但不构成独立 VLM Planner 与 Executor 双端共同 RL 的证明。〔E3〕

本轮没有核实到：在操纵任务中，**两个独立的高层 VLM Planner 与低层 WAM／VLA Executor 均由任务奖励训练，并有充分冻结／单端／双端消融的成熟公开配方**。这是本轮检索边界，不是不存在此类研究的断言，也不能据此宣称研究空白。〔E3：检索判断〕

## 2. 判断“联合”的标准

| 类型 | 高层／表征模块 | 低层／动作模块 | 本文口径 |
|---|---|---|---|
| 联合推理 | Frozen Planner 生成子目标 | Frozen Policy 执行 | 系统协作，尚无后训练 |
| 联合 SFT | CE／理解／视频预测损失 | BC／Flow Matching | 联合监督学习 |
| 单端 RL | 冻结 | Task RL | Action-only／Executor-only |
| 共享策略 RL | Backbone 接受任务相关梯度 | Action Head／Expert 接受任务相关梯度 | VLM＋Action 联合 RL |
| 推理与动作联合 RL | Reasoning Token 接受 Outcome Advantage | Action Token 接受 Outcome Advantage | Reasoning–Action 联合优化 |
| 混合／交替后训练 | World Model 用在线视频 SFT | Actor 用 RL | 联合适配，但两端目标不同 |
| 严格分层双端 RL | 独立 Planner 接受其策略梯度 | 独立 Executor 接受其策略梯度 | 最贴近独立“大小脑共同学” |

以上为本报告的分析定义。Shared Attention、共享权重、端到端推理、名称中的 “RL” 均不能单独证明训练梯度的范围。〔E3：分析口径〕

## 3. VLM＋Action Expert：最直接的三组证据

### 3.1 Z-1：选择性联合 RL 的直接正例

**优先级：P0。** π0.5 先做按场景 SFT，再按任务 GRPO；困难任务可关闭 expert-only freezing，让 VLM 与 Action Expert 接受同一 clipped GRPO loss。Appendix D.4 明确说明：只改变 trainable parameter set，不改变 Advantage 或 Flow-SDE Ratio 定义。〔E3；[论文 §4.3.2、D.4](https://arxiv.org/html/2606.31846v1#A4.SS4)，2026-06-30〕

24 项 RoboCasa 平均成功率为 67.4%→80.6%，这是整套方法及 task-wise policies 的结果；**不能把 13.2 个百分点都归给联合更新**。TurnOnStove 消融显示联合组优于 AE-only，正文没有给出精确曲线终点数字。本轮未找到作者训练代码入口，不能声称已可完整复现。〔E3〕

**借鉴点〔E3：建议〕**：当失败来自视觉定位／语言条件表征时，再考虑解冻 VLM；以相同 RL 目标和预算对照冻结组，避免把多项改动的总体收益误归因于联合。

### 3.2 π_RL／RLinf：联合可行，但 LIBERO 上收益不明显

**优先级：P0，工程复现首选参考。** Flow-Noise／Flow-SDE 为 Flow Policy 构造可优化的随机过程，主实验使用 PPO；主配置冻结 VLM。Appendix F.2 另外明确测试 **VLM LoRA（r=32，α=32）＋Action Expert 全参更新**。〔E3；[论文 F.2](https://arxiv.org/html/2510.25889v3#A6.SS2)，核查版本 2026-01-29；[官方代码](https://github.com/RLinf/RLinf)〕

在 π0、LIBERO-Long 上，LoRA 联合组需要更保守的学习率／更新次数，调整后曲线仅与冻结组相当。作者认为该场景的 VLM 联合收益不明显。不能将论文主结果的高分当成联合训练结果。〔E3〕

**借鉴点〔E3：建议〕**：把 action-only 作为强基线；同时测训练时随机采样与部署时确定性采样的差异，别只看 rollout return。

### 3.3 SyVLA：真机双系统与可核验的全 Policy 优化范围

**优先级：P0/P1，算法实现须另审。** SyVLA 用 Intention Decoupling／Feature Query Tokens 连接 VLM 与 Flow Action Expert；论文报告真机 RL 与视觉语言能力保留。〔E3；[论文 §3、附录 A](https://arxiv.org/html/2606.09009v1)，2026-06-08；[作者项目](https://sy-vla.github.io/)〕

官方 commit `1b4ca0b251f5089752addd299358285e8e140b92` 中，[modeling_rl.py:32](https://github.com/sy-vla/syvla/blob/1b4ca0b251f5089752addd299358285e8e140b92/syvla/models/rl/modeling_rl.py#L32) 对 policy 统一启用梯度；[rl_trainer.py:90](https://github.com/sy-vla/syvla/blob/1b4ca0b251f5089752addd299358285e8e140b92/syvla/rl/rl_trainer.py#L90) 将全部 policy 参数交给 AdamW。这证明优化器允许更新的范围，尚不能单凭它证明每个参数都收到非零梯度。〔E1〕

进一步，[rl_syvla.py:25](https://github.com/sy-vla/syvla/blob/1b4ca0b251f5089752addd299358285e8e140b92/syvla/models/rl/rl_syvla.py#L25) 用 Qwen Hidden States 形成条件表示，[同文件:58](https://github.com/sy-vla/syvla/blob/1b4ca0b251f5089752addd299358285e8e140b92/syvla/models/rl/rl_syvla.py#L58) 将其送入 Action Head，随后以负平方误差构造 surrogate。该路径没有 Detach，可把动作目标梯度回传 VLM；所以它确有两模块共同优化的实现路径，但未在本轮实跑测量梯度。〔E1；可回传的判断为 E3〕

其 [RL loss:62](https://github.com/sy-vla/syvla/blob/1b4ca0b251f5089752addd299358285e8e140b92/syvla/models/rl/modeling_rl.py#L62) 合并动作策略项、Value Loss 与辅助 CoT Loss；可见代码直接裁剪 `exp(action_log_prob)`，此处没有显式 old/new policy ratio。**不能据论文的 PPO 名称直接认定为标准 PPO 实现**；显式 CoT 监督与动作奖励梯度也须分别核验。〔E1；算法含义为 E3 判断〕

## 4. 推理与动作共享任务反馈

### 4.1 DeepThinkVLA：最清楚的 reasoning–action 联合训练例子

**优先级：P0。** π0-FAST 基础上的 Hybrid Decoder：CoT 使用 Causal Attention，Action 使用并行 Bidirectional Attention；SFT 后以稀疏任务成功奖励做 Outcome RL，对完整 Reasoning–Action 轨迹分配 Group-relative Advantage。它是统一策略，未拆成两个独立 Planner／Executor。〔E3；[论文 v3 §3.3](https://arxiv.org/html/2511.15669v3)，核查版本 2026-08-05；[官方代码及权重入口](https://github.com/OpenBMB/DeepThinkVLA)〕

LIBERO-Long 的 SFT→RL 为 94.2%→96.2%；97.0% 是整体 LIBERO 成绩。真机部分主要验证 SFT／架构，不能拿来证明真机联合 RL。〔E3〕

**借鉴点〔E3：建议〕**：评价“大脑”时增加 CoT 移除／打乱、正确推理配错误动作、执行动力学扰动等对照；单有可读推理文本，不能证明其改善控制。

### 4.2 VLA-Thinker：把感知工具调用也放入轨迹

Thinking-with-Image 将 Reasoning、视觉工具调用与 Action 交织；SFT Cold Start 后用 GRPO 对完整轨迹做 Outcome 对齐。与纯文本 CoT 相比，它还学习何时再次获取视觉信息。〔E3；[论文 §2.2](https://arxiv.org/html/2603.14523v1)，2026-03-15；[作者项目及代码入口](https://cywang735.github.io/VLA-Thinker/)〕

报告 LIBERO 97.5%；仍属于共享模型内的轨迹优化，不能等同于独立 VLM＋Flow WAM 两模块训练。优先借鉴交互与 Credit Assignment，迁移到 Motus 时仍需重新定义连续动作 likelihood。〔前句 E3；迁移建议 E3 推断〕

### 4.3 π*0.6／RECAP：真实经验闭环的重要替代路线

RECAP 将 Demonstrations、自主经验与人工 Corrections 汇合，用 Value 估计 Advantage，再进行 Advantage-conditioned Policy Extraction；不要求照搬在线 PPO。论文报告洗衣、装箱、espresso 等真实任务，困难任务吞吐量可翻倍、失败率约减半。〔E3；[论文 §IV–V](https://arxiv.org/html/2511.14759)；[官方说明](https://pi.website/blog/pistar06)〕

其多目标训练同时涉及 VLM 与 Flow Expert，但 **Knowledge Insulation 阻断 Flow Loss 对 VLM 的回传**，不能用它证明连续动作 Policy Gradient 穿透两端。本轮未确认完整 RECAP 训练栈已公开；openpi 的存在不等于 RECAP 可直接复现。〔E3〕

## 5. WAM：联合适配与真正 RL 的边界

### 5.1 WAM-RL：与 WAM 联合后训练最贴题

**优先级：P0，方法贴合，实验支撑仍有限。** 基于 Genie Envisioner-ACT：World Model 用成功 Online Rollouts 做 Video SFT＋KL，Actor 采用 Flow-SDE 路线与预测／执行结果的 Reconstruction Reward 做 RL。属于**两组件协同在线优化，两个目标不同**；没有证据表明独立 VLM 也接受 RL 更新。〔E3；[论文 §3–4](https://arxiv.org/html/2606.17906v1)，2026-06-16〕

LIBERO-Object 为 Base／Actor-only／完整方法＝68／78／82%；RLBench Water Plants＝19／18／22%。后者增益较小，不能外推为广泛长程突破。本轮未找到作者完整训练实现入口。〔E3〕

**借鉴点〔E3：建议〕**：在线数据同时修复预测能力与控制能力，但必须保留外部 Task-success 指标；预测与执行一致本身并不保证完成目标。

### 5.2 Motus2：有 MBRL，但更新范围比共享架构窄

共享模型提供 Policy／Simulator／Evaluator，使用 DiffusionNFT 做 Model-based RL。论文 §3.3.2 明确只更新动作相关参数，Video Backbone 与 Evaluator 保持冻结。**共享三接口不代表三者一起接受 RL 更新。**〔E3；[论文](https://arxiv.org/html/2608.30237v1)，2026-08-31；[官方项目](https://motus-robotics.github.io/motus2/)〕

两个 MBRL 任务、每项 20 次评测的平均成功率为 65%→72.5%，叠加 Planning 为 75%。小规模结果应单列。本轮检查的[官方仓库](https://github.com/shengshu-ai/Motus2)仅提供 README，尚不能据源码复核训练。〔E3〕

### 5.3 World Model 作为训练环境：WMPO／WoVR

| 工作 | 更新闭环 | 与“共同奖励联训”的区别 |
|---|---|---|
| [WMPO](https://arxiv.org/html/2511.09515v1) | 在像素 World Model 中做 Policy GRPO；用 Policy 行为数据适配 World Model，Lifelong 阶段再采真实经验 | 分阶段数据闭环；不是 World Model 与 Policy 共享 Policy Gradient |
| [WoVR](https://arxiv.org/html/2602.13977v1) | Action-conditioned Wan＋OpenVLA-OFT，Masked GRPO；PACE 用更新 Policy 轨迹一次或低频修正 World Model | World Model 改进主要是监督适配；依赖用于建模的真实／仿真数据 |

两项均为论文记载〔E3〕；[WMPO 代码](https://github.com/WM-PO/WMPO)与 [WoVR 官方实现说明](https://rlinf.readthedocs.io/en/latest/rst_source/resources/publications/wovr.html)提供工程入口。**学习环境误差与 Policy 利用模型漏洞的问题，需要独立真实／物理环境评测。**〔E3：研究建议〕

## 6. 独立大小脑接口与长程 Credit Assignment

### 6.1 HiRoC：最贴近独立 Planner–Executor，但 Planner 冻结

Qwen2.5-VL Planner 经 SFT 后冻结，Executor 先做 Subgoal-conditioned SFT 对齐，再以 Hierarchical GRPO 结合 Task-level／Subgoal-level 信号学习。关键是先修复 Planner 语言与 Executor 训练指令间的 Distribution Misalignment。〔E3；[论文 Methodology 与附录 Experimental Details](https://arxiv.org/html/2608.05999v1)，2026-08-06〕

它适合作为独立大小脑研究的强基线，**不能作为双端同时 RL 的文献证据**。本轮未确认作者可运行训练仓库。〔E3〕

### 6.2 AtomicRL：最近的长程奖励传播改进

SAPO 在语义子任务边界限制失败 TD Residual 的跨界传播，BATE 将探索分配到尚未掌握的子任务。论文报告 LIBERO-Long 相对 PPO 提升 3.6／4.0 个百分点；PCC 离线训练并在 RL 时固定。〔E3；[论文 §3、附录 A.4](https://arxiv.org/html/2610.30097v1)，2026-10-21〕

它改进的是 Credit Assignment 与采样，未证明 VLM Planner 与 Executor 双端 RL。若研究联合训练，应把“哪些模块更新”和“奖励怎样传播”当作两条独立实验轴。〔前句 E3；建议 E3 推断〕

## 8. 对 Motus 式 VLM＋WAM 研究的具体启发

### 8.1 先区分底座 VLM 与 Understanding Expert

公开 Motus commit `88f6fe30c62af033874b0a2e48ad1cbdaf12cfdf` 的源码显示：

- [models/motus.py:534](https://github.com/thu-ml/Motus/blob/88f6fe30c62af033874b0a2e48ad1cbdaf12cfdf/models/motus.py#L534)：底座 VLM 的 `requires_grad=False`。〔E1〕
- [models/motus.py:329](https://github.com/thu-ml/Motus/blob/88f6fe30c62af033874b0a2e48ad1cbdaf12cfdf/models/motus.py#L329)：Language Model 前向位于 `torch.no_grad()` 中，之后再经过 Adapter。〔E1〕
- [models/motus.py:892](https://github.com/thu-ml/Motus/blob/88f6fe30c62af033874b0a2e48ad1cbdaf12cfdf/models/motus.py#L892)：Video MSE＋Action MSE 加权求和。〔E1〕

因此，**Understanding Expert 在学、Shared Attention 在学，都不能替代“底座 VLM 也在学”的证据**。只把 VLM 参数加入 Optimizer 仍可能被 `no_grad`／Detach／特征缓存切断；如研究联合，须逐组验实际梯度与权重变化。这里是公开源码分析，不代表任何远端修改版的当前状态。〔E1 事实；验收建议 E3〕

### 8.2 推荐的研究问题

比“全参一起 RL 是否能跑”更有解释力的问题是：**什么类型的失败必须更新语义／世界表征，什么类型只需动作适配；联合更新怎样兼顾 Task Return 与表征稳定？** Z-1 与 π_RL 的不同结果提供了检验这一问题的依据，但尚未给出跨任务通用答案。〔E3：基于 §3 的研究推断〕

### 8.3 建议的最小对照矩阵

以下为研究方案建议〔E3〕，不构成训练启动或恢复指令。

| 组别 | VLM | World／Video | Action | 要回答的问题 |
|---|---|---|---|---|
| A：Action-only RL | 冻结 | 冻结 | RL | 低层控制适配能到哪里 |
| B：有限 VLM 联合 | LoRA／选层任务 RL | 冻结 | 同一任务 RL | 语义／视觉表征是否是瓶颈 |
| C：在线 World 适配 | 冻结 | Online Video SFT＋稳定约束 | RL | 改善未来预测是否足够 |
| D：组合适配 | LoRA／选层任务 RL | Online Video SFT＋稳定约束 | RL | 两类收益能否叠加、是否互相干扰 |

矩阵必须预先说明 Understanding／Adapter 参数归属；A–D 的 SFT 初始权重、训练任务、环境交互预算、Action Chunk、采样噪声与评测协议保持可比。C／D 属于混合后训练，不称为三模块都做同一 RL。〔E3：方案定义〕

对照至少覆盖三种失败：语言／目标歧义、接触控制失误、长程失败后的恢复。指标同时记录 Task Success、子任务完成／恢复、OOD 语言与视觉、原有 VLM 能力、预测质量、每组 Gradient／Weight Delta，以及 Rollout 与更新成本。多个 Seed 与配对评测用于判断收益是否稳定；不以单个最佳 Checkpoint 或训练曲线替代最终评测。〔E3：建议〕

### 8.4 从哪条开始

1. **工程落地**：先以 π_RL／RLinf 的 Action-only Flow RL 建基线，再做 B 的有限解冻；它有公开实现，也有诚实的冻结对照。〔E3：推荐〕
2. **研究联合收益**：以 Z-1 的问题设定做失败分类及模块消融；SyVLA 可作全 Policy 训练参考，但先审其 Loss／Likelihood。〔E3：推荐〕
3. **研究 WAM 协同适配**：以 WAM-RL 的 C 组与 Motus2 的 Action-only 思路对照，不先承诺重建三模块同奖励全参训练。〔E3：推荐〕
4. **研究真正独立大小脑**：用 HiRoC 的对齐流程做起点，再研究 Planner 更新与 Executor 更新的时间尺度、子目标可执行性和信用分配；现有证据不足以把它当作即插即用配方。〔E3：推荐〕
