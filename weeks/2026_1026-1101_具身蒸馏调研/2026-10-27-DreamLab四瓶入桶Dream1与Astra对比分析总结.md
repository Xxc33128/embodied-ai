### 3.2 10-26 诊断批：B5 中止与 B6 改写指令

**B5（首次启动，3600 步，官方指令）**

- 任务源码只改一行（L11 `step_lim = 700 → 3600`，diff `11c11`，SHA256 `3ba6e19d…`→`4d082d52…`），场景、资产、布局、评分、指令模板均未动。〔E1：证据摘录中的 diff，本篇核对任务源码 L11〕
- 首次启动因 Isaac EULA 交互确认在 nohup 下 EOF 崩溃，按原生 runner 先例接受 EULA 后正常启动。〔E2〕
- 运行中 Dream API 拒绝官方指令。约 13 分钟内拒绝 170 次，消息去重后只有 1 种：`DA-4000 BAD_REQUEST (malformed): unsafe instruction, refused before planning: Throwing bottles into a dustbin can break them or cause damage.`；同期成功推理块 29 个。评测客户端把每次拒绝当作当集失败并重置，约 66 次重置后于 15:12 停止全部进程：0 完成集、无得分、无成集视频。〔E2〕
- 对照：10-20 同任务同指令的 B3＋B4 共 180 次请求零拒绝。Dream 服务端在 10-20 之后对该指令新增或收紧了过滤，属外部变化、与步数上限无关，原生 700 步口径同样会被拒。〔E2 数字；服务端变化为 E3 推断〕
- 已恢复：任务源码恢复官方 SHA256，`max_requests` 恢复 145，远程 GPU 节点无本批残留进程；旧 600 集批次保持叫停。〔E2〕

**B6（改写指令重跑，诊断口径）**

- 相对官方只改两处：步数上限 3600；指令模板里的 "throw them into the dustbin" 改为 "place them into the dustbin"（官方原文见任务源码 L57–59）。成绩须永久标注"非官方指令"。〔E1/E2〕
- 3 集 layout 0/1/2、seed 0，15:18–16:09 跑完。450 次成功请求（3×150 动作块），0 拒绝，0 会话重建；三集均 40/100，均跑满 3600 步，未触发完整成功。〔E2〕

## 5 失败与差异归因

- **共同瓶颈**：第四瓶入桶＋双臂复位。700 步口径下 Astra-pilot 三集与 Dream-1 两版六集都没通过第四阶段；B6 给足预算后 Dream-1 三集稳定在第三瓶档。〔E2 数字；瓶颈定位为 E3〕
- **B6 相对 B4 的提升**：预算 ×5.14 与指令措辞同时变化，拆不开。能确认的只有"预算充足时 Dream-1 能稳定完成 3/4 的抓取入桶序列"；未做单变量对照。〔E3〕
- **B3→B4 均分 16.67→11.67**：同日、同场景、同指令，只换了控制接法，属 3 集样本内波动，不能据此判断性能方向。〔E3〕
- **Astra-pilot 的失败形态**：目标要么精确到达，要么离散大失——2 次约 1.5 rad 的 IK 分支翻转；layout0 的 EEF 阶段连续 4 块差 12–22 cm，模型自述 "outside IK reach"、"diverged sideways during IK branch transition"，切到关节模式后才恢复；layout2 绿瓶落地未找回。〔E2：`decisions/`、layout2 `trial_summary.json`〕
- **执行误差与低分的关系**：两条管线的块末跟踪误差（Astra-pilot 多数 < 1 mrad；Dream-1 求解器残差典型 mm 级、块尾常 1–2 cm）都小于"瓶子能否入桶"所需的厘米级尺度，解释不了低分；问题更可能出在目标选错或时序不对。〔E3〕
- **执行级验收缺口**：两条 Dream-1 成绩链"模型目标→关节命令→真实 TCP"的精度验收至今未完成，B4／B6 整集逐 tick trace 仍在远程 GPU 节点。〔E3：转引〕
- **官方指令口径被阻塞**：Dream 服务端在 10-20 之后对官方指令新增了安全过滤（B5）；B6 的 40 分是改写指令的诊断口径，不能当官方成绩。〔E2 数字；服务端变化为 E3〕
- **延迟差**：VLA 流式与 agent 式是两种控制范式，差异来自范式本身，不能记到某一家 API 头上。〔E3〕
- **样本量**：每管线 3 集、单 seed，Astra 两条管线又各不相同。以上全部对比都未做因果分解，不构成模型排名。〔E2／E3〕
