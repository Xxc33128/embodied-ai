# 2026-09-09 远程 NPU 机器接入与集群监控经验

> **公开版说明**：本副本已隐去公网/内网 IP、真实姓名、节点归属等基础设施信息（以 `<…>` 占位）；完整原件仅存本地。

一次配通的实操记录：Mac（挂代理）→ 远程 8×910B3 NPU 机器 + 集群监控面板。

## 1. 接入方式

- 主力机器：终端 `ssh npu` 即可（`~/.ssh/config` 已配别名：Host npu → `<npu-公网IP>`，User root），已装 ed25519 公钥**免密登录**。
- RLinf 实验机：`ssh npunew`（cluster_c 节点，内网 `<npunew-内网IP>`，经 npu 跳转 ProxyJump；面板备注：RLinf 强化学习实验；8×910B3 空闲、/data_nv2 6.6T 全空、Docker 27.2.0），公钥已安装。
- 长任务必须放 tmux 里（SSH 断线不杀任务）：`tmux new -s 任务名` → 离开按 `Ctrl+B` 再按 `D` → 回来 `tmux attach -t 任务名`。
- 传文件：`scp 文件 npu:/root/`（上传）/ `scp npu:/root/xx .`（下载）；目录同步用 `rsync -avP`。
- VS Code Remote-SSH 扩展选 `npu` 即可远程改代码。

## 2. 代理与直连冲突（本次最大的坑，含一次误诊事故）

### 2.1 初次故障与修复（09-09 白天）
- **现象**：Clash Verge 开 TUN 模式接管全部流量；两个华为云 IP（`<npu-公网IP>` / `<面板-公网IP>`）在 GeoIP 库里不判为 CN，落到兜底规则 `MATCH → 代理节点`，从日本出口出去；而集群只放行本组 Wi-Fi 的出口 IP（白名单机制）→ SSH 握手后被掐、面板返回空响应。
- **修复**：给 mihomo 加两条最高优先级规则 `IP-CIDR,x.x.x.x/32,DIRECT,no-resolve`，热重载生效。

### 2.2 深夜"服务器失联"事故（09-09 晚 ~ 09-10 晨，实为误诊）
- **现象**：23:55 起 npu SSH 握手即断（TCP 通、协议断）、面板超时、npunew（经 npu 跳转）也进不去，持续 8.5 小时；曾误判为"下载连接风暴打满服务器 conntrack"。
- **真相**：**从头到尾都是我这台 Mac 的 Clash 出口坏了**。订阅 24h 自动更新（`update_interval: 1440, allow_auto_update: true`）触发 Verge 重新生成配置：① 之前热修进运行文件的直连规则被冲掉；② 写进全局 Merge.yaml 的 `prepend-rules` 键**这版 Verge 根本不展开**，被原样拷成文件顶部的无效键。于是集群流量又走了代理节点，被白名单拒绝。而我所有诊断（SSH 探测、面板 curl、"npunew 内网验证"）全部从 Mac 出发、全部经过这条坏路径——**"内网验证"的第一跳也是 Mac→npu，同样被劫持**。
- **教训（重要）**：
  1. **TUN 模式下 TCP 握手是 mihomo 本地完成的**，`nc`/端口探测"通"不代表远端可达；必须用数据层验证（ssh-keyscan 等 banner、curl 等 HTTP 响应）。
  2. **所有诊断共用同一条网络路径时，先怀疑路径本身**——应该第一时间关代理对比测一次，而不是给服务器编理论。
  3. 高并发下载器要有重试上限和退避（这条照旧成立，虽然这次不是它的锅）。

### 2.3 正确的持久化直连方案（09-10 定稿）
三层保障，写完测过：
1. **运行配置热修**（立即生效）：把两条 IP-CIDR 规则插进 `clash-verge.yaml` 的 `rules:` 列表头部，`curl -X PUT --unix-socket /tmp/verge/verge-mihomo.sock 'http://localhost/configs?force=true' -d '{"path":"<配置绝对路径>","payload":""}'` 热重载。
2. **profile 规则文件（真正的持久化，原生机制）**：当前订阅在 `profiles.yaml` 里的 `option.rules` 指向的文件（如 `rmetulSlCzOW.yaml`），用它的 `prepend:` 列表加规则——这就是 Verge UI"编辑规则"按钮写的地方，每次重新生成都会合并。
3. **全局 Script.js 兜底**：`profiles/Script.js` 里写 `main(config)` 往 `config.rules` 头部插入规则。
- ❌ **不要用** Merge.yaml 的 `prepend-rules` 键（这版不展开，会变成无效垃圾键）。

### 2.4 热重载的隐藏雷：mode 回带（09-10，我改坏梯子的事故）
- **现象**：修完直连后用户外网全断。原因：用户早上"关梯子"时 Verge 是 direct 模式，`mode: direct` 残留在配置文件里；我的 force reload 把运行内核覆盖回 direct，直连模式下国外网站全不通。
- **修复**：`curl -X PATCH --unix-socket /tmp/verge/verge-mihomo.sock 'http://localhost/configs' -d '{"mode":"rule"}'` 即时切回；同时把文件里的过期值也改掉。
- **教训**：对他人代理做 force reload 前必须核对 `mode` 字段与运行态一致；reload 后要复查 mode（我加了规则却忘了 mode）。

## 3. 机器信息（主力机 = 面板上的 cluster_b 节点）

- aarch64，Huawei Cloud EulerOS 2.0，内网 `<npu-内网IP>`，1.5TB 内存。
- **8× 昇腾 910B3 64GB**，CANN 8.5.2，driver 25.5.1（npu-smi 25.5.1）。
- 磁盘：`/` 可用 393G；`/data_nv2` 6.6T 空闲 NVMe（放仓库/模型首选）；`/data` 是 292T 共享 NFS（别人的东西多，勿动）。
- 网络：pypi / HuggingFace / GitHub **直连全通**，不用配镜像。
- Docker 27.2.0，默认 runtime 就是 `ascend`，可跑 NPU 容器；机器上已有 verl / vllm-ascend 等 CANN 9.x 系镜像（说明宿主驱动兼容 CANN 9.0 系镜像）。
- 现成 Python 环境：`/root/rl_framework_py310`（py3.10，torch 2.7.1 + torch_npu 2.7.1.post2 + transformers 4.57.6）——本机 CANN 8.5.2 下实证可用的组合，别删。

## 5. 共享机器注意事项

- 卡是否空闲以面板 / `npu-smi info` 为准（有别人容器常驻在跑但没占卡，如 llm-lab-pt-final）。
- 非交互 `ssh npu '命令'` 不加载 /etc/profile，没有 Ascend 环境变量，需要先 `source /usr/local/Ascend/cann/set_env.sh`。
- 礼仪：控制用卡数量（学习实验 4 卡足够）、长任务进 tmux、跑之前面板确认没人临时借用。

## 6. 顺带完成的 RLinf 调研结论（下次开跑的依据）

- 目标组合：RLinf（官方 v0.3 支持 Ascend）+ GR00T N1.5 + LIBERO-spatial + PPO，官方 Ascend CI 同款配置 `libero_spatial_ppo_gr00t`。
