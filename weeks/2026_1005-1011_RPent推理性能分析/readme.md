## 2026-10-09 · 换 LLM 首批实跑：DeepSeek-V4.1-Flash（8 集）

- 对象：`openai-chat:deepseek-v4.1-flash`（华为云 MaaS 同端点），api planner，Long Swap t0/t9 × seed0/1 × {medium 主档, none 关思考对照} = 8 集，串行、每集重启专用 VLA（dev7，RNG seed 固定）、整批共用一次 SAM3。
- [报告](2026-10-09-RPent-DeepSeek-V4.1-Flash-接入与关思考对照.md)｜[脱敏指标与标定](evidence-ds-20261009/)｜[录像帧接触表](figures-ds-20261009/)（含 overview 总览）。
- 结果：8 集全部 `exit=0`、无重试无超时；t0 四集全解出，t9 四集全未解出（medium 长时间试错后正常失败，none 直接提前停手）。
- 两个适配坑（换脑必踩）：openai 3.19.2 走独立包 `httpx2`（只包 `httpx` 会一条都记不到）；pydantic-ai 对未知模型 id **静默丢弃推理档位**（`supports_thinking` 默认 False → `medium`/`none` 会发出完全相同的请求，必须在 provider 适配层声明能力并在预飞断言 wire）。
- 计时口径：批次内非流式请求只有“整请求墙钟 + token 计数”可测；**A 阶段补测**（用本批真实出站体做流式重放 9 体 × 42 次 + 字节阶梯）把 **TTFT / TPOT / 上传税变成实测**，prefill 与解码仍为派生，报告 §6 列全方法与限制。
- **A 阶段最有价值的一条**：出站体因 9 张 base64 观测图固定在 **~5.9 MB/请求**（与 token 数无关），实测链路 **1.80 MB/s** ⇒ **上传税 1.2–4.0 s/请求、占整集 LLM 墙钟 7.0–20.4%**；把观测图降分辨率即可直接省掉这一段。
- A 阶段还修正了旧标定：小上下文（≤16k）标出的 decode 系数 1.48 ms/token 在真实 5 万–23 万上下文下低估 **1.6–3.8 倍**（实测 TPOT 2.42–4.92 ms/token，随上下文上升）；报告派生表已改用按上下文的 TPOT。
- 副产品：TTFT 同体重发 max/min 达 **1.12–2.21**（65k 上下文体在 9.1–17.1 s 间摆动）；medium 档首个 token 就是第一个**思考** token（思考流式可见，不藏在 TTFT 里）。
- **B1（stream-shim）单集验证通过**：在 transport 层把非流式请求翻成流式、再把 SSE 重组成非流式返回给 SDK，planner 无改动。验证集（t0_s0/medium）**解出**、22 请求与 RPent 自报 `[agent] usage:` **in/out/请求数三项全 MATCH**、22/22 行标流式且 22/22 记录"原始为非流式"、无一行退化成非流式相位。由此**每请求的 TTFT（中位 10.6 s）、可见思考时长（中位 4.6 s）、TPOT（中位 7.4 ms/token）首次成为实测**；证据 [b1-verification.json](evidence-ds-20261009/b1-verification.json)。
- **B2 全批 8 集重跑完成**（`shim-` 命名空间，与 10/09 正式批并存不混算）：解出 **4/8，逐集与冻结批完全一致**；**178 个请求全部带真实 TTFT / 可见思考窗口 / TPOT**——medium TTFT 中位 10.4 s、可见思考中位 3.0 s、TPOT 中位 5.3 ms/token；none TTFT 中位 8.9 s、无思考窗口、TPOT 中位 4.2 ms/token。shim 透明性 5 项检查全过（含 tool_call id **0 孤儿引用**）；报告新增 §7，指标见 [metrics-shim.json](evidence-ds-20261009/metrics-shim.json)。
- **B2 暴露一个既有悬崖（非 shim 引入）**：`t9_s0/t9_s1 medium` 两集以 `exit=1` 崩溃，错误是 pydantic-ai 在「响应只有思考、无可见输出」且 `finish_reason=length` 时的硬抛（**不重试**），根因是 `--max-tokens 8192` 对 medium 档推理偏小。三条证据切开与 shim 的关系：崩溃请求 `completion_tokens` 正好 8192；冻结批 306 次请求**从未出现 `length`**，但最接近的一次是 **8184/8192（差 8 token）**；对同一份崩溃请求体做两模式交错 A/B，**16/16 全为 `tool_calls`、零截断**，推理长度中位 3769(stream) vs 3836(plain)。证据 [cliff-ab.json](evidence-ds-20261009/cliff-ab.json)。
- **口径纪律**：B2 与 10/09 正式批**整集口径不可比**（2 集崩溃 + 逐集工作量随机波动，同一身份工具调用 43–80 次），**逐请求时延口径可比**。
- **新增独立 HTML 深度计时报告**（[deep-report-ds/](deep-report-ds/)，自包含可离线/可筛选/可导 CSV）：显式对照同周的 [两场景深度计时报告](deep-report/RPent-两场景深度计时报告.html)，补上它被结构性挡住的四项——**逐请求 TTFT（本页 178/178，参考报告 0/473）、逐请求 TPOT（参考报告无此字段）、prefill 显式拆分（参考报告 8/8 集留空）、可见思考窗口与占生成窗口比例（参考报告 `hidden_thinking_s` 8/8 留空）**。要点：medium 生成窗口中位 **69.8%** 花在思考 token 上；TTFT 中位 10.4 s（p10 2.6 / p90 19.6）；prefill 斜率 0.0368 ms/token、截距 7.04 s；上传税合计 332.2 s = LLM 墙钟 2750.6 s 的 **12.1%**。数据契约 [report-data-ds.json](deep-report-ds/report-data-ds.json)，装配与渲染脚本同目录。
